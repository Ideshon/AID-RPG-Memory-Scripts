# AI Dungeon — Memory Engine: совместимость с Universal RPG

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine установка]] · [[AI - AI Dungeon Memory Engine диагностика и ограничения]]

**Memory Engine v1.6.2 является самостоятельным Adventure Script.** В JavaScript комплекта нет обращений к `state.rpg`, RPG-характеристикам, модификаторам или таблицам навыков. Его данные хранятся в `state.aidm`. Другие Adventure Scripts не могут напрямую читать эту область `state`. Совместимость — по тексту повествования и общему модельному контексту, а не по синхронизации хранилищ.

## Разделение заметок Universal RPG и Memory Engine

**Удалять журнал Universal RPG не нужно.** Системы используют заметки для разных задач:

| Universal RPG | Memory Engine |
|---|---|
| Ресурсы, механика, игровые задачи и собственный журнал `state.rpg.journal` | Биографии, отношения, локации, фракции, сюжетные факты, хронология и календарь |
| `:aidm export` передаёт часть журнала как `notes` в снимке | `;mem import rpg card` сохраняет `notes` в `state.aidm.rpgSnapshot.notes` для справочного просмотра через `;mem import rpg status` |

**Критично:** Memory Engine v1.6.2 **не переносит `rpgSnapshot.notes` автоматически в `facts`, `events` или Story Cards** и **не добавляет их в собственный контекст для модели**. При импорте снимка он передаёт в свой контекст только краткую справку о герое/профессии/месте снимка. При этом Universal RPG может самостоятельно добавлять свои заметки в общий модельный контекст — Memory Engine не управляет этим поведением.

Избегай двух ручных записей одного и того же факта. Например, сведения об оплате и состоянии предмета оставляй в RPG; факт знакомства NPC и причину отношения — в Memory Engine. Для сюжетно значимого RPG-события допустимо создать отдельное краткое событие в летописи, но не копируй весь технический журнал в сюжетную память.

**Если дубли есть в View Context:** сначала сравни блоки `[AID MEMORY]`, Story Cards и блоки RPG. Дублирование может возникать из-за пользовательских Story Cards или ручных заметок, а не из-за `rpgSnapshot.notes`. Отключать всю систему заметок Universal RPG для решения такой проблемы избыточно.


## Разделение ответственности

| Система | За что отвечает |
|---|---|
| Memory Engine | Персонажи мира, их биографии и описательные навыки, отношения, локации, фракции, сюжетные факты, календарь и летопись |
| Universal RPG (если подключён отдельно) | Числовые характеристики героя, броски, временные эффекты, HP, деньги, инвентарь и игровое время RPG |
| Встроенный Memory Bank AI Dungeon (если активен) | Собственные резюме и поиск по истории; не синхронизируется с `state.aidm` как база структурированных полей |

`;mem here Кабинет Даны` задаёт местонахождение героя **только для Memory Engine**. `;mem char Дана | at=Кабинет Даны` задаёт последнее известное место NPC. Это не то же самое, что `:place` или другие команды RPG.

Аналогично `;mem skill Алиса | Рисование | высокий` — описательный навык NPC, **не бонус к броску**.

## Возможные конфликты

1. **Порядок подключения.** Один скрипт может преобразовать введённый текст до того, как его увидит следующий. В результате `;mem` может считаться ходом RPG или частью обычного действия. Порядок зависит от списка Scripts в приключении.
2. **Несогласованное игровое время.** Команды RPG `:time`, `:date`, `:rest` не обновляют `state.aidm.date` автоматически. При значимых переходах укажи `;mem date YYYY-MM-DD HH:MM` отдельно.
3. **Конфликт инструкции рассказчику.** Если два скрипта ждут собственные JSON/XML-блоки, модель может пропустить один из форматов. Memory Engine запрашивает маркер `[[AIDM_UPDATE]]...[[/AIDM_UPDATE]]`; другой скрипт может использовать собственный протокол.
4. **Общие Story Cards.** Memory Engine не переписывает карточки игрока с совпадающими ключами, но другой скрипт может редактировать те же карточки по собственным правилам.

## Сброс Memory Engine и независимость от RPG

Команды `;mem reset data/cards/all confirm` работают **только** с `state.aidm` Memory Engine и его помеченными Story Cards. Они не обращаются к `state.rpg`, не сбрасывают HP, деньги, навыки и другие параметры Universal RPG. При этом Story Cards и история приключения могут быть общими для игрового мира — пользовательские карточки остаются на месте. Самостоятельная синхронизация данных между скриптами не добавляется.

## Безопасная диагностика

- Проверяй Memory Engine отдельно с командами `;mem ping`, `;mem status`, `;mem list char`.
- По очереди включай другие скрипты, контролируя `;mem ping`, действия RPG и события в календаре.
- Если модель не поддерживает оба протокола, отключи только автоотчёты памяти через `;mem auto off`; ручная память и контекст сохранятся.
- **Не изменяй файлы Universal RPG по этой инструкции.** Ни одной готовой правки к его коду пакет Memory Engine не содержит. Изменять RPG-обработчик следует только в его собственном проекте после отдельной проверки.

Автоматическая синхронизация данных между скриптами не реализована; доступен только явный обмен экспортной Story Card по командам. Ограничения основаны на [официальных правилах Adventure Scripts](https://help.aidungeon.com/scripting).

## Мост для переноса данных из Universal RPG — v1.5.0

> [!important] Между отдельными Adventure Scripts нет общего `state`
> Memory Engine **не имеет права и технической возможности** читать `state.rpg` другого подключённого Universal RPG. Общее `state.memory` не заменяет структурированный экспорт: разные скрипты могут записывать туда свои тексты, а порядок влияет на итог. Поэтому автоматической синхронизации числовых параметров в v1.5.0 нет.

**Согласованный контракт обмена (Universal RPG v2.28):** Universal RPG формирует компактный JSON со стабильной схемой и передаёт его одним из двух способов:

1. **Обменная Story Card** типа `Custom`, у которой `Entry` начинается с `[AID_RPG_EXPORT:1]`, следующая часть — JSON. Memory Engine читает её по команде `;mem import rpg card`. Экспортирующий RPG-скрипт должен самостоятельно создавать/обновлять эту карточку, если будет реализована соответствующая функция на его стороне.
2. **Ручная вставка JSON**: `;mem import rpg paste | {JSON}`. Подходит для разового переноса. JSON должен быть компактным и помещаться в лимит одного игрового действия; длинные инвентарные списки лучше исключить из экспорта.

**Схема снимка v1:**

```json
{
  "source": "Universal RPG",
  "version": 1,
  "hero": {
    "name": "Алиса",
    "race": "человек",
    "class": "детектив",
    "bio": "Расследует исчезновения",
    "occupation": "Следователь"
  },
  "location": "Офис Даны",
  "date": "2016-01-02",
  "time": "09:00",
  "stats": {"Интеллект": 15},
  "skills": {"Расследование": 25},
  "inventory": ["Фонарик"],
  "notes": ["Получено предложение работы"]
}
```

Для карточки `Entry` должен иметь следующую форму (метка не является JSON):

```text
[AID_RPG_EXPORT:1]
{"source":"Universal RPG","version":1,"hero":{"name":"Алиса"},"stats":{"Интеллект":15}}
```

Команды получателя:

```text
;mem import rpg
;mem import rpg card
;mem import rpg status
```

**Что импортируется:** в `state.aidm.rpgSnapshot` сохраняются копии имени/вида/класса, характеристик, навыков, инвентаря, заметок, даты и места. Для существующего персонажа Memory Engine заполняет только **пустые** `bio`, `appearance`, `occupation` и `at`. Текущую дату, положение, числа и активную механику Memory Engine не перезаписывает. Числовые параметры отображаются в статусе снимка, но не считаются навыками Memory Engine и не меняют правила Universal RPG.

**Что ещё потребуется:** отдельная реализация экспортирующей команды на стороне Universal RPG, согласованная с его текущим состоянием и API. В этот пакет файлы Universal RPG не добавлялись и не менялись. Автоматизация запуска такого экспорта «по расписанию» или «после изменения параметров» потребует совместного тестирования в AI Dungeon.

**Не используйте** незадокументированное обращение к переменным другого скрипта, чтение общего `frontMemory` как гарантированного источника JSON или механическое копирование двух `Library.js` в одну вкладку.

## Исправление v1.6.1: команда импорта с точкой

Режим **Do** может дописывать точку. В v1.5.0 и v1.6.0 ввод `;mem import rpg card.` отвечал списком синтаксиса. В v1.6.1 `;mem import rpg card` и `;mem import rpg card.` работают одинаково. При успешном импорте проверь `;mem import rpg status`.

**Обменный формат:** тип `Custom`, Keys `__AID_RPG_EXPORT_V1__`, начало Entry `[AID_RPG_EXPORT:1]`, затем новая строка и JSON до 5000 символов. Источники `source="Universal RPG"`, `version=1`, непустое `hero.name` обязательны. Отдельный `state.rpg` Memory Engine не читает.

## Перенос памяти между разными приключениями

В v1.7.0 `;mem transfer export` **не включает** механические значения Universal RPG и информационный снимок `rpgSnapshot`. После переноса в новое приключение выполни новый `:aidm export` в **его** Universal RPG, затем `;mem import rpg card` в Memory Engine.
