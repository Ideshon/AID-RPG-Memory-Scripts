# AI Dungeon — Memory Engine: быстрый старт

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine установка]] · [[AI - AI Dungeon Memory Engine все команды]]

**Цель:** начать играть с автоматизированной памятью, не обновляя каждую Story Card вручную.

> [!tip] Быстрая проверка версии 1.4.1
> `;mem ping` — безопасная команда самопроверки загрузки Library/Input. После неё проверь `;mem status`. Если обе команды не работают, см. [[AI - AI Dungeon Memory Engine диагностика и ограничения]].


> [!warning] Для версии 1.4.4
> Если видишь `AM_HELP_PAGES has already been declared` или `Unexpected end of input`, старый/несохранённый код либо ошибка загрузки не даёт Input запуститься. Полностью замени **все четыре вкладки** из полного архива v1.7.0. Память игры не очищай. Подробности: [[AI - AI Dungeon Memory Engine установка]] и [[AI - AI Dungeon Memory Engine диагностика и ограничения]].

## Минимум для существующего приключения

1. Подключи отдельный Adventure Script по инструкции [[AI - AI Dungeon Memory Engine установка]].
2. Проверяй `;mem status`. Если есть ранее созданные персонажи/локации/организации, попробуй `;mem import`.
3. Зафиксируй **игровые** время и место через `;mem date ...` и `;mem here ...`.
4. Играй обычными действиями. Скрипт будет пытаться извлекать факты из ответов рассказчика.
5. Если импортировались не все Story Cards, выполни `;mem list fact` — нестандартные типы в v1.3.1 сохраняются как факты.
6. Периодически открывай `;mem pending`, `;mem day`, `;mem list rel`; исправляй важные ошибки вручную.

```text
;mem status
;mem import
;mem date 2016-01-02 09:06
;mem here Офис Даны
;mem list char
;mem list rel
;mem day
```

> [!important] Автоматизация не равна гарантированной записи
> Автоизвлечение работает только при корректном маркере `[[AIDM_UPDATE]]...[[/AIDM_UPDATE]]` в ответе модели. Если маркер отсутствует, хранится лишь короткий фрагмент текста, **не** готовая карточка или достоверный факт.

## Быстрое создание без десятка команд

Вместо последовательных `;mem char`, `;mem skill` и `;mem rel` используй **пакетный режим**. Одно сообщение:

```text
;mem batch
§;mem char Алиса | bio=Начинающий дизайнер | traits=Любознательная и настойчивая
§;mem char Дана | bio=Руководитель дизайнерского отдела
§;mem rel Дана -> Алиса | view=Профессиональный интерес | reason=Впечатлена эскизами
§:apply
```

Шаблон для одной категории выдаёт команда `;mem batch template char`. Полная инструкция: [[AI - AI Dungeon Memory Engine пакетное заполнение]].

## Старт нового мира

```text
;mem date 2016-01-02 09:06
;mem world Реалистичный современный мир. Действие происходит в Де-Мойне.
;mem place Де-Мойн | kind=город | description=Город в Айове
;mem place Здание Строй-Арт | parent=Де-Мойн | kind=здание | description=Пятиэтажный офисный центр
;mem faction Строй-Арт | description=Компания по дизайну офисов | territory=Де-Мойн
;mem place Офис Даны | parent=Здание Строй-Арт | kind=офис | description=На пятом этаже
;mem here Офис Даны
;mem char Алиса | bio=Начинающая дизайнер | traits=Любознательная, смелая | appearance=Тёмные волосы | occupation=Стажёр | at=Офис Даны
;mem char Дана | bio=Руководитель отдела | traits=Внимательная к деталям | occupation=Начальница отдела | at=Офис Даны
;mem rel Дана -> Алиса | view=Заинтересованность | reason=Впечатлена эскизами
;mem rel Алиса -> Дана | view=Уважение и надежда | reason=Получила шанс проявить себя
```

Одинаковые имена распознаются без учёта регистра и разницы `ё`/`е`, но **дубликаты с разными прозвищами** автоматически не объединяются. Используй одинаковое имя во всех командах.

## Проверка после сцены

```text
;mem pending
;mem list char
;mem show char Алиса
;mem list rel
;mem show rel Дана -> Алиса
;mem day
;mem timeline
```

**Проверяй только значимые изменения**: новые персонажи, поворот отношений, место действия, важные факты и крупные события. Подробная работа: [[AI - AI Dungeon Memory Engine практические примеры]].

## Если требуется начать память с нуля

В версии **1.4.7** команды `;mem reset data`, `;mem reset cards`, `;mem reset all` **без `confirm`** показывают, сколько записей каждого вида будет удалено. Общий предпросмотр доступен через `;mem reset`. Ни одна из этих команд ничего не удаляет. Для реального сброса нужны соответственно `;mem reset data confirm`, `;mem reset cards confirm`, `;mem reset all confirm`. Перед очисткой сделай копию приключения. Это необратимо через `;mem undo` и не удаляет встроенный Memory Bank. См. [[AI - AI Dungeon Memory Engine все команды#Полный сброс памяти и Story Cards]].

## Если память ошиблась

- Последний автоматический пакет неверен и после него не было ручных правок → `;mem undo` (Story Cards при этом не откатываются).
- Важен только один неверный параметр → повтори `;mem char`, `;mem place` или `;mem rel` с правильным полем.
- Удалить объект → `;mem delete ...`. Для `event`, `fact`, `plan` требуется ID.
- Модель часто выдумывает данные → `;mem auto off`; сохраняй подтверждённые факты командами.

[[AI - AI Dungeon Memory Engine автообновление и Story Cards]] · [[AI - AI Dungeon Memory Engine диагностика и ограничения]]

> [!tip] Неочевидные поля
> `parent` — это место выше по иерархии, а не компания-владелец; `at` — местонахождение NPC, `here` — место повествования, `kind` — текстовая метка, `trust` — пока лишь хранимое число. Подробности: [[AI - AI Dungeon Memory Engine поля и влияние]].

## Если `;mem ping` не показывает версию 1.4.6

Открой [[AI - AI Dungeon Memory Engine диагностика и ограничения]] и проверь **Input → Script Test** с полем `text: ";mem ping"`. Скрипт должен сохранить ответ в `state.aidm.pendingUI` и показать диагностическое `state.message`. Если нет даже этого, не продолжай тесты пакетного ввода; сначала проверь, что активен правильный скрипт.


## Импорт готового приключения — рекомендуемый порядок v1.6.0

```text
;mem import preview
;mem import
;mem list char
;mem list place
;mem list fact
;mem import plot status
```

Сначала будут импортированы все доступные Story Cards с их типами, а также Plot Essentials/Author's Note, **если** скрипт видит их в `state.memory`. Для Story Summary и AI Instructions скопируй текст вручную: `;mem import plot summary | Текст` и `;mem import plot instructions | Текст`.

Если в другом подключённом скрипте работает Universal RPG, воспользуйся `;mem import rpg`. Самостоятельно прочитать его внутренние значения Memory Engine не может.

## Проверка новых автоматических записей (v1.6.0)

Теперь автоизвлечение **не меняет память молча**. Уведомление `state.message` предложит проверить изменения.

```text
;mem review
;mem review 1
;mem accept 1
```

Для исправления: `;mem edit 1 | Новый текст`, затем `;mem accept 1`. Для отказа: `;mem reject 1`. При конфликте с ручной/старой записью скрипт покажет, как использовать `;mem accept 1 replace`. Подробнее: [[AI - AI Dungeon Memory Engine проверка автопамяти]].

## Если переносишь мир в новую историю

Из старого приключения выполни `;mem transfer export`, затем копируй части из `;mem transfer part N`. В новом приключении вставляй готовые команды и заверши `;mem transfer apply confirm` после предпросмотра. Полные правила: [[AI - AI Dungeon Memory Engine перенос между историями]].
