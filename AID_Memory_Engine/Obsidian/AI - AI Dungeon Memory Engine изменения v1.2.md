# AI Dungeon — Memory Engine: изменения v1.2

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine установка]] · [[AI - AI Dungeon Memory Engine все команды]]

> [!info] 3 ноября 2026 года
> Это **изменение работающего JavaScript-кода** по сравнению с v1.1, а не только редакция документации. Проверено локально в Node.js с эмуляцией Input/Context/Output и Story Cards. Реальное воспроизведение на AI Dungeon не проверено.

## Что исправлено

| Функция | Новое поведение | Что остаётся ограничением |
|---|---|---|
| `place.parent` | Родитель должен существовать; нельзя ссылаться на себя или замкнуть цикл. В одном `batch` можно создать родителя и потомка в любом порядке. | Названия остаются текстовыми; нет координат, расстояний и автопереходов. |
| `!mem validate` | Проверяет сохранённую карту на отсутствующие родители и циклы, включая старые данные. | Ничего не исправляет автоматически. |
| Удаление `place` | Запрещено удалять родителя, пока у него есть дочерние места. | Другие текстовые ссылки — NPC `at`, фракции `territory` — автоматически не перепривязываются. |
| `kind` и `territory` | Добавлены в контекст выбранных локаций и фракций. | Не влияют на RPG-механику или физическую доступность. |
| `trust` и `tags` | Включены в контекст выбранных отношений и Story Card первого участника. | `trust` — описательная шкала, не бонус к d20. |
| Сюжетные `result`, `start`, `end` | Видны в контексте выбранной сюжетной линии. | Не являются таймерами или триггерами. |
| `event importance` | Значимость 1–3 используется для приоритета до 4 событий из последних 90; `day` и `timeline` показывают уровень. | Важность не меняет историю и не гарантирует внимание модели. |
| Календарь | `#ID` показывается при создании плана, в `calendar` и `day`; `delete plan ID` теперь практически применим. | `calendar` может показывать прошедшие разовые планы. |
| Обычные `char`, `place`, `faction`, `arc`, `rel` | Неизвестные/пустые поля и некорректное `trust` отклоняются без сохранения. | Для очистки отдельного поля по-прежнему нет универсальной команды. |
| `!mem here` | Активная локация и до двух известных родителей приоритетно выбираются для контекста, даже если их названия не повторены в действии. | Общее ограничение контекста — 3200 символов, вставка может быть пропущена при полном контексте AI Dungeon. |

## Установка поверх v1.1

1. Открой существующий Adventure Script **Memory Engine**, не Universal RPG.
2. Замени четыре вкладки `Library`, `Input`, `Context`, `Output` файлами v1.2. Не создавай новый `state.aidm` и не удаляй старые карточки вручную без проверки.
3. В игре проверь `!mem status`, `!mem validate`, `!mem map`, `!mem calendar`.
4. Если `!mem validate` находит ошибку, создай недостающего родителя либо укажи правильный существующий `parent` у ребёнка. Для удаления старого родителя сначала удали/перенеси его детей.
5. Проверь `!mem place Название` и `!mem show char Имя`, а затем обычный ход с просмотром Context Viewer. Ключевое свидетельство новых полей — строки `тип`, `метки`, `доверие` и `[важность N/3]` в выбранных воспоминаниях.

> [!warning] Сохранность старых данных
> Формат `state.aidm.version` остаётся `1`, поэтому существующие записи, ID, календарь и персонажи не должны сбрасываться при установке v1.2. Старые неверные `parent` не удаляются: `!mem validate` предназначен для обнаружения проблем. `!mem undo` не откатывает автоматически созданные Story Cards. Делай резервную копию приключения штатными средствами платформы перед заменой скриптов.

## Границы исправлений

В v1.2 **нет** географических маршрутов, реальных независимых агентов, автоматического переноса персонажей при смене `here`, синхронизации даты с Universal RPG, полноценного автоматического контроля истинности и интерфейса Banshee. Выводимые поля помогают рассказчику, но не являются изменениями числовой механики.
