# AI Dungeon — Memory Engine: все команды (v1.8.0)

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine обновления]] · [[AI - AI Dungeon Memory Engine установка]] · [[AI - AI Dungeon Memory Engine устройство памяти]]

> [!info] Сверено с исходным кодом команд Memory Engine v1.8.0
> Ниже только существующие команды, а не планируемые функции. Основной префикс **`;mem`**. Псевдоним `:mem` конфликтует с Universal RPG. Команды вводятся **по одной за ход, кроме многострочной `;mem batch`**; `|` — разделитель аргументов. Используй `on/off` в нижнем регистре.

> [!tip] Что на что влияет
> Значение каждого `bio`, `at`, `parent`, `kind`, `trust`, `importance`, `result` и прочих полей разъяснено в [[AI - AI Dungeon Memory Engine поля и влияние]]. Там отдельно указано, что видно в `show`, что передаётся рассказчику, что попадает в Story Cards и что **не** изменяет механику.


> [!info] Диагностика версии 1.4.1
> `;mem ping` — проверить загрузку обработчика команд без изменения игрового состояния. При переходе с v1.4 замени **Library + Input + Context + Output**, а не только Library. Подробности в [[AI - AI Dungeon Memory Engine диагностика и ограничения]].

## Встроенная тематическая справка

**`;mem help`** выводит темы, `;mem help all` — общий указатель, а `;mem help char/place/rel/plan/...` — синтаксис с примерами и ограничениями. Доступны русские синонимы, например `;mem help персонажи`, `;mem help карта`, `;mem help календарь` и `;mem help пакет`. `;mem batch help` показывает ту же инструкцию, что и `;mem help batch`.

Все темы с объяснениями: [[AI - AI Dungeon Memory Engine встроенная справка help]].

> [!tip] Команды в Do и точка в конце
> AI Dungeon может преобразовать `;mem list char` в `> You ;mem list char.`. С v1.3.1 завершающая точка корректно обрабатывается для команд просмотра и переключателей. Команда `;mem list char/place` выводит **оба списка**, но для одного раздела лучше использовать `;mem list char` и `;mem list place` отдельно.

**Все изменения, присланные рассказчиком, сначала поступают в очередь**. Не попадают в Story Cards до принятия. Сведения об источнике доступны по ID.

| Команда | Действие |
|---|---|
| `;mem review` | Показать ожидающие решения предложения и наблюдения. |
| `;mem review ID` | Прочитать полное значение и источник. |
| `;mem accept ID` | Подтвердить запись; ручные/импортированные поля защищены от замены. |
| `;mem accept ID replace` | Осознанно заменить защищённое значение. |
| `;mem edit ID | Новый текст` | Исправить предложение, потом отдельно подтвердить. |
| `;mem reject ID` | Отклонить без изменения базы. |
| `;mem review log` | Последние решения. |
| `;mem sources char Имя` | Происхождение полей персонажа. |
| `;mem sources place Название` | Происхождение полей места. |

## Общие команды и режимы

| Команда | Назначение |
|---|---|
| `;mem` / `;mem help` | Оглавление тем встроенной справки. |
| `;mem status` | Режимы, игровая дата, текущее место, счётчики, автопакеты, пропуски, ошибки карточек и отклонённые ссылки на родителей. |
| `;mem validate` | Проверить сохранённые связи `parent`: отсутствующие родители и циклические ссылки. Старые ошибочные записи не изменяет. |
| `;mem auto on` / `;mem auto off` | Включить/выключить обработку JSON от рассказчика. Изначально `on`. |
| `;mem cards on` / `;mem cards off` | Включить/выключить обновление собственных Story Cards. Изначально `on`. |
| `;mem cards show TYPE ИМЯ` | Активная карточка, индекс, ID, тип, название, ключи и Entry. |
| `;mem cards repair` | Вернуть исходные тип и сохранённое название существующих управляемых карточек. |
| `;mem cards link INDEX \| TYPE \| ИМЯ` / `... \| confirm` | Связать источник с существующей записью без создания новой. Для fact укажи ID. |
| `;mem cards unlink INDEX` / `... confirm` | Удалить только явную связь; сначала restore, если карточка управляемая. |
| `;mem cards audit` | Найти ручные стандартные и Custom-карточки, сопоставленные с сущностями или фактами памяти. |
| `;mem cards adopt INDEX` / `;mem cards adopt INDEX confirm` | Предпросмотр и передача конкретной ручной карточки под управление Memory Engine; отсутствующие в памяти строки сохраняются как дополнительные сведения. `INDEX` нужно заменить числом после `#` из `audit`: для `#1 char Алиса` введи `;mem cards adopt 1`, затем `;mem cards adopt 1 confirm`. |
| `;mem cards remove-own TYPE ИМЯ` / `... confirm` | Удалить только свою дублирующую карточку после предпросмотра, если ручная карточка уже существует. |
| `;mem cards extra TYPE ИМЯ` / `;mem cards extra TYPE ИМЯ \| Текст` / `\| -` | Показать, заменить или очистить дополнительные строки, перенесённые из ручной Story Card. |
| `;mem cards backups` / `;mem cards backup TYPE ИМЯ` | Список переданных карточек и полная исходная копия одной карточки. |
| `;mem cards restore TYPE ИМЯ` / `... confirm` | Предпросмотр и восстановление исходной ручной карточки. `TYPE`: `char`, `place`, `faction`, `fact`; для `fact` укажи ID. |
| `;mem import` | Импортировать Character/Location/Faction как сущности, остальные типы (Custom, Class, Race, Item и т. д.) — как факты; исходные Story Cards остаются. |
| `;mem list fact` / `;mem show fact ID` | Просмотр фактов и импортированных карточек нестандартных типов. |
| `;mem undo` | Отменить последний подтверждённый или ручной `batch`-пакет, если доступен снимок. Story Cards и сброс не откатываются. |
| `;mem reset` / `;mem help reset` | Предпросмотр всех категорий базы и собственных Story Cards / инструкция по сбросу. Ничего не удаляет. |
| `;mem pending` | Очередь ожидающих предложений и наблюдений; синоним просмотра `;mem review`. |
| `;mem recent` | Сырые краткие фрагменты последних сцен, без подтверждения достоверности. |

## Полный сброс памяти и Story Cards

> [!danger] Необратимое действие
> Перед использованием сделай резервную копию приключения средствами AI Dungeon. **`;mem undo` не восстанавливает очищенную базу или удалённые Story Cards.** Сброс не предназначен для устранения ошибок компиляции `Input Modifier` и не исправляет неподключённый скрипт.

| Команда | Что удаляется | Что остаётся |
|---|---|---|
| `;mem reset` | Показывает полный предпросмотр базы и собственных Story Cards: количество записей по категориям, без удаления. | Все данные остаются. |
| `;mem reset data` | Показывает **сколько именно записей каждой категории базы** будет удалено при подтверждении. | База и все Story Cards остаются. |
| `;mem reset cards` | Показывает число собственных Story Cards отдельно по персонажам, локациям и фракциям. | База и все Story Cards остаются. |
| `;mem reset all` | Показывает **оба списка** — категории базы и собственные Story Cards. | База и все Story Cards остаются. |
| `;mem reset data confirm` | **Только база `state.aidm`**: мир, персонажи, места, связи, фракции, факты, хронология, планы, настройки, сведения об импорте, счётчики и очередь синхронизации. Сразу создаётся пустая база с начальными настройками `auto=on`, `cards=on`. | **Все Story Cards**, история приключения, Memory Bank и другие скрипты. |
| `;mem reset cards confirm` | **Только Story Cards Memory Engine**, определяемые по служебной метке в начале `Entry`. Очищает очередь карточек и отключает `cards` во избежание немедленного пересоздания. | База `state.aidm`, другие карточки, история и Memory Bank. |
| `;mem reset all confirm` | Сначала собственные Story Cards, затем **всю `state.aidm`**, только если удалось удалить все найденные собственные карточки. | Пользовательские/импортированные Story Cards без маркера, сюжет, Memory Bank, `state.memory` и данные других Adventure Scripts. |

**Что выводит предпросмотр базы:** наличие описания мира, даты, времени и текущего места; количество персонажей, их отдельных описательных навыков, локаций, фракций, направленных отношений, фактов, событий, записей дней и месяцев, сюжетных линий, планов, недавних фрагментов, меток импорта и элементов очереди Story Cards. Навыки уже находятся внутри персонажей, а события могут одновременно упоминаться в днях — эти строки **не нужно суммировать**.

**Что выводит предпросмотр карточек:** общее число собственных Story Cards, отдельно количество карточек персонажей, локаций и фракций. Если API списка недоступен, вместо числа будет **«недоступно»**, а не выдуманный ноль. Обычные пользовательские карточки не учитываются. Количество пересчитывается **при каждом вызове**, а не сохраняется при просмотре. Команда без `confirm` не запускает также фоновую синхронизацию Story Cards на этом ходу.

Для безопасности `confirm` обязателен. Например, `;mem reset all` **без** `confirm` ничего не удаляет. Нельзя вызвать сброс из `;mem batch`. При реальном подтверждении операция использует **текущее** состояние, поэтому количество может отличаться от предыдущего просмотра.

### Какие карточки считаются принадлежащими скрипту

Только те, у которых `Entry` **начинается** с метки формата `[AIDMEM:1:char:имя]`, `[AIDMEM:1:place:имя]` или `[AIDMEM:1:faction:имя]` (следом перевод строки). Тип карточки и её ключи без такой метки не служат основанием для удаления. Ручные, импортированные и Custom-карточки без указанного маркера не удаляются.

### Частичное удаление и ошибка API

За один запуск удаляется **не больше 30 собственных карточек** (от последних индексов к первым). Если их больше или API сообщает об ошибке, ответ показывает количество удалённых, оставшихся и ошибок. **Повтори ту же команду** до завершения. Для `reset all` база остаётся нетронутой, пока ещё есть карточки; на время неполного сброса выключаются `auto` и `cards`. Для `reset cards` база остаётся, а автосинхронизация карточек выключается независимо от результата частичного удаления. Если список карточек или API удаления недоступен, опасная операция не продолжается.

> [!warning] Что не делает сброс
> Он не очищает сюжетную историю и встроенный Memory Bank. После `reset data` оставшиеся Story Cards можно повторно импортировать через `;mem import`. После `reset all` не затронутые ручные карточки могут продолжать поступать в контекст модели; чтобы получить совершенно пустой мир, их нужно удалять отдельно и осознанно.

Проверить результат: `;mem status`, `;mem list char`, `;mem map` и раздел Story Cards в интерфейсе. См. [[AI - AI Dungeon Memory Engine автообновление и Story Cards]] и [[AI - AI Dungeon Memory Engine диагностика и ограничения]].

## Пакетное заполнение

В v1.4 **пакет содержит те же команды, что отправляются отдельно**. Перед каждой строкой ставь `§`, заверши `§:apply`. Весь блок отправляй **одним сообщением** в Do. Пакет проверяется целиком: при ошибке изменения не записываются.

| Команда | Назначение |
|---|---|
| `;mem batch help` / `;mem help batch` | Встроенная подробная справка. |
| `;mem batch template char` | Пример персонажа и навыков. |
| `;mem batch template skill/rel/place/faction/world/fact/event/day/arc/plan/delete` | Отдельный готовый шаблон по категории. |
| `;mem batch template all` | Универсальный шаблон. |
| `;mem batch template legacy char/place/faction/arc/all` | Старые формы `§поле=значение`, совместимые с v1.1–v1.3.1. |

```text
;mem batch
§;mem char Алиса | bio=Главная героиня | traits=Любознательная
§;mem skill Алиса | Рисование | высокий | Делает эскизы
§;mem place Офис | kind=кабинет | description=Рабочее место
§;mem rel Алиса -> Дана | view=Уважает | reason=Получила работу
§:apply
```

Можно скопировать обычную строку `;mem char ...` в пакет, лишь добавив `§`. Разрешены также `world`, `date`, `here`, `faction`, `fact`, `event`, `summary`, `arc`, `plan` и `delete`. `status`, `map`, `list`, `auto`, `import` и другие команды чтения/режимов в пакет не входят. При сохранении переносов строк допустим вариант без `§` с завершающим `;mem apply`, но в AI Dungeon надёжнее `§:apply`. Максимум **3950 символов и 55 развёрнутых полей**.

Подробные шаблоны по всем категориям, ограничения, совместимость и откат: **[[AI - AI Dungeon Memory Engine пакетное заполнение]]**. Перенос ручных карточек: [[AI - AI Dungeon Memory Engine управление Story Cards]].

## Мир, карта и фракции

| Команда | Назначение |
|---|---|
| `;mem world` | Показать текущее описание мира. |
| `;mem world Описание` | Заменить общее описание мира. |
| `;mem here` | Показать текущее место. |
| `;mem here Офис Даны` | Указать текущее место (не создаёт отдельную локацию). |
| `;mem map` | Вложенная текстовая карта мест (до 55) и фракций (до 25); не графическая карта. |
| `;mem place Название \| parent=... \| description=... \| kind=... \| status=...` | Создать или частично изменить место. |
| `;mem faction Название \| description=... \| territory=... \| goal=... \| status=...` | Создать/изменить фракцию. |
| `;mem list place` / `;mem list faction` | Имена мест и фракций. |
| `;mem show place Название` / `;mem show faction Название` | Поля одной записи. |

Поле `parent` требует **уже существующего** места в одиночной команде; в `batch` родитель и ребёнок могут быть созданы вместе. Удаление родителя с детьми запрещено, пока дети не перенесены или удалены. `;mem validate` проверит ошибки прежней базы.

Поля мест: `description`, `parent`, `kind`, `status`. Поля фракций: `description`, `territory`, `goal`, `status`. **`parent` связывает названия мест текстом, `kind` не создаёт правила типа локации, `status` не ограничивает вход. `territory` не устанавливает границы; `goal` не запускает автономные действия.** Подробнее: [[AI - AI Dungeon Memory Engine поля и влияние]].

```text
;mem world Современные США, действие в Де-Мойне.
;mem place Де-Мойн | kind=город
;mem place Здание Строй-Арт | parent=Де-Мойн | kind=здание | description=Пятиэтажный офис
;mem place Офис Даны | parent=Здание Строй-Арт | kind=офис
;mem faction Строй-Арт | territory=Де-Мойн | goal=Дизайн интерьеров
;mem faction Местная полиция | territory=Де-Мойн | goal=Поддерживать порядок
;mem here Офис Даны
;mem map
```

## Персонажи и навыки

| Команда | Назначение |
|---|---|
| `;mem char Имя \| bio=... \| traits=... \| appearance=... \| skills=... \| occupation=... \| at=...` | Создать или частично изменить персонажа; достаточно одного поля после имени. |
| `;mem char Имя` | Показать краткие поля персонажа, если уже создан. |
| `;mem list char` | Показать имена персонажей. |
| `;mem show char Имя` | Поля персонажа; отдельные навыки удобнее смотреть через `;mem skills Имя` (сырой `skillSet` может отображаться технически). |
| `;mem skill Имя \| Навык \| Уровень \| Комментарий` | Добавить/изменить один описательный навык уже существующего персонажа. |
| `;mem skills Имя` | Вывести отдельные описательные навыки. |
| `;mem delete skill Имя \| Навык` | Удалить один отдельный описательный навык. |

Поля персонажа: `bio` — биография; `traits` — характер; `appearance` — внешний вид; `skills` — общее описание способностей; `occupation` — роль; `at` — местонахождение. `skill` сохраняет **текстовый** уровень, не механический уровень Universal RPG.

```text
;mem char Алиса | bio=Молодая дизайнер | traits=Упорная | appearance=Тёмные волосы | occupation=Стажёр
;mem skill Алиса | Рисование | высокий | делает эскизы вручную
;mem skills Алиса
;mem char Алиса | at=Строй-Арт
;mem show char Алиса
```

| Команда | Назначение |
|---|---|
| `;mem rel Имя А -> Имя Б \| view=... \| reason=... \| tags=... \| trust=...` | Создать или частично изменить отношение **А к Б**. |
| `;mem list rel` | Список всех направленных отношений. |
| `;mem show rel Имя А -> Имя Б` | Показать параметры конкретного направления. |
| `;mem delete rel Имя А -> Имя Б` | Удалить конкретное направление, не затрагивая Б→А. |

`trust`: необязательное **целое −100…100**; неверное число в любой команде — ошибка без сохранения. `trust` и `tags` передаются в контекст выбранных отношений и Story Card источника, но **не изменяют RPG-броски**. Связь может быть создана даже до создания карточек обоих персонажей, но более удобно добавить персонажей сначала. Самосвязь A→A не допускается.

```text
;mem rel Дана -> Алиса | view=Симпатия | reason=Впечатлена работами | trust=20
;mem rel Алиса -> Дана | view=Настороженное уважение | reason=Руководительница | trust=5
;mem show rel Дана -> Алиса
```

## Факты и летопись

| Команда | Назначение |
|---|---|
| `;mem fact Тема \| Текст` | Создать устойчивый факт с числовым ID. Текст — минимум 8 символов. |
| `;mem edit fact ID \| Новый текст` | Исправить текст существующего факта, сохранив его ID. |
| `;mem edit fact ID \| Новая тема \| Новый текст` | Исправить тему и текст существующего факта. |
| `;mem event Описание` | Добавить событие на текущую дату, если она есть. |
| `;mem event YYYY-MM-DD \| Описание \| 1..3` | Добавить событие на выбранную дату; 1–3 — значимость. |
| `;mem date YYYY-MM-DD` | Установить дату, прежнее время сохраняется. |
| `;mem date off` / `;mem date on` | Выключить или вернуть календарь Memory Engine в контексте рассказчика, сохранив уже записанную летопись. |
| `;mem date YYYY-MM-DD HH:MM` | Установить дату и время. |
| `;mem day` / `;mem day YYYY-MM-DD` | События и итоги текущего/выбранного дня; планы отдельно помечаются как запланированные. |
| `;mem summary YYYY-MM-DD \| Итог дня` | Создать/изменить сводку дня. |
| `;mem timeline` | Последние 24 подробно хранимых дня + до 10 последних сюжетных арок. |
| `;mem delete event ID` | Удалить конкретное событие. |
| `;mem delete fact ID` | Удалить конкретный факт. |

```text
;mem date 2016-01-02 09:06
;mem fact Условия найма | Пробный период составляет две недели.
;mem event 2016-01-02 | Дана предложила Алисе работу | 2
;mem summary 2016-01-02 | Алиса прошла собеседование и приступила к работе.
;mem day 2016-01-02
;mem timeline
```

> [!note] ID и отсутствие списка фактов
> При создании факта скрипт показывает ID. В v1.3.1 его также можно найти через `;mem list fact` и открыть через `;mem show fact ID`. Полнотекстового поиска и экспорта базы пока нет.

## Календарь и большие события

| Команда | Назначение |
|---|---|
| `;mem arc Название \| summary=... \| status=... \| result=... \| start=... \| end=...` | Создать/частично изменить долгую сюжетную линию. |
| `;mem list arc` / `;mem show arc Название` | Просмотреть сюжетные линии. |
| `;mem plan YYYY-MM-DD \| Заголовок \| Примечание` | Добавить календарный план. |
| `;mem plan YYYY-MM-DD \| Заголовок \| Примечание \| yearly` | Ежегодный план. |
| `;mem calendar` | До 35 записанных планов после сортировки по датам, **включая прошлые разовые** (не строго «ближайшие»). |
| `;mem delete arc Название` / `;mem delete plan ID` | Удалить сюжетную линию / план. ID плана показывается после создания и в `;mem calendar`/`;mem day`, например `#12`. Удаление: `;mem delete plan 12`. |

```text
;mem arc Пробная работа | summary=Стажировка Алисы | status=идёт | start=2016-01-02
;mem plan 2016-01-22 | Снежная буря | Возможны задержки транспорта
;mem plan 2016-02-14 | День святого Валентина | Кафе готовят меню | yearly
;mem calendar
```

## Просмотр и удаление

| Команда | Что делает |
|---|---|
| `;mem list char/place/faction/rel/arc` | Перечислить сущности указанного класса. |
| `;mem show char/place/faction/arc Название` | Показать отдельную запись. |
| `;mem show rel A -> B` | Показать одно направленное отношение. |
| `;mem delete char Имя` | Удалить персонажа, все его отношения, попытаться удалить собственную карточку. |
| `;mem delete place Название` | Удалить место, попытаться удалить собственную карточку. |
| `;mem delete faction Название` | Удалить фракцию, попытаться удалить собственную карточку. |
| `;mem delete rel A -> B` | Удалить одно направление связи. |
| `;mem delete arc Название` | Удалить сюжетную линию. |
| `;mem delete skill Имя \| Навык` | Удалить навык одного персонажа. |
| `;mem delete event ID` / `;mem delete fact ID` / `;mem delete plan ID` | Удалить запись по числовому ID. |

## Синтаксис и ограничения

- Команды предназначены для **отдельных сообщений** в режиме Do. Исключение — специальный блок `;mem batch` с маркерами `§...` и последней строкой `§:apply`. Несколько обычных команд `;mem` в одном сообщении не выполняются.
- Разделитель полей `|` обязателен для большинства записей. Внутри значения используйте слова вместо `|`.
- Имена хранятся по нормализованному ключу (без различия регистра и `е`/`ё`), но прозвища или новые варианты имён **не сливаются** автоматически.
- `;mem char`, `place`, `faction`, `arc` с одним именем без дополнительных полей **показывают**, а не создают запись.
- Команды обновляют **только указанные непустые поля**; `bio=` не стирает старое `bio`. **Неизвестные поля одиночных команд `char`, `place`, `faction`, `arc` и `rel` отклоняются, как и в `batch`.**
- `;mem event` требует минимум 8 символов описания; `;mem fact` — минимум 8 символов текста.
- ID для событий, фактов, планов **монотонно увеличиваются** и не обязаны начинаться снова с 1 после удаления. **ID плана выводится при создании и в `;mem calendar`**, поэтому его можно найти и использовать для удаления.
- Для `;mem auto on/off` и `;mem cards on/off` вводи именно строчные `on`/`off`.
- `;mem pending` — диагностическая сводка, **не модерация** изменений. Автоматические изменения только `date/time/place/world` могут не увеличить счётчик принятых пакетов.
- `;mem undo` откатывает последний доступный автопакет или `batch`-пакет, но не Story Cards; для исправления старых событий/отношений используются прямые команды.
- Команды `;mem export`, `;mem clear`, `;mem search`, `;mem confirm` **отсутствуют**. Факты доступны через `;mem list fact`, `;mem show fact ID`, `;mem edit fact ID | ...` и `;mem delete fact ID`. Команда `;mem edit ID | ...` без слова `fact` изменяет только предложение в очереди проверки.

## Импорт источников v1.5.0

| Команда | Результат |
|---|---|
| `;mem import preview` | Доступные Story Cards и поля Plot, без сохранения. |
| `;mem import` | Новые Story Cards (включая Custom) + Plot Essentials/Author's Note, если доступны через `state.memory`. |
| `;mem import refresh` | Перечитать название, текст, ключи и тип ранее импортированных нестандартных карточек; ID связанного факта сохраняется. Ручные поля стандартных карточек защищены. |
| `;mem import plot` | Инструкция импорта Plot. |
| `;mem import plot auto` | Копировать доступные Plot Essentials (`state.memory.context`) и Author's Note (`authorsNote`). |
| `;mem import plot essentials \| Текст` | Внести скопированные Plot Essentials. Аналогично `summary`, `authorsnote`, `instructions`. Символ `\|` в таблице означает разделитель полей `|` при вводе, **без обратной косой черты**. |
| `;mem import plot status` | Перечень сохранённых Plot-компонентов и длина. |
| `;mem import rpg` | Справка по обмену с Universal RPG. |
| `;mem import rpg card` | Прочитать обменную Story Card с меткой `[AID_RPG_EXPORT:1]`, если RPG её создал. |
| `;mem import rpg calendar` | Синхронизировать дату и время Memory Engine по импортированному RPG-снимку; неподходящую для григорианского календаря дату не подменять. |
| `;mem import rpg paste \| {JSON}` | Вставить подготовленный JSON формата обмена. |
| `;mem import rpg status` | Просмотреть импортированный снимок (включая характеристики и инвентарь). |

> [!warning] Не путай «всё импортировано» и «все компоненты доступны»
> Официальный Script API гарантирует массив Story Cards и отдельные поля `state.memory.context`/`authorsNote`, но не гарантирует чтение Story Summary и AI Instructions из интерфейса Plot. Для них требуется копирование и вставка. RPG не предоставляет Memory Engine доступ к чужому `state.rpg`.

**Примеры:**

```text
;mem import plot summary | Алиса переехала в город и устроилась дизайнером.
;mem import plot status
;mem import rpg card
;mem import rpg status
```

Подробнее: [[AI - AI Dungeon Memory Engine автообновление и Story Cards]] и [[AI - AI Dungeon Memory Engine совместимость с RPG]].

### Приём экспорта из Universal RPG v2.28

После `:aidm export` в Universal RPG запусти `;mem import rpg card`, затем `;mem import rpg status`. С версии 1.6.1 подкоманды импорта понимают также точку, которую режим Do иногда добавляет в конце (`;mem import rpg card.`). Импорт не удаляет исходную Custom Story Card и не меняет параметры RPG.

Для переданной Custom-карточки `;mem edit fact ID | Текст` обновляет её Entry; допустимы до 950 символов и буквальное `\n` для новой строки. Общий Entry — до 1000 символов. Подробности: [[AI - AI Dungeon Memory Engine управление Story Cards]].
