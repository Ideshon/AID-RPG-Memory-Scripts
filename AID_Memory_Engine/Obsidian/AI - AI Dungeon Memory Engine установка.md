# AI Dungeon — Memory Engine: установка

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine быстрый старт]] · [[AI - AI Dungeon Memory Engine диагностика и ограничения]]

> [!warning] При обновлении до v1.7.9 заменяй все четыре вкладки
> `Library.js`, `Input.js`, `Context.js`, `Output.js` должны быть **из одного полного пакета**. Нельзя объединять `Library.js` новой версии с `Input.js` старой. Код RPG или других скриптов **не менять**.

> [!info] Проверка
> Для v1.7.9 локально проверены синтаксис четырёх JS-файлов, перенос недостающих строк, ограничение длины карточки и запуск в AID-Sandbox. Работа этой версии на сервере AI Dungeon **не подтверждена**. Если платформа показывает значок ERROR, нужен текст ошибки.

## Файлы комплекта

| Файл | Вкладка AI Dungeon | Назначение |
|---|---|---|
| `Library.js` | **Library** | `state.aidm`, модель данных, Story Cards, формирование контекста, обработка ответов модели |
| `Input.js` | **Input** | Команды `;mem`, `Help`, шаблоны и пакетное редактирование |
| `Context.js` | **Context** | Вызов формирования контекста памяти |
| `Output.js` | **Output** | Отображение квитанций и разбор служебного JSON-отчёта |
| `test.js`, `test_import.js`, `test_review.js`, `test_rpg_v228.js`, `test_debug.js`, `test_transfer.js` | **Не устанавливать** | Локальные регрессионные тесты Node.js |

Папка `Obsidian/` содержит всю пользовательскую документацию. Отдельных `README.md`, `COMMANDS.md` и `RPG_Integration.md` в корне комплекта нет.

## Причина ошибки `AM_HELP_PAGES has already been declared`

> [!danger] Подтверждённый конфликт версий
> У `Library.js` v1.4 **830 строк**, и в нём уже объявлена `const AM_HELP_PAGES` (строка 648). В v1.4.1–v1.4.2 эта таблица перенесена в `Input.js` (строка 36). Когда AI Dungeon объединяет **старую Library** с **новым Input**, второе объявление попадает на **строку 867** и останавливает Input Modifier с ошибкой `Identifier 'AM_HELP_PAGES' has already been declared`. Этот сбой локально воспроизведён **с тем же номером строки**, который появился у пользователя.
>
> В v1.4.3 справка и команды были изолированы внутри Input, но Script Test сообщил новую ошибку `Unexpected end of input [<isolated-vm>:902:5]`. В v1.4.4 используется более простой официальный шаблон: **Input завершается `modifier(text);`**, а большой справочник `AM_HELP_PAGES` хранится один раз в Library. Вкладки имеют взаимную проверку версии. **Точная причина ошибки 902 на сервере не подтверждена**, поэтому её нельзя считать доказанно устранённой до игрового теста.

**Правильное исправление:** открой редактор каждого из четырёх разделов, выдели весь старый код (`Ctrl+A`), полностью замени его содержимым **соответствующего JS из одного комплекта v1.7.9** и нажми Save. При использовании подключаемого Adventure Script проверь, что в приключении активен именно этот обновлённый экземпляр.

Существующий `state.aidm` не сбрасывается; **не используй команды очистки и не удаляй приключение**.

## Новая установка

1. Создай сценарий AI Dungeon с поддержкой Scripting. В редакторе открой **Library**, **Input**, **Context**, **Output**.
2. Полностью замени содержимое каждой вкладки соответствующим файлом из архива и сохрани (**Save**). Во всех трёх исполняемых вкладках последняя команда — **`modifier(text);`**, как в официальной документации. Ничего не дописывай. Важно полностью **заменять**, а не добавлять код в конец вкладки.
3. Для использования как отдельного Adventure Script включи **Mark as Script** и сохрани. В своём приключении открой **Game settings → Scripts → + Add Script → My Scripts** и добавь его.
4. Не вставляй эти файлы в вкладки Universal RPG: это отдельный скрипт со своим `state.aidm`.
5. В **Do** введи сначала `;mem ping`, затем `;mem status` и `;mem help`.
6. В готовом мире можно воспользоваться `;mem import`; оригинальные Story Cards не удаляются. Результаты проверь через `;mem list char`, `;mem list place`, `;mem list fact`.

У подключаемых Adventure Scripts собственные изолированные `state`; влияние на текст друг друга зависит от порядка подключения. При ошибках попробуй временно выключить другие скрипты и проверить Memory Engine отдельно.

## Обновление установленной v1.0–1.4.3

1. По возможности сделай резервную копию сценария и приключения. Не удаляй существующую игру.
2. **Замени сразу все четыре вкладки** из комплекта v1.7.9; ни один файл из чужого пакета использовать нельзя.
3. Сохрани код и убедись, что в приключении подключён именно обновлённый скрипт.
4. Введи `;mem ping`, `;mem status`, `;mem list char`, `;mem list place`, `;mem validate`.
5. Только после проверки используй `;mem batch template char` и другие пакетные формы.

Схема сохраняемой памяти остаётся `state.aidm.version = 1`; предусмотрено сохранение старых объектов и заполнение отсутствующих служебных полей. Скрипт **не сбрасывает** объект памяти при неизвестном номере схемы; выдаёт диагностическую ошибку. Это защищает от автоматической потери данных при несовместимости.

> [!caution] Если команды не работают
> Открой **Game settings → Scripts** и проверь включение Memory Engine и наличие метки **ERROR**. Ошибка и текст из **Console Log** намного полезнее догадок о причинах. Ошибка компиляции Library не может быть перехвачена внутренним `try/catch`. Порядок проверки: `ping` → `status` → отдельный `help` → `batch`.

## Если вместо `;mem ping` появляется обычное повествование (v1.4.5)

Для `;mem` нужен **режим Do** и включённый Adventure Script. Новый Input принимает прямую команду и типичные обёртки `> You ...`, включая `say`, `type` и кавычки. При получении команды он сразу создаёт `state.message` с текстом `[AID Memory: команда принята; Output должен показать ответ]`, а в `state.aidm.pendingUI` сохраняет полный результат.

1. Сначала открой **Input → Script Test**, замени в тестовом JSON только `text` на `";mem ping"`, нажми Submit.
2. Проверь `state.aidm.pendingUI`: должен быть ответ с `v1.5.0`. В `state.message` должна появиться диагностическая подсказка. Результат `text` в тесте — технический маркер, не полный ответ пользователю.
3. Если оба значения есть, Input и Library работают. Теперь отправь `;mem ping` в игре. В норме **Output** заменит сюжетный ответ на квитанцию версии 1.5.0. При пропуске Output информационная подсказка может остаться видимой.
4. Если в Script Test нет этих данных или вместо них `error`, проверь содержимое всех четырёх вкладок, Save, **Game settings → Scripts** и значок ERROR.
5. Если Script Test успешен, а в игре нет даже `state.message`, вероятен неактивный экземпляр скрипта, иной режим ввода или несовпадающий прикреплённый Adventure Script. Это гипотезы; нужны фактические данные из Scripts/Inspect.

> [!important] **Не сбрасывай сохранения.** Нормальная генерация вместо ответа не означает удаления персонажей и локаций. Повторный `;mem import` для диагностики не нужен.

## Почему в Script Test появилось `Unexpected end of input` (строка 902)

Это **синтаксическая ошибка JavaScript до выполнения `Input Modifier`**. Она не связана с самим содержимым тестового JSON и не исправляется изменением поля `history` или `state`. Даже пустой `logs` в отчёте здесь ожидаем: обработчик ещё не начал работу. В отличие от первой ошибки с повторным `AM_HELP_PAGES`, **точная причина сбоя на сервере не подтверждена**.

В v1.4.4 были введены два защитных изменения: в `Input.js` убрана внешняя обёртка со строкой `return modifier(text)`; в конце расположен прямой `modifier(text);`. Большие справочные таблицы перенесены в Library: `Input.js` около 43 КБ, `Library.js` около 57 КБ (UTF-8). Разделение предотвращает избыточный размер Input; это **не доказательство**, что серверный сбой был именно ограничением длины.

### Проверка в панели Script Test

1. Выбери вкладку **Input** и открой **Script Test**.
2. В примере JSON измени только значение свойства `text` на `";mem ping"` (сохрани корректный JSON). Это **тестовые данные**, их нельзя вставлять в JS-вкладку.
3. Нажми **Submit**: в результате `state.aidm.pendingUI` должна появиться квитанция `AID Memory v1.4.5` и `state.message` с префиксом `[AID Memory`; `text` должен стать служебной фразой о журнале памяти.
4. В отдельной проверке **Output** после Input квитанция показывается пользователю, но тест двух хуков требует одного сохраняемого состояния. Проще проверить через два игровых действия: `;mem ping`, затем `;mem status`.
5. Если снова появляется `Unexpected end of input`, **не очищай память**, а проверь, что в Input последняя строка точно `modifier(text);` и в Library нет старого кода после нового. Затем сохрани обе вкладки и проверь активный экземпляр подключённого скрипта.

## Переход на v1.4.6 и проверка сброса

При обновлении с v1.4.5 **замени все четыре JS-вкладки из одного полного архива**. Старое содержимое удалить перед вставкой, а не дописывать новый код ниже. `test.js` используется только локально и в AI Dungeon не вставляется. Схема сохранённых данных `state.aidm.version = 1` сохраняется, переносить или сбрасывать базу не нужно.

Сначала проверь отдельными действиями в Do:

```text
;mem ping
;mem status
;mem help reset
;mem reset
```

Последняя команда **ничего не удаляет**. Убедись, что версия в `ping` — **1.4.6**. Не используй команды `reset ... confirm`, если действительно не требуется очистить данные. Подробности: [[AI - AI Dungeon Memory Engine все команды#Полный сброс памяти и Story Cards]].

## После установки: обязательная проверка

Отправляй команды в **Do по одной**, а не одним абзацем:

```text
;mem ping
;mem status
;mem list char
;mem list place
;mem help char
```

В ответ на `ping` должна появиться версия **1.4.5**. Если сообщение осталось `v1.4`, `v1.4.1`, `v1.4.2` или `v1.4.3` или `v1.4.4`, значит активен старый скрипт или часть вкладок не сохранена. Если отображается «Несовместимые вкладки», найди ошибочно оставленный старый файл и замени **все четыре** ещё раз.

При синтаксической ошибке с прежним номером строки 867 в редакторе всё ещё есть старый `Library.js` и старый `Input.js` либо новая вкладка была **добавлена в конец** вместо полной замены.

## Базовые команды

```text
;mem ping
;mem status
;mem list char
;mem list place
;mem world
;mem help batch
;mem batch template place
```

**Префикс `;mem`** выбран, потому что `!` может переключать Do в Story, а `:mem` может перехватить отдельный RPG-скрипт. Старые `!mem` и `:mem` код распознаёт для совместимости, но для ввода вручную используй `;mem`.

Команды в режиме Do могут приходить с добавленной точкой. Для команд просмотра парсер удаляет служебную точку; для описаний содержательный текст сохраняется. Подробности — [[AI - AI Dungeon Memory Engine диагностика и ограничения]].

## Пакетное редактирование

Скопируй блок целиком в **одно действие Do**:

```text
;mem batch
§;mem char Алиса | bio=Начинающая художница
§;mem char Дана | bio=Руководитель отдела
§;mem rel Алиса -> Дана | view=Уважение
§:apply
```

Ошибка любого поля отклоняет пакет, а уже сохранённые Story Cards автоматически не откатываются. Для готовых форм используй `;mem batch template char/place/rel/all`. Полный синтаксис и ограничения: [[AI - AI Dungeon Memory Engine пакетное заполнение]].

## Документы Obsidian

Помести содержимое `Obsidian/` из архива в ту же папку хранилища, разрешив замену файлов с одинаковыми именами. **Не переименовывай** заметки и не создавай новые версии файлов по номеру сборки. Начальная точка: [[AI - AI Dungeon Memory Engine оглавление]]. История исправлений ведётся в **[[AI - AI Dungeon Memory Engine обновления]]**.

При переходе со старой структуры вручную удали устаревшие заметки `AI - AI Dungeon Memory Engine изменения v1.2.md` и `AI - AI Dungeon Memory Engine изменения v1.3.md`, если они ещё присутствуют.

## Ограничения

- Ручные команды обычно требуют игрового хода модели; они не гарантированно бесплатны.
- Структура `state.aidm` изолирована от `state.rpg` другого скрипта. Время, деньги и числовые навыки не синхронизируются.
- Нет полноценного встроенного резервного экспорта базы из интерфейса скрипта; **не очищай сохранения ради обновления**.
- Автоотчёты зависят от поведения ИИ-модели. Для ручного режима введи `;mem auto off`.

## Обновление до v1.6.1

Заменить **все четыре JavaScript-вкладки** из одного полного пакета. Старый `state.aidm` не очищать. Если Universal RPG уже создал Story Card экспорта, повторный `:aidm export` не нужен: `;mem import rpg card` прочитает существующую карточку.

## Перенос памяти из другого приключения

Подключение одной и той же версии скрипта **не переносит** `state.aidm` автоматически: это независимые игры. Для сохранения мира и персонажей используй [[AI - AI Dungeon Memory Engine перенос между историями]]. Другие Adventure Scripts, история игры и Memory Bank этим способом не копируются.
