# Memory Engine — план исправлений и приёмки

Подробные доказательства, воспроизведения, приоритеты и ограничения проверки обоих скриптов: [[AI - AI Dungeon Memory Engine аудит и план исправлений]]. Этот документ задаёт порядок работ Memory Engine; результаты ручной приёмки отмечаются в [[AI - AI Dungeon Memory Engine чек-лист проверки в AI Dungeon]]. Соседний план: [[AI - AI Dungeon Universal RPG план исправлений]]. Пункты ниже ещё не считаются выполненными исправлениями.

## Последовательность

- [ ] **M-P01, P1 — воспроизводимые тесты.** Убрать зависимость исторических наборов от расположения hooks в tests и жёсткой версии 1.7.0; отделить миграционные fixtures от состояния после инициализации. Критерий: штатный runner выполняет актуальные проверки без переписывания тестового исходника, а reset-preview сравнивается с корректной базой. Связь с аудитом: пункт 9.
- [ ] **M-P02, P1 — согласованность undo и карточек.** После отката заново синхронизировать затронутые управляемые карточки; сохранить связи и резервные копии при отказе API. Критерий: изменение → Output → undo → Output возвращает согласованные данные и Entry. Аудит: 4; проверки M-S20, M-S28.
- [ ] **M-P03, P1 — перенос всех активных сведений.** Включить extras в переносимую каноническую часть, не переносить чужие ID и резервные копии как местные связи. Проверить all/world, совместимость portable v1 и настройки календаря. Критерий: перенос не теряет сведения, видимые рассказчику. Аудит: 5; M-S29.
- [ ] **M-P04, P1 совместно с RPG — общий бюджет контекста.** Согласовать приоритеты защищённой памяти, механики и истории, проверить оба порядка Context. Критерий: итог не превышает бюджет и содержит текущий результат броска. Аудит: 3; M-S31, M-S32.
- [ ] **M-P05, P2 — сравнение полного текста.** Отделить нормализацию имён от дедупликации фактов и длинных предложений. Критерий: разные концы текстов после 110/500 символов не теряются, точные повторы не размножаются. Аудит: 6; M-S07, M-S09.
- [ ] **M-P06, P2 — владение полями RPG/Memory.** Явно хранить источник и ручное переопределение даты, места, профессии и описания героя; определить правила переименования и связи. Критерий: повторный снимок не создаёт неожиданный дубль и не затирает ручной канон. Аудит: 7; M-S25, M-S26, M-S32.
- [ ] **M-P07, P2 — устаревание extras.** Распознанные сведения предлагать для структурированных полей с указанием источника; произвольные строки оставить редактируемыми. Критерий: удалённая/устаревшая профессия не возвращается из скрытой копии. Аудит: 8; M-S21.
- [ ] **M-P08, P2 — исходные модули и сборка.** Выделить модули состояния, импорта, карточек, команд и подтверждения памяти; собирать те же четыре вкладки с проверкой версии, синтаксиса и размера. Критерий: воспроизводимый комплект и совместимые сохранения, один экземпляр каждой общей функции. Аудит: 10.
- [ ] **M-P09 — приёмка на платформе.** Пройти весь [[AI - AI Dungeon Memory Engine чек-лист проверки в AI Dungeon]], начать с Алисы и одной тестовой Custom «Записка». Пункт закрывается только по результатам пользователя на поставляемой версии; автотесты не заменяют его.

## Что уже реализовано, но требует ручного подтверждения

Комплект 1.8.0 содержит сохранение метаданных при adopt, show/repair, явную связь и снятие связи, передачу Custom и защиту связанных фактов. Их локальные тесты описаны в аудите. В живом AI Dungeon успешность этих функций пока не подтверждена. Сообщённое исчезновение Алисы считается проблемой до проверки M-S13–M-S15.

## Порядок выпуска

Сначала M-P01 и общий бюджет вместе с первыми защитами RPG; затем undo и portable, дедупликация, владение полями и extras. После стабилизации контрактов — модульная сборка. Каждый выпуск кода получает новую версию четырёх вкладок и описание поведения в журнале. Эта правка документации имеет отдельную ревизию и не меняет версию кода.
