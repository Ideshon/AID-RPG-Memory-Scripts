# AI Dungeon — Memory Engine: обновления

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine установка]] · [[AI - AI Dungeon Memory Engine диагностика и ограничения]]

> [!info] Текущая версия скрипта — 1.7.4
> Здесь описывается поведение новых версий. Новые выпуски дополняют этот документ; имя файла остаётся неизменным. Номер версии указывается внутри заметки.

## Правило ведения журнала

Для каждой новой версии описывай только изменения, важные пользователю: возможности, поведение и миграцию данных. Не добавляй пункты «Изменены», «Обновление», списки затронутых файлов, смену версий в заголовках и отчёты о проверках. Порядок установки размещай в отдельной заметке.

## Версия 1.7.4 — изменение сохранённых фактов (7 ноября 2026)

- `;mem edit fact ID | Новый текст` исправляет факт без смены ID; вариант с двумя полями меняет также тему.
- Исправленные заметки, перенесённые из RPG, не возвращаются к старому тексту при повторном импорте того же снимка.

## Версия 1.7.3 — отключаемый календарь (7 ноября 2026)

- `;mem date off` убирает текущую дату и часы Memory Engine из контекста рассказчика, приостанавливает календарные напоминания и новые предложения даты; летопись и планы сохраняются.
- `;mem date on` возвращает календарь. При выключенном режиме часы Universal RPG продолжают попадать в контекст через сам RPG-скрипт.

## Версия 1.7.2 — исправлена совместимость вкладок (7 ноября 2026)

- Устранена ошибочная блокировка Memory Engine после установки полного комплекта: проверки совместимости больше не требуют устаревшую версию 1.7.0.
- `;mem ping`, `;mem status` и справка показывают актуальную версию.

## Версия 1.7.1 — RPG календарь и перенос заметок (7 ноября 2026)

- RPG снимок сохраняет дату по игровому календарю из 12 месяцев по 30 дней.
- `;mem import rpg calendar` синхронизирует Memory Engine по снимку: валидную григорианскую дату и время применяет; невозможную григорианскую дату не подменяет, но сохраняет RPG календарь в снимке и синхронизирует время.
- `;mem import rpg notes` переносит импортированные заметки RPG в факты Memory Engine без повторных дублей.

## Версия 1.7.0 — перенос памяти между приключениями (5 ноября 2026)

- Реализованы команды `;mem transfer export`, `;mem transfer export world`, `;mem transfer part N`, `;mem transfer import ID N/TOTAL DATA`, `;mem transfer status`, `;mem transfer apply`, `;mem transfer apply confirm`, `;mem transfer apply replace confirm`, `;mem transfer cancel`, `;mem help transfer`.
- Обмен основан на зафиксированном JSON-снимке и отдельных безопасных для копирования частях; контрольная сумма проверяется перед изменением базы. Порядок ввода частей произвольный, повтор одной и той же части допустим.
- Для непустой памяти требуется отдельная явная команда замены. Старые собственные Story Cards целевой истории не удаляются автоматически — до замены потребуется `;mem reset cards confirm`. Пользовательские карточки не затрагиваются.
- При переносе сохраняются подтверждённые сущности, но не ожидающие подтверждения предложения, `rpgSnapshot`, история действий, Memory Bank, состояние других скриптов и сами Story Cards. При копировании исходные `sourceCardId` удаляются, поскольку ID действуют только внутри приключения.
- Добавлен `test_transfer.js` с независимыми тестовыми состояниями, длинными русскоязычными данными, частями вне порядка, повторной вставкой, целостностью, заменой, защитой Story Cards и разграничением RPG.
- Технические команды другого скрипта (например, `:setup` и `:aidm export`) больше не вызывают AIDM-рекордер и не увеличивают счётчик ответов «без распознанного маркера». Старые накопленные значения счётчика не сбрасываются.
- Новая отдельная заметка [[AI - AI Dungeon Memory Engine перенос между историями]]. Стабильные имена предыдущих заметок сохранены.

**Установка:** заменить все четыре игровые JS-вкладки v1.7.0. Очистка `state.aidm` не нужна. Работа с реальными приключениями AI Dungeon пока не проверена.


## Версия 1.6.2 — журнал RPG и диагностика контекста (5 ноября 2026)

- Добавлен безопасный отладочный режим `;mem debug on/full/off/status/last/context`: хуки Input, Context, Output; текст и объём добавленного в контекст блока; успешный/пропущенный JSON-отчёт; причины отказа при лимите контекста.
- При обычном ходе технические сведения выводятся через `state.message`, **не** в художественный текст. При наличии уведомления о новых предложениях памяти оно сохраняется рядом с debug.
- В `state.aidm.debugTrace` сохраняется **только последний игровой ход**, не история всех промптов. Отладочные команды не заменяют данные персонажей и не пишут в Universal RPG.
- Подтверждено по исходникам: `rpgSnapshot.notes` из импорта RPG не входят в `amContext()` и не становятся автоматически фактами. Система заметок RPG остаётся независимой. Уточнена инструкция о разграничении журналов.
- Добавлен отдельный `test_debug.js`; повторно выполнены старые тесты, включая импорт Universal RPG и режим проверки предложений.
- **Ограничение:** показанное дополнение Memory Engine не является полным конечным контекстом платформы. `state.message` другого скрипта может переопределить отладку; проверь `;mem debug context` и View Context в AI Dungeon.

**Обновление:** заменить все четыре JS-вкладки из одного пакета v1.6.2, не очищая `state.aidm`. Скрипт Universal RPG не меняется.


## Версия 1.6.1 — исправление импорта RPG в режиме Do (5 ноября 2026)

### Исправление

- Команды `;mem import rpg card.`, `;mem import rpg status.`, `;mem import preview.`, `;mem import refresh.` и другие **простые подкоманды импорта с автоматически добавленной точкой** теперь обрабатываются так же, как без точки. Это исправляет ситуацию, когда после `:aidm export` Universal RPG Memory Engine вместо импорта показывал общую подсказку «Синтаксис».
- Пунктуация в содержимом `;mem import plot summary | Текст.` и JSON для `;mem import rpg paste | {JSON}` не изменяется. Обработка специальных данных остаётся строгой.
- Добавлены регрессионные тесты с Story Card `Custom`, ключами `__AID_RPG_EXPORT_V1__`, Entry с `[AID_RPG_EXPORT:1]`, полями 9/7/11/5 и проверкой повторного импорта без дубликатов. Также проверены оба варианта Do, сохранение существующего героя и исходной Story Card.
- **Контракт экспорта Universal RPG v2.28 не менялся.** Доработана только сторона Memory Engine. Старые данные `state.aidm` сохраняются. Версия `state.aidm.version` остаётся `1`.

### Установка

Полностью замени **все четыре вкладки** из одного пакета v1.6.1. Затем используй `;mem ping` → `;mem import rpg card` → `;mem import rpg status`. Повторно экспортировать RPG не требуется, если служебная Story Card уже существует и актуальна. Проверено локально, не на сервере AI Dungeon.

## Версия 1.6.0 — проверяемая автопамять (5 ноября 2026)

### Скрипт

1. Изменён порядок автоматического извлечения: `Output` вместо немедленного `amReport` создаёт отдельные предложения с ID в `reviewQueue`. Без решения игрока они **не изменяют** персонажей, отношения, факты, календарь или Story Cards.
2. Добавлен третий уровень `observations` для слухов, догадок и намерений. Наблюдения не попадают в контекст как подтверждённые факты, но их можно осознанно принять или отклонить.
3. Через официальный `state.message` показываются количество и первые три предложения после сцены; текст рассказчика не засоряется уведомлениями. Полный список: `;mem review`, источник: `;mem review ID`.
4. Новые команды: `;mem accept ID`, `;mem accept ID replace`, `;mem edit ID | текст`, `;mem reject ID`, `;mem review log`, `;mem sources char/place/rel ...`, `;mem help review`. `;mem pending` теперь показывает очередь.
5. В `provenance` фиксируются источники ручных записей, импорта и подтверждённых предложений. Уже существующие поля без метки происхождения считаются защищёнными. Принятие конфликтующего предложения без `replace` или осознанной правки блокируется.
6. Подавляются текстовые дубликаты в очереди и недавно принятые/отклонённые предложения; сохранён журнал решений. Лимит очереди 60 предложений, история 100 решений. Это **не семантическая проверка**.
7. `amSnapshot` дополнен данными очереди/источников для корректного отката подтверждения; данные `state.aidm.version=1` не очищаются, импорты Story Cards/Plot/Universal RPG сохраняют прежний контракт.
8. Добавлен `test_review.js`, обновлён `test.js` под модель подтверждения, сохранён `test_import.js`. Проверены раздельная загрузка хуков, отказ, редактирование, защита ручных данных, текущие и старые сохранения, импорт, Story Cards, undo и JSON без изменений.

### Документация

Создана заметка [[AI - AI Dungeon Memory Engine проверка автопамяти]] и обновлены тематические документы, Help, диагностика и общий справочник. Оглавление содержит только ссылки с краткими описаниями. Сохранены существующие имена файлов.

### Ограничения

Оповещения использует `state.message`; их отображение зависит от интерфейса AI Dungeon. Встроенный Script Test и локальные проверки не заменяют проверку внутри реального приключения. Без структурированного отчёта модели очередь не заполняется.

## Версия 1.5.0 — импорт Story Cards, Plot и мост Universal RPG (4 ноября 2026)

### Скрипт

1. `;mem import` продолжает переносить Character/Location/Faction в свои разделы, а **любой нестандартный тип Story Card** в именованные факты. Для Custom/Class/Race/Item/Lore сохраняются исходный `type`, **все `keys`**, ID источника и текст до 1100 символов. Ключи участвуют в отборе факта для контекста. Собственные карточки `[AIDMEM:1:...]` и служебный RPG-экспорт не повторно импортируются как обычные факты.
2. `;mem import refresh` сверяет кастомные карточки с уже импортированными фактами и обновляет текст/ключи без создания дубликатов. Старые метки импорта v1.4.7 поддерживаются; существующие вручную изменённые стандартные Character/Location/Faction не перезаписываются.
3. `;mem import preview` — предпросмотр числа доступных Story Cards и полей Plot без изменений. Обычный `;mem import` дополнительно пытается импортировать **только доступные через `state.memory`** Plot Essentials (`context`) и Author's Note (`authorsNote`). Если это поле уже изменено другим скриптом, сохранится именно доступное скрипту значение; произвольные компоненты UI Plot не читаются.
4. `;mem import plot auto` — принудительно повторно считать доступные поля; `;mem import plot essentials | Текст` и аналоги `summary`, `authorsnote`, `instructions` — сохранить вручную скопированные Plot Components. `;mem import plot status` — источники и длины. Исходный Plot не меняется. В контекст добавляется лишь короткая справочная выдержка из Essentials/релевантного Summary; импортированные AI Instructions и Author's Note **не применяются повторно**.
5. Добавлен безопасный **приёмник экспорта Universal RPG**: `;mem import rpg paste | {JSON}` либо `;mem import rpg card`, читающий Custom Story Card с маркером `[AID_RPG_EXPORT:1]`. Снимок сохраняется в `rpgSnapshot`. Биография и роль героя могут заполнить только пустые поля персонажа; механические значения остаются отдельно, **не влияют** на RPG и не пересчитываются скриптом памяти.
6. `;mem import rpg status` показывает импортированный снимок; `;mem import rpg` объясняет схему обмена. Экспортирующую сторону Universal RPG **не меняли** и не добавляли в этот архив: для автоматизированной передачи ему потребуется собственный экспорт в указанном формате. Прямой доступ к `state.rpg` другого Adventure Script отсутствует.
7. Новые поля `plotImports` и `rpgSnapshot` инициализируются без очистки старой базы (`state.aidm.version` по-прежнему `1`). Сброс `reset data/all` очищает их; предпросмотр учитывает их количество.
8. Добавлен `test_import.js`: импорт произвольных типов, ключи, обновление, отсутствие дубликатов, Plot API/ручной ввод, RPG JSON/Story Card, отсутствие доступа к чужому `state` и старые сохранения. Существующие тесты сохранены.

### Ограничения и установка

- Синтаксис всех прежних команд сохранён. Для этой версии следует **заменить все четыре вкладки**, не смешивая версии. База и собственные Story Cards не очищаются.
- Story Summary и AI Instructions **не представлены отдельными полями документированного Script API**. Их импорт выполняется вставкой текста; встроенный Memory Bank отдельно недоступен.
- Автоматическая запись по-прежнему использует JSON, предложенный рассказчиком, **без независимой проверки достоверности**. Улучшения контроля источников и очереди конфликтующих автоматических правок описаны в [[AI - AI Dungeon Memory Engine автообновление и Story Cards]] как следующие этапы, не как реализованная функция.
- Реальное совместное выполнение с подключённым Universal RPG в AI Dungeon не тестировалось; тесты относятся к локальной модели вызовов API.

## Версия 1.4.7 — подробный предпросмотр сброса (4 ноября 2026)

### Изменения JavaScript

1. `;mem reset data`, `;mem reset cards`, `;mem reset all` без `confirm` теперь показывают **живой детальный перечень** того, что удалит подтверждённая операция. `;mem reset` показывает обе группы и выбор режима.
2. Для базы отдельно подсчитываются: описание мира, дата, время, текущее место, персонажи, их навыки, локации, фракции, направленные отношения, факты, события, записи дней и месяцев, сюжетные линии, планы, недавние фрагменты, метки импорта и элементы очереди обновления карточек. Настройки и технические счётчики указываются как сбрасываемые служебные данные. Вложенные навыки и связи событий **не следует складывать** в единый итог объектов.
3. Для собственных Story Cards показывается общее число и разбивка по маркерам `char`, `place`, `faction`. Если список недоступен, выводится **«недоступно»**, а не число 0. Чужие карточки без маркера не учитываются.
4. При получении квитанции предпросмотра Output **пропускает фоновую синхронизацию карточек на этом ходу**. Таким образом команда просмотра не инициирует создание или удаление Story Cards. Настройки `auto/cards` и очередь при просмотре не меняются.
5. Сами подтверждённые команды `reset ... confirm` остались прежними: защита через `confirm`, максимум 30 удалений карточек за вызов, частичное завершение при ошибке API и запрет пакетного вызова.
6. Добавлены регрессионные тесты точных количеств по категориям, неизменности данных и Story Cards при предпросмотре, пересчёта после изменения базы и всех трёх режимов.

### Обновление и ограничения

Заменить **все четыре JS-вкладки** из одного комплекта v1.4.7; сохранённые записи `state.aidm.version=1` сохраняются. Для знакомства с новым предпросмотром достаточно безопасных `;mem reset data`, `;mem reset cards` и `;mem reset all`. Перед подтверждением больших сбросов рекомендуется копия приключения. Скрипт проверен локально; выполнение внутри AI Dungeon требует проверки в игре.

## Версия 1.4.6 — штатный безопасный сброс памяти (4 ноября 2026)

### Изменения JavaScript

1. Добавлены `;mem reset data confirm`, `;mem reset cards confirm` и `;mem reset all confirm`, а также безопасные `;mem reset` (предпросмотр) и `;mem help reset` / `;mem help сброс`.
2. Единый фабричный объект `amBlankState()` позволяет очистить `state.aidm` **на месте**, сохранив ссылку, которой пользуются Input и Output в текущем ходе. Схема данных по-прежнему `version: 1`; данные других Adventure Scripts не затрагиваются.
3. Собственные Story Cards распознаются только по **строгой метке в начале Entry** `[AIDMEM:1:char/place/faction:...]`, а не по имени или типу карточки. Удаление выполняется **по убыванию индексов** через официальный `removeStoryCard(index)`.
4. При `reset cards` очередь карточек очищается и `cards` выключается, иначе Output мог бы создать их заново. Для `reset all` при неполном удалении временно выключаются `auto` и `cards`, **база сохраняется до завершения**. За один вызов удаляется максимум 30 карточек; повторный вызов продолжает процесс.
5. При недоступности списка Story Cards или `removeStoryCard` **сброс карточек/all отклоняется**. Если API удаления сообщает ошибку, вывод содержит количество удалённых и оставшихся карточек; пользователь может повторить команду.
6. Подтверждение `confirm` обязательно. Команды сброса не разрешены внутри `;mem batch` и не попадают в механизм `;mem undo`.
7. Тесты расширены изолированными сценариями: собственные/ручные/кастомные карточки, подтверждение, работа всех четырёх хуков, частичное удаление при 35+ карточках, ошибка API, повторный вызов, отсутствие пересоздания и сохранение пользовательских карточек.

### Обновление и ограничения

Полностью заменяй **все четыре JS-файла** из одной v1.4.6. Не требуется сбрасывать старые данные. Сначала `;mem ping` и `;mem help reset`. Для критических данных перед сознательной очисткой сделай резервную копию приключения. **Ни один сброс не удаляет** историю сюжета, встроенный Memory Bank, пользовательские Story Cards или данные Universal RPG. При `reset data` уже существующие собственные Story Cards также сохраняются; если это нежелательно, используй `reset all`. Локальные тесты выполнены; живой AI Dungeon остаётся непроверенным.

## Версия 1.4.5 — защита от обычной генерации вместо ответа на команду (4 ноября 2026)

**Сообщение пользователя:** после установки v1.4.4 вместо квитанции по `;mem` появлялось обычное сюжетное продолжение. Точный текст, который получал Input в реальном приключении, и ошибка платформы не предоставлены. Поэтому причина отказа **не доказана**, но выявлен и исправлен недостаточно гибкий разбор Do/Say.

### Изменения JavaScript

1. `Input.js`: единая функция `amNormalizePlayerCommand` распознаёт `;mem` в прямом вводе, `> You ;mem ...`, `> You try to ...`, `> You type ...`, `> You say: ...`, в кавычках и при вставке одиночной команды с ограждением Markdown. Многострочные команды `;mem batch` сохраняют `§` и переносы строк.
2. `Input.js`: после перехвата команда записывается в `state.aidm.pendingUI` **и** в стандартное `state.message`. Последнее — независимая диагностическая подсказка: видно, что Input отработал, даже если Output не показал квитанцию.
3. `Input.js`: если введён текст с `;mem`, но его формат не распознан, он **не отправляется рассказчику как обычная реплика**: вместо этого выводится диагностическая подсказка. Это предотвращает молчаливый отказ на части неизвестных обёрток.
4. `Library.js` и `Output.js`: при успешной замене ответа служебная подсказка очищается; при ошибке Output сохранённая квитанция возвращается как запасной ответ.
5. Добавлены регрессионные тесты 12 видов Do/Say-ввода, проверки `state.message` без Output и полного замещения художественного ответа. Все четыре скрипта компилируются вместе с Library. Формат сохранений остаётся `state.aidm.version=1`.

### Установка и проверка

Полностью заменить **Library.js, Input.js, Context.js, Output.js** из *одного* пакета 1.4.5. Во вкладке Input → Script Test установить `text: ";mem ping"`; после Submit увидеть `state.aidm.pendingUI` и `state.message`. В игре отправить `;mem ping` в Do. Если появляется только обычная генерация и **нет** информационного сообщения AID Memory, нужно проверить, включён ли правильный Adventure Script, а также его ERROR и Console Log. При успешно принятой команде Output должен показывать `AID Memory v1.4.5`. Не очищать `state.aidm` и не импортировать карточки повторно.

**Граница проверки:** локальные тесты подтверждают поведение JavaScript на проверенных вариантах входа; работа конкретной подключённой копии в AI Dungeon до игрового теста остаётся неподтверждённой.

## Версия 1.4.3 — устранение ошибки компиляции Input Modifier (4 ноября 2026)

### Подтверждённая причина

В живом приключении AI Dungeon появилась ошибка **`Identifier 'AM_HELP_PAGES' has already been declared [<isolated-vm>:867:7]`** при `;mem ping`. При сравнении файлов выяснилось, что `Library.js` из **v1.4** имеет **830 строк** и объявляет `AM_HELP_PAGES` на строке 648; в `Input.js` из **v1.4.1/1.4.2** та же переменная объявлена на строке 36. При объединении старой Library с новым Input второе объявление находится на строке **867** (830 + разделитель + 36). Сценарий воспроизведён в Node.js VM **с идентичным сообщением и номером строки**.

Это ошибка несовместимого набора вкладок, а не повреждение данных `state.aidm`. Ранее проводимые тесты запускали файлы из одной сборки и потому не могли её обнаружить.

### Изменения JavaScript

1. Весь код `Input.js` (включая `AM_HELP_PAGES`, алиасы, обработчик и шаблоны) помещён в **локальную область видимости**. Общие имена старой Library больше не приводят к ошибке повторного объявления при объединении кода.
2. Добавлен явный маркер сборки `AM_ENGINE_BUILD = '1.4.3'` в `Library.js`, проверяемый `Input.js`, `Context.js` и `Output.js`. При старой Library Input сообщает о несоответствии версий вместо использования несовместимых функций.
3. Сохранён обычный ответ хука Input из изолированной функции; это проверено регрессионным тестом.
4. Тесты расширены сценарием повторного объявления с `AM_HELP_PAGES` и проверкой отсутствия синтаксической ошибки при новом Input. Проверены команды `;mem ping`, `;mem help`, пакетный ввод, отображение выходной квитанции и сохранение прежних данных.
5. Схема памяти остаётся `state.aidm.version = 1`; миграции базы не требуется. Логика записей и параметры игры не изменялись.

### Установка

**Полностью замени содержимое всех четырёх вкладок** `Library.js`, `Input.js`, `Context.js`, `Output.js` из единого полного ZIP v1.4.3. Старый код нужно удалить, не дописывать поверх него. После Save отправь `;mem ping` и проверь, что выводится **1.4.3**. Не сбрасывай данные и не импортируй Story Cards повторно без необходимости.

### Проверка и ограничения

Ошибка версии `AM_HELP_PAGES` воспроизведена локально точно. Новая сборка проходит локальные тесты, включая смешанное старое окружение без повторного объявления. Реальное выполнение v1.4.3 в AI Dungeon ещё не подтверждено; непредусмотренные сочетания файлов или подключаемых скриптов могут вызывать другие ошибки.

Если ни одна команда не отвечает, открыть **Game settings → Scripts**, посмотреть **ERROR** на Memory Engine и текст сообщения. Если ошибки нет, проверить включение скрипта, сохранение всех вкладок и конфликт подключённых скриптов; см. [[AI - AI Dungeon Memory Engine диагностика и ограничения]].

## Версия 1.4 — пакет из обычных команд (4 ноября 2026)

### Изменения JavaScript

1. В `;mem batch` разрешён новый формат: строки **`§;mem char ...`**, **`§;mem place ...`**, **`§;mem rel ...`** и другие привычные одиночные команды. В конце — `§:apply`. Можно копировать стандартную команду, добавив только `§`.
2. Поддерживаются категории: `char`, `skill`, `place`, `faction`, `rel`, `arc`, `world`, `date`, `here`, `fact`, `event`, `summary`, `plan`, `delete`. Команды просмотра и режимов внутрь пакета не принимаются.
3. При сохранении настоящих переносов строк разрешён вариант **без `§`**, завершённый `;mem apply`. Поскольку Do может склеивать строки, предпочтителен первый вариант.
4. **Новые шаблоны:** `;mem batch template char/skill/rel/place/faction/world/fact/event/day/arc/plan/delete/all`. Они выдают пример из обычных команд. Старые шаблоны доступны через `;mem batch template legacy char/place/faction/arc/all`.
5. Предыдущий формат `§поле=значение` полностью сохранён. Не смешивать оба формата в одном блоке.
6. Пакеты по-прежнему **атомарны**: при ошибке одной команды ни одно изменение не сохраняется. Можно создать дочернюю локацию раньше родителя в пределах одного пакета. Доступен `;mem undo` — только для базы памяти; удалённые/обновлённые Story Cards не возвращаются автоматически.
7. Для `delete` добавлено пакетное удаление записей по имени или ID с проверкой существования и защитой родительских локаций от удаления при наличии детей.
8. Ограничения: до **3950 символов** и **55 развёрнутых директив**, включая поля составных команд.

### Обновление поверх v1.3.1

- Замени **только `Library.js`**, не очищая `state.aidm`. `Input.js`, `Context.js`, `Output.js` не изменены.
- Замени существующие Markdown-документы в Obsidian, сохранив прежние имена файлов. Единое оглавление осталось только со ссылками.

- Тесты: существующий набор и новые проверки копируемых команд, шаблонов, неверных полей, отклонения всего пакета, отката, удаления и зависимостей локаций. Полноценное воспроизведение в AI Dungeon не подтверждено.

## Версия 1.3 — префикс и тематическая справка (3 ноября 2026)

### Изменения JavaScript

1. Основной префикс команд изменён с `!mem` на **`;mem`**. Старые `!mem` и `:mem` принимаются для совместимости при прямой отправке, но `!` может переключать режим Story, а `:mem` может перехватываться Universal RPG.
2. Реализована **21 тема** `;mem help Тема`: начало, статус, мир, локации, фракции, персонажи, навыки, отношения, факты, события, летопись, сюжетные линии, планы, пакетный ввод, автоматизация, Story Cards, редактирование, откат, диагностика, синтаксис и общий список.
3. Добавлены русские синонимы: `;mem help персонажи`, `;mem help карта`, `;mem help отношения`, `;mem help календарь`, `;mem help пакет` и другие.
4. `;mem help` выводит список тем; `;mem help all` — краткий перечень команд.
5. `;mem batch help` открывает ту же расширенную инструкцию, что `;mem help batch`.
6. Учтена завершающая пунктуация, которую режим Do может добавить к `;mem help char.` и `;mem batch help.`.

### Обновление поверх v1.2 / v1.2.1

Для функциональных изменений v1.3 достаточно заменить **Library.js** в отдельном Adventure Script Memory Engine. В полном пакете находятся все четыре вкладки (`Library.js`, `Input.js`, `Context.js`, `Output.js`), `test.js` и `Obsidian/`. `test.js` предназначен **только** для локальных тестов Node.js.

Проверь `;mem status`, `;mem help`, `;mem help char`, `;mem batch help`. Формат `state.aidm.version = 1` не изменился; очистка существующей памяти не требуется.

> [!warning] Горячие клавиши
> Символ `;` выбран для обхода конфликта клавиши `!` с режимом Story; отсутствие конфликта `;` со всеми версиями интерфейса и раскладками AI Dungeon не подтверждено. Проверь символ в режиме Do.

В переходной сборке исправлены упоминания старого префикса в части сообщений и шаблонов; пользовательский синтаксис с `;mem` был подготовлен до тематического Help v1.3. Следующий релиз v1.3 закрепил основной префикс и расширил справку. Отдельная установка v1.2.1, если используется v1.3, не нужна.

## Версия 1.2 — проверка данных и контекста (3 ноября 2026)

Это были **изменения исполняемого JavaScript**, не только документации.

| Область | Реализованное изменение | Ограничение |
|---|---|---|
| Родительская локация `parent` | Проверка существования родителя; запрет ссылки на себя и циклов. В `batch` родитель и ребёнок могут создаваться вместе. | Нет координат, маршрутов и автоматического движения. |
| `;mem validate` | Поиск отсутствующих родителей и циклических ссылок, в том числе в данных старых версий. | Команда только диагностирует, не исправляет. |
| Удаление локации | Родителя с дочерними местами удалить нельзя, пока дочерние записи не перенесены или удалены. | NPC `at` и текстовое `territory` не перепривязываются. |
| `kind`, `territory` | Добавлены к контексту выбранных локаций и фракций. | Не управляют физической доступностью и механикой RPG. |
| `trust`, `tags` | Появились в контексте отношений и Story Cards первого участника. | Доверие остаётся описательной шкалой. |
| Сюжетные `result`, `start`, `end` | Передаются в контекст выбранной сюжетной линии. | Не запускают таймеры или события. |
| Значимость событий | `importance` от 1 до 3 участвует в приоритете выборки до 4 событий из последних 90; уровень выводится в `day` и `timeline`. | Приоритет не гарантирует упоминание в ответе модели. |
| Календарные планы | ID показываются при создании, в `calendar` и `day`. | Прошедшие планы могут оставаться в календаре. |
| Прямые команды | Неизвестные и пустые поля `char/place/faction/arc/rel`, некорректное `trust` отвергаются. | Нет универсального очищения отдельного поля. |
| `;mem here` | Текущая локация и до двух её родителей приоритетно подаются в контекст. | Учитывается лимит контекста 3200 символов. |

### Переход с v1.1

- Замени JavaScript в существующем скрипте Memory Engine; не трогай Universal RPG.
- Проверяй `;mem status`, `;mem validate`, `;mem map`, `;mem calendar` (в старой v1.2 использовался также префикс `!mem`).
- Если `validate` выявляет старую некорректную цепочку родителей, создай недостающее место или исправь `parent` у дочернего. Для удаления родителя сначала перенеси/удали его дочерние места.
- `state.aidm.version` остаётся равен `1`; неправильные связи старых версий не исправляются сами.
- `;mem undo` не откатывает ранее синхронизированные Story Cards. Перед обновлением сделай резервную копию приключения доступными средствами платформы.

## Версия 1.1 — пакетное заполнение

Добавлен **`;mem batch`** (в выпущенной версии v1.1 изначально использовался префикс `!mem`): ввод нескольких полей и сущностей одним сообщением через строки `§поле=значение`, обязательное завершение `§:apply` и готовые шаблоны `template char/place/faction/arc/all`.

Валидация проводится до записи: ошибочный пакет **не сохраняет частичные изменения**. Поддерживаются персонажи, отношения, локации, фракции, сюжетные линии, события и календарные планы. Добавлен одношаговый откат последнего подходящего пакета через `;mem undo` с ограничением: Story Cards не откатываются автоматически. Подробная актуальная инструкция: [[AI - AI Dungeon Memory Engine пакетное заполнение]].

## Версия 1.0 — первый выпуск

Первая версия отдельного Adventure Script: база `state.aidm`, команды для мира, локаций, фракций, персонажей, отношений, фактов, событий, сводок, сюжетов и планов; выбор актуальных фактов в контекст, попытки автоизвлечения JSON-отчётов рассказчика, создание собственных Story Cards и импорт поддерживаемых карточек пользователя. Точные команды и ограничения **текущего** выпуска см. [[AI - AI Dungeon Memory Engine все команды]].

## Не реализовано в версии 1.4

- Отдельная модель-секретарь, независимая проверка достоверности и полноценный графический интерфейс Banshee.
- Географические расстояния, маршруты и автоматическое перемещение NPC при изменении `here`.
- Автоматическая синхронизация даты, навыков и состояния с Universal RPG.
- Универсальный экспорт всей базы, многоуровневый журнал откатов и автоматический откат собственных Story Cards.

См. [[AI - AI Dungeon Memory Engine диагностика и ограничения]] и [[AI - AI Dungeon Memory Engine совместимость с RPG]].
