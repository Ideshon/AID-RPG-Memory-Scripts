# AI Dungeon — Memory Engine: диагностика и ограничения

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine установка]] · [[AI - AI Dungeon Memory Engine автообновление и Story Cards]]

## Отладка работы Memory Engine — v1.6.2

| Команда | Эффект |
|---|---|
| `;mem debug on` | После каждого игрового ответа показать, что выполнили Input, Context и Output; вывести фрагмент реально добавленного текста (первые ~950 символов). |
| `;mem debug full` | После каждого игрового ответа показывать **весь добавленный Memory Engine текст** (справочная память и инструкция Recorder). Может занимать много места. |
| `;mem debug context` | Показать весь текст последнего дополнения Memory Engine через служебную команду. Не выполняет повторного запроса и не обновляет память. |
| `;mem debug last` | Последний отчёт: был ли контекст добавлен, сколько символов, удалялась ли ранняя история, был ли JSON-маркер и сколько предложений создано. |
| `;mem debug status` | Режим и наличие последнего отчёта. |
| `;mem debug off` | Отключить дополнительные сообщения; сохранённые игровые факты остаются. |

**Где появляется результат:** в `state.message` — отдельном сообщении интерфейса, а не в художественном тексте истории. Режим включён только у Memory Engine, не управляет диагностикой Universal RPG.

**Что значит «передано модели»:** `Context.js` возвращает AI Dungeon исходный контекст с **дополнением Memory Engine**. Отладка сохраняет именно этот добавленный фрагмент, но не знает итоговой сборки контекста платформой или изменений других подключённых скриптов. Для проверки окончательного контекста открой **View Context / Inspect Input** в AI Dungeon. Если ограничение `info.maxChars` помешало вставке, debug прямо покажет «НЕ добавлен».

**Обычный ход:** Output сообщает, обнаружен ли `[[AIDM_UPDATE]]`, разобран ли JSON, созданы ли предложения очереди. Debug не принимает предложения автоматически — используй `;mem review` и `;mem accept ID`.

> [!warning] Совместимость нескольких скриптов
> `state.message` — общее видимое сообщение. Если Universal RPG или другой скрипт пишет туда же позже, сообщение Memory Engine может оказаться перезаписанным. Тогда используй `;mem debug last` / `;mem debug context` и системный **Inspect Input**. В debug full объём текста больше, поэтому включай его только на время проверки.


## Ошибка `Identifier 'AM_HELP_PAGES' has already been declared`

Точная причина ошибки на строке **867:7** — `Library.js` версии **1.4** совместно с `Input.js` версии **1.4.1/1.4.2**. Первая таблица помощи объявлена внутри старой Library, вторая — в новом Input. Скрипт останавливается до выполнения команд, поэтому `ping` тоже не отвечает.

1. В редакторе Memory Engine **полностью замени содержимое всех четырёх вкладок** на JS из v1.4.4. Не вставляй новые файлы в конец старых.
2. Сохрани сам Adventure Script и проверь, что в приключении включён обновлённый экземпляр, а не старая копия.
3. Запусти `;mem ping`; проверь **v1.4.5**. Затем `;mem status` и `;mem list char`.
4. При сообщении «Несовместимые вкладки» проверь Library; при новой синтаксической ошибке пришли её полный текст и номер строки.

> [!note] Сохранность данных
> В исправлении нет пересоздания базы. Все персонажи, отношения, локации и летопись в `state.aidm` остаются в текущем приключении. Однако локальные проверки не заменяют тестирование внутри AI Dungeon.

## Когда можно и нельзя сбрасывать `state.aidm`

> [!warning] Сброс не является ремонтом скрипта
> Если `;mem ping` не отвечает, вместо квитанции идёт обычная генерация, Input Modifier выдаёт `Unexpected end of input` или повторную декларацию переменной — **не сбрасывай память**. Исправляй JS-вкладки, версию и сообщение ERROR. Сброс не решит эти ошибки, но удалит персонажей, отношения и летопись.

Начиная с **v1.4.6** доступны три подтверждаемые команды:

- `;mem reset data confirm` — удалить только базу, оставить Story Cards.
- `;mem reset cards confirm` — удалить только собственные Story Cards с меткой `[AIDMEM:1:...]`, сохранить базу, выключить их пересоздание.
- `;mem reset all confirm` — удалить собственные карточки и только затем очистить базу.

Без `confirm` данные не удаляются. `;mem reset data` показывает подробные счётчики базы, `;mem reset cards` — свои Story Cards по типам, `;mem reset all` — обе группы, `;mem reset` — общий предпросмотр. Эти команды не запускают синхронизацию карточек на ходе просмотра. При недоступности API удаления или частичном результате команда сообщит причину; повторный вызов продолжит работу с оставшимися собственными карточками (не более 30 за один вызов). **Сброс нельзя отменить через `;mem undo`.** Ни одна команда не очищает Memory Bank, сюжет или данные Universal RPG.

Полная инструкция: [[AI - AI Dungeon Memory Engine все команды#Полный сброс памяти и Story Cards]].

## Диагностика по порядку

1. **Команда:** `;mem status` выдаёт служебный ответ и счётчики? Если нет, проверь `Input.js`, `Output.js` и включение скрипта.
2. **Хранилище:** добавь `;mem char Тест | bio=Тестовый персонаж`, затем `;mem list char`. Если записи нет — проверь `Library.js` и состояние приключения.
3. **Контекст:** открой Context Viewer после обычного хода. Ищи `[AID MEMORY ...]` и инструкцию `AID Memory Recorder`. Их отсутствие при заполненном контексте не всегда ошибка: скрипт может отказаться от вставки, чтобы не обрезать критическую часть текста.
4. **Извлечение:** проверь `;mem pending`, затем `;mem status`. Счётчик «Автопакеты» отражает применённые изменения, а не количество предложений в очереди. Для новых предложений проверь `;mem review`. Если маркер модель не пишет, растёт счётчик пропусков.
5. **Карточки:** `;mem list char` показывает запись, а Story Card нет? Проверь `;mem cards on`, наличие поддерживаемого API и конфликт ключей с уже созданными ручными карточками.
6. **Сосуществование:** сравни RPG `:status` до/после метакоманды. Если растёт число RPG-ходов — см. [[AI - AI Dungeon Memory Engine совместимость с RPG]].

## Вместо ответа команды появляется обычная генерация (v1.4.5)

**Признак:** после ввода `;mem ping` или `;mem status` рассказчик продолжает сюжет, как будто команды не было. Точная причина предыдущего отказа v1.4.4 пока не подтверждена.

В v1.4.5 обработчик Input распознаёт больше вариантов формы Do/Say, а также добавляет **немедленный диагностический `state.message`** и сохраняет ответ в `state.aidm.pendingUI`. Теперь возможны три различимых случая:

| Наблюдение | Значение | Проверка |
|---|---|---|
| Есть нормальная квитанция `AID Memory v1.4.5` | Input и Output выполнились в данном ходе | Проверить `;mem list char` |
| Есть подсказка `[AID Memory: команда принята...]`, но сюжет продолжился | Input сработал; Output мог быть пропущен, переопределён или завершился ошибкой | Открыть `Scripts → ERROR` и Console Log, проверить порядок скриптов |
| Нет ни квитанции, ни подсказки | Ввод не дошёл до данного Input либо скрипт не выполняется | `Input → Script Test` с `text: ";mem ping"`, проверить активную копию скрипта и флажок Scripting |

> [!warning] Сообщения в `state.message` не заменяют Output Modifier: они служат резервной диагностикой. Если оба обработчика исправны, сюжетная генерация заменяется полным ответом команды.

## Исправление ошибок команд в режиме Do (v1.3.1)

AI Dungeon может автоматически дописать точку: `;mem list char` попадает в Input как `> You ;mem list char.`. В старой v1.3 категория `char.` считалась неверной, поэтому выдавалось «Раздел: char, place, faction, rel, arc.». Аналогично `;mem world.` выдавал ошибку неизвестной команды. В v1.3.1 оба случая исправлены: данные не терялись, ошибался только разбор команды.

Если ошибка повторяется после обновления, проверь, что в **действительно подключённом Adventure Script** заменён `Library.js` (иногда в сценарии и в отдельном скрипте остаются две разные копии). Проверь `;mem list char`, `;mem list place` и `;mem world` отдельными ходами.

Надпись `МИР: help.` в выводе `;mem map` означает, что в поле `world` уже записано слово «help.». Это содержимое базы, а не ошибка отображения. Для исправления задай настоящий сеттинг: `;mem world Современный город, реалистичный мир`. Записи персонажей и мест не затрагиваются.

## Ошибка `Unexpected end of input [<isolated-vm>:902:5]` в v1.4.3

**Симптом:** при проверке Input Modifier панель **Script Test** сообщает `Unexpected end of input`, а `logs` пуст. Присланный пользовательский JSON содержал примерные значения полей `text`, `history`, `storyCards`, `info`, `state`; это тестовые данные и они не являются причиной синтаксической ошибки.

**Подтверждено:** локальная проверка JavaScript исходников v1.4.3 проходила, но серверная компиляция отвергла код. Точная причина расхождения не установлена; повреждённая вставка, усечение редактором и особенности исполнения платформы — гипотезы, а не подтверждённые причины.

**Изменение в v1.4.4:** `Input.js` переведён на стандартную форму `const modifier = ...; modifier(text);` без внешней обёртки. Справочные таблицы `AM_HELP_PAGES` и `AM_HELP_ALIASES` теперь объявлены только в `Library.js`. Размер каждого из `Library.js` и `Input.js` меньше 64 КиБ. На локальных тестах оба файла компилируются совместно, включая вариант с внешней обёрткой, и обрабатывают стандартный JSON Script Test.

**Проверка после обновления:** замени все четыре вкладки и сохрани; во вкладке Input открой Script Test, в его JSON замени `text` на `";mem ping"` и нажми Submit. Если в выводе снова ошибка синтаксиса, пришли **новую строку/номер** и убедись, что Input действительно заканчивается `modifier(text);`. Не очищай `state.aidm` и не повторяй импорт до успешного запуска.

## Отказ всех команд после обновления v1.4

> [!warning] Ранее исправлено в v1.4.1, дополнительная защита от конфликта версий добавлена в v1.4.3
> После v1.4 пользователь сообщил, что перестали работать **все** команды. Исходный JavaScript v1.4 проходил локальные тесты; причина на сервере AI Dungeon осталась неизвестной. В v1.4.1 большой файл Library разделён между Library и Input, добавлен перехват исключений и диагностическая команда `;mem ping`. Это мера по устранению потенциальной проблемы загрузки/обработчика, **не подтверждение исправления конкретной серверной ошибки**.

**Проверяй последовательно:**

1. В редакторе отдельного Adventure Script замени **все четыре** файла `Library.js`, `Input.js`, `Context.js`, `Output.js` из **одного и того же** полного архива v1.5.0; нажми **Save**. Ранее было достаточно только Library; теперь недостаточно.
2. В уже существующем приключении открой **Game settings → Scripts**. Убедись, что включена нужная копия Memory Engine. Обновление текста другого сценария не меняет автоматически код подключённого независимого скрипта.
3. В Do введи **`;mem ping`**. Ответ `AID Memory v1.4.5: Library и Input работают...` подтверждает, что обработчик команд запустился. Затем проверь `;mem status` и `;mem list char`.
4. Если ничего не произошло, ищи значок **ERROR** в Scripts и открой краткое сообщение об ошибке. Приложи его к отчёту: оно позволяет отличить синтаксическую ошибку, ограничение выполнения и конфликт скриптов. По официальным сведениям, скрипт с ошибкой может быть пропущен в текущем ходе.
5. Если после v1.4.4 проблема осталась, для быстрого восстановления верни все четыре вкладки из **v1.3.1**, не очищая базу. В v1.3.1 **нет** нового пакетного синтаксиса v1.4, но есть старый `§поле=значение`.

**Важно:** вызовы в Input и Output могут не состояться из-за ошибок загрузки/синтаксиса; собственные обработчики ошибок эти случаи не поймают. Для такого отказа необходим значок ERROR/Console Log. Сведения об изолированности подключённых Adventure Scripts и пропуске скрипта при ошибке изложены в официальном руководстве AI Dungeon.

## Таблица неисправностей

| Проблема | Возможная причина | Действие |
|---|---|---|
| `;mem status` становится обычной репликой | Скрипт не включён, Input не работает или команда искажена вводом. | Проверь Scripts Enabled и вкладки Input/Output; введи команду отдельно в Do. |
| Появляется `amInit is not defined` | Library не загружена/не вставлена. | Перепроверь Library и сохранение всех вкладок. |
| Видно `[[AIDM_UPDATE]]` | Output не сработал или модель выдала нестандартный регистр/обрыв. | Проверь Output и ошибки; при повторе отключи `;mem auto off`. |
| «Автопакеты» = 0 | Модель не пишет валидный JSON, пишет `{}` или нет обновлений. | Проверь Context Viewer и `;mem recent`; протестируй другую модель или фиксируй вручную. |
| Импорт не нашёл отношения | Неизвестные типы импортируются как факты; их содержание **не разбирается** в направленные отношения. | Создай две направленные связи командами `;mem rel`. |
| Существующая Story Card не изменилась | Ручные карты защищены, совпали ключи или Card API недоступен. | `;mem show` для базы; вручную поправь чужую карточку или отключи авто-карты. |
| После `undo` карточка по-прежнему содержит ложный факт | Откат восстанавливает только `state.aidm`. | Исправь карточку отдельно, при необходимости `;mem cards off`. |
| Дата летописи неправильная | `state.aidm` не синхронизирован с часами RPG, модель могла установить дату. | `;mem date ...`; записи с прежними датами исправляй удалением/повторным вводом. |
| Не видна нужная локация в ответе модели | Лексический выбор и лимит контекста. | Упомяни название в сцене; сократи записи; проверь Context Viewer. |
| Отношение поменялось без сюжетного основания | Модель неверно интерпретировала сцену. | `;mem rel ...` для правки, `;mem undo` при подходящих условиях, либо `;mem auto off`. |
| `:mem` перехватывает RPG | Оба обработчика используют двоеточие. | Используй `;mem`. |
| Команда засчитана RPG-ходом | Неизолированный Input другого скрипта обработал её как обычный текст. | Установи необязательный патч совместимости, затем протестируй. |

## Важные ограничения

- **Нет независимого ИИ-анализатора:** структурированные обновления присылает сама модель-рассказчик.
- **Нет гарантированной проверки канона:** содержательные ошибки модели могут сохраниться в базу.
- **Нет полноценного UI Banshee:** карта, список отношений, летопись и календарь — только текстовые команды, плюс Story Cards.
- **Нет поиска по всем событиям:** `timeline` показывает последние подробные дни, а `pending` — последние события; факты можно просматривать через `;mem list fact` и `;mem show fact ID`, но произвольного полнотекстового поиска нет.
- **Нет резервного экспорта/импорта всей базы:** `;mem import` переносит Story Cards в структуры/факты, но не экспортирует и не восстанавливает всю базу `state.aidm`.
- **Нет автоматической синхронизации времени/навыков** с Universal RPG.
- **Нет гарантии полной синхронизации карточек:** не более **8** за один вызов Output; пользовательские карты не переписываются; обновление при ошибках может не произойти.
- **Нет произвольного отката:** `undo` откатывает лишь один последний авто- или `batch`-пакет, но не Story Cards.
- **Нет удаления отдельного поля через пустое значение** и нет команды глобального `clear`.
- **Нет полностью автоматического создания дневных и месячных сводок:** модель может прислать день; старые дни могут сворачиваться в текст месяца без отдельного интерфейса чтения.
- **Не подтверждён живой тест в AI Dungeon:** локальная эмуляция проверяет JS-логику, но не реальный порядок срабатывания нескольких Adventure Scripts и поведение выбранной модели.

## Недостаточно очевидные особенности команд

| Симптом | Причина в реализации | Действие |
|---|---|---|
| `;mem place ... | typo=...` отклоняется | Неизвестные ключи и пустые значения теперь проверяются в одиночных командах. | Исправь имя поля (`parent`, `description`, `kind`, `status`); запись не изменилась. |
| `kind`, `trust`, `tags` есть в контексте, но герой может их игнорировать | Поля передаются модели только при выборе связанной записи; их влияние текстовое, а не механическое. | Укажи имя локации или персонажа в текущей сцене и проверь Context Viewer. |
| `;mem delete plan ID` не удаётся | ID теперь выводится в `calendar` как `#ID` и при создании `plan`. | Найди строку в `;mem calendar`, затем введи `;mem delete plan ID`. |
| `;mem here` задан, а свойства места в контексте отсутствуют | Место не создано в `places` или движок не смог вставить весь контекст в лимит. | Создай запись через `;mem place`, проверь `;mem map` и Context Viewer. |
| `;mem calendar` показывает прошедший план | Сортировка содержит и исторические **разовые** планы, без фильтра «только будущее». | Удаляй неактуальные планы по ID; отдельного `list plan` нет. |
| `importance=3` не выглядит первым в летописи | `timeline` хронологический; значимость повышает приоритет события в контексте и выводится отдельным блоком важных событий. | Смотри `[3/3]` в `;mem day` и раздел «Ключевые события» в `;mem timeline`. |
| `;mem pending` не изменился, а дата/место изменились | Автоотчёт мог поменять только `date`, `time`, `place`, `world`, без увеличения `accepted`. | Проверь `;mem status`, `;mem here`, `;mem world`; вручную исправь неверное. |
| При удалении персонажа другие карточки сохранили упоминание о нём | Карточки других участников теперь ставятся в очередь обновления, но очередь зависит от `cards on` и наличия API. | После нескольких ходов проверь Story Cards; при `cards off` исправь вручную. |
| После `;mem cards off` старая Story Card по-прежнему активируется | `cards off` останавливает новые попытки синхронизации, **не удаляет старые карты**. | Отключи/исправь карточки в интерфейсе AI Dungeon. |

Полная матрица: [[AI - AI Dungeon Memory Engine поля и влияние]].

## Проверка старых связей после обновления

```text
;mem validate
;mem map
```

Новые записи проверяются, **но старые записи v1.1 с ошибочным `parent` не удаляются автоматически**. Исправь их вручную, начиная с верхних уровней иерархии. Удаление родителя с детьми блокируется.

## Режим восстановления контроля

Когда автоизвлечение загрязняет память ошибками:

```text
;mem auto off
;mem cards off
;mem pending
;mem recent
;mem list char
;mem list rel
;mem timeline
```

После ручной очистки/исправления включай режимы отдельно. Отключение синхронизации **не удаляет** автоматически созданные ранее Story Cards.

## Ошибки пакетного ввода

- **«Не найдено полей §»** — в блоке нет строк, начинающихся с `§`; используй `;mem batch template char`.
- **«добавь §:apply»** — пакет не был завершён; ни одна запись не сохранена.
- **«поле N»** — неверный тип/значение поля N; исправь поле и повтори блок целиком.
- **«достигнут лимит»** — новые объекты или навыки превышают вместимость. Раздели пакет/освободи место.
- **Обновилось не всё в Story Cards** — синхронизация выполняется до 8 карточек за ответ, оставшиеся обрабатываются при следующих ходах.

Полная инструкция: [[AI - AI Dungeon Memory Engine пакетное заполнение]].


> [!tip] Проверка миграции кастомных карточек
> После обновления до v1.3.1 повтори `;mem import`, затем `;mem list fact`. Неизвестные типы Story Cards сохраняются как факты. Оригинальные карточки не удаляются; это не конвертация произвольных карточек в NPC или числовые навыки.

## Пакетные команды v1.4

- Ответ «Ошибка пакета, команда N» — проверь строку N; она должна начинаться с `§;mem` и содержать допустимую команду изменения. Ошибочный пакет **не изменяет базу**.
- Ответ «нет `§:apply`» — заверши именно этой строкой. Если вставляешь команды без `§`, используй настоящий перенос строки и `;mem apply` последней строкой.
- Превышение 3950 символов или 55 **развёрнутых полей** — раздели пакет. Одна строка `char` с пятью полями расходует больше одной директивы.
- Команды `list`, `show`, `map`, `status`, `auto`, `cards`, `import` и `help` не включаются в пакет. Выполняй их отдельно.
- Если поле `parent` ссылается на ещё не созданное место, создай его в том же пакете. После сохранения используй `;mem validate`.
- Не смешивай `§;mem char ...` и устаревшие `§bio=...` в пределах одного блока. Старый формат поддерживается **только как отдельный целый пакет**.
- После `;mem undo` проверь собственные Story Cards: их обновление/удаление не откатывается вместе с базой.

Подробные рабочие примеры: [[AI - AI Dungeon Memory Engine пакетное заполнение]].


## Импорт и обмен данными — диагностика v1.5.0

| Симптом | Причина / действие |
|---|---|
| `;mem import` переносит Custom как факт, но он редко вспоминается | Проверь `;mem show fact ID`: должны быть `Тип Story Card` и `Ключи`. Ключи совпадают по тексту, изменение падежа автоматически не гарантируется. |
| После редактирования старой Custom-карточки факт остался прежним | Запусти `;mem import refresh`; исходные карточки не переписываются. |
| `;mem import plot auto` пишет «недоступно» | Поле не было предоставлено `state.memory` в этом скрипте. Скопируй компонент из Plot и вставь вручную: `;mem import plot essentials | ...`. |
| AI Instructions или Story Summary не импортировались автоматически | Для них в документированном Script API нет отдельных полей. Нужен ручной перенос текста. |
| `;mem import rpg card` не находит экспорт | Universal RPG должен создать обменную Custom Story Card с `[AID_RPG_EXPORT:1]`; Memory Engine сам её не создаёт. |
| В RPG поменялись HP/время/инвентарь, а память не обновилась | RPG и Memory Engine изолированы. Импорт — снимок, для обновления нужна новая экспортная карточка или новая вставка JSON. |

При ошибках импорта исходные Story Cards и Plot не удаляются. Не очищай `state.aidm` ради повторного импорта; сначала используй `;mem import refresh` и `;mem import plot status`.

## Диагностика очереди проверки (v1.6.0)

- Нет видимого уведомления — проверь `;mem review`: интерфейс может иначе показывать `state.message`.
- Есть художественный текст, но нет предложений — проверь `;mem auto on`, `;mem recent`, `;mem status` и наличие маркера `AIDM_UPDATE` в Inspect.
- `;mem accept ID` выдаёт «КОНФЛИКТ» — значение уже установлено вручную, импортировано либо сохранено в старой версии. Используй `;mem edit ID | ...` или явную `;mem accept ID replace`.
- Непроверенное наблюдение не видно в карточках — это ожидаемо: его ещё не приняли.
- Предложение исчезло после отказа — проверь `;mem review log`; дубликаты временно подавляются.
- После обновления v1.5.0 старые персонажи не исчезают: `state.aidm.version=1` сохранён; очередь и метки происхождения добавляются без сброса.

Подробнее: [[AI - AI Dungeon Memory Engine проверка автопамяти]].

## Импорт Universal RPG вместо результата показывает синтаксис

Если после `:aidm export` появлялось «Синтаксис: ;mem import ...» при вызове `;mem import rpg card`, убедись, что используется **Memory Engine v1.6.1 или новее**. В предыдущих версиях в режиме Do автоматически добавленная точка превращала `rpg card` в `rpg card.` — неизвестную подкоманду.

Проверяй последовательно:

```text
;mem ping
;mem import rpg card
;mem import rpg status
```

Если карточка не найдена, проверь, что оба скрипта подключены **к одному приключению** и RPG создал Custom Story Card с Entry, начинающимся ровно с `[AID_RPG_EXPORT:1]`. Ошибка синтаксиса и отсутствие карточки — разные неисправности. Сбрасывать `state.aidm` не нужно.

## Диагностика переноса между приключениями (v1.7.0)

Команда `;mem transfer status` показывает отсутствующие части. `;mem transfer apply` без `confirm` проверяет весь набор перед изменением базы. Прерывание переноса не повреждает подтверждённые данные. Подробные сценарии ошибок и ограничения: [[AI - AI Dungeon Memory Engine перенос между историями]].

## Технические команды другого скрипта и счётчик маркеров

Начиная с v1.7.0 команды вида `:setup`, `:aidm export`, `:aidm status` и другие начинающиеся с двоеточия действия, которые не являются `:mem`, игнорируются рекордером Memory Engine как **технические команды**. Для них не нужно ждать `[[AIDM_UPDATE]]`; они не увеличивают счётчик «без распознанного маркера». Значения счётчика, накопленные в старых версиях, остаются как историческая статистика и не свидетельствуют о потере RPG-снимка. Обычные сюжетные действия по-прежнему отслеживаются; если на них модель не выдаст служебный JSON, счётчик увеличится.
