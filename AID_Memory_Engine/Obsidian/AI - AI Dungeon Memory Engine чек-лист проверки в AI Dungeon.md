# Memory Engine — чек-лист проверки в AI Dungeon

Комплект проверки: **Memory Engine 1.8.0**, при совместных сценариях **Universal RPG 2.33**. Связанные документы: [[AI - AI Dungeon Memory Engine план исправлений]], [[AI - AI Dungeon Memory Engine аудит и план исправлений]], [[AI - AI Dungeon Universal RPG чек-лист проверки в AI Dungeon]], [[AI - AI Dungeon Memory Engine дерево команд]], [[AI - AI Dungeon Memory Engine все команды]].

## Что уже явно показано пользователем

- [x] **M-H01, до 1.8.0.** Показаны `;mem status`, `;mem char Алиса` и списки записей: команды выдают данные. Это не подтверждает все поля, текущую загрузку четырёх вкладок 1.8.0 или точность рассказчика.
- [x] **M-H02, 1.7.4 и последующие показанные сеансы.** Импорт снимка RPG для Алисы и перенос пяти старых RPG-заметок завершились сообщениями об успехе; записи видны в списке. Фактическая неизменность механики RPG отдельно не проверена.
- [x] **M-H03, до 1.8.0.** `;mem import` показал 15 импортированных карточек, в том числе 4 персонажей, 5 мест и 6 фактов. Повторный `;mem import refresh` показал 0 новых карточек и сохранение прежнего количества фактов. Реальное обновление изменённого источника этим не доказано.
- [x] **M-H04, до 1.8.0.** `;mem status` показал `Календарь: off`. Отсутствие конфликтующей даты в контексте рассказчика отдельно не подтверждено.
- [x] **M-H05, 1.7.6–1.7.9.** Показаны результат `cards audit`, читаемый многострочный предпросмотр и автоматическое включение строки «Любит рисовать» в дополнительные сведения. Подтверждены именно поиск и предпросмотр.

**Сообщённая проблема:** после `cards adopt 1 confirm` Алиса исчезла из списка Story Cards. Успешная передача, видимость после исправления в 1.8.0, автоматическая синхронизация и restore пока **не подтверждены**.

## Как заполнять результаты

`[ ]` означает отсутствие явного успешного подтверждения пользователем на указанной версии в настоящем AI Dungeon. `[x]` в историческом разделе означает только конкретное наблюдение из переписки; его область указана рядом. Локальные тесты, AID-Sandbox, текст справки и сообщение «команда выполнена» не подтверждают фактический игровой эффект.

Для каждого выполненного пункта запиши версию всех четырёх вкладок, дату, идентификатор пункта, исходное состояние, команду/действие, ожидаемый и фактический результат. Для совместной проверки запиши версию второго скрипта и порядок подключения. Флажок ставится только после сверки фактического состояния и повторного открытия приключения, если пункт затрагивает сохранение. При ошибке оставь `[ ]` и приложи текст ошибки/фактический результат. Если пункт содержит несколько вариантов, он закрывается после проверки каждого; частичные результаты записывай отдельно.

Шаблон записи: `ID: …; версия: …; дата: …; исходное состояние: …; действие: …; ожидается: …; получено: …; повторное открытие: …; итог: подтверждено/ошибка/не проверено`.

Проверки reset, uninstall, удаления, замены переносимой базы и миграций выполняй в копии приключения с сохранённым исходником. Указываемые ниже `ID`, `INDEX`, `Имя`, `TYPE` и значения — заменяемые аргументы; буквально их вводить не нужно. Индекс Story Card и ID факта не взаимозаменяемы. В блоках с `/` проверь перечисленные альтернативы по отдельности, а не вводи весь перечень, если синтаксис команды этого не разрешает.

## Известные ограничения проверки

Известный дефект не считается успешно проверенной функцией. Связанные с ним пункты оставлены открытыми до исправления и повторной проверки. Причины и критерии исправлений: [[AI - AI Dungeon Memory Engine аудит и план исправлений]]. Сценарии неизвестной версии сохранения, повреждения state, отказа API и точного переполнения контекста требуют подготовленной тестовой фикстуры или диагностического стенда: игровой команды для их создания нет. Не подменяй такой сценарий обычным ходом в игре.

## Полный проход команд и их вариантов

Ниже перечислены все командные строки и поля из текущего дерева команд. Все флажки открыты для нового полного прогона: исторические подтверждения приведены отдельно и не означают проверки всех режимов команды. Описание после команды задаёт ожидаемое назначение. Для изменения проверь точное изменение указанного поля, сохранение остальных полей и сохранение результата после повторного открытия; для просмотра проверь полноту вывода и отсутствие игровых изменений; для переключателя проверь оба положения и реальное поведение модуля. Для ошибочного ввода ожидаются объяснение и отсутствие частичной записи. Нужные аргументы и ограничения сверяй с полным справочником.

### Справка и диагностика

- [ ] **M-C001** `;mem` / `;mem help` — открыть встроенную справку.
- [ ] **M-C002** `;mem help all` / `;mem help Тема` — общий указатель или справка по теме; доступны и русские названия тем.
- [ ] **M-C003** `;mem ping` — проверить загрузку Library и Input.
- [ ] **M-C004** `;mem status` — показать режимы, счётчики и состояние памяти.
- [ ] **M-C005** `;mem validate` — проверить вложенность мест и ссылки на родителей.
- [ ] **M-C006** `;mem debug` / `;mem debug status` — показать состояние отладки.
  - [ ] **M-C007** `;mem debug on` — включить технические сообщения после ходов.
  - [ ] **M-C008** `;mem debug full` — включить полный вывод добавления в контекст.
  - [ ] **M-C009** `;mem debug off` — выключить отладочные сообщения.
  - [ ] **M-C010** `;mem debug last` — показать отчёт последнего хода.
  - [ ] **M-C011** `;mem debug context` — показать последний текст, добавленный Memory Engine в контекст.

- [ ] **M-C014** `;mem cards show TYPE Имя` — показать активную карточку; для fact укажи ID.

- [ ] **M-C016** `;mem cards link INDEX | TYPE | Имя` / `... | confirm` — связать источник с существующей записью.
- [ ] **M-C017** `;mem cards unlink INDEX` / `... confirm` — снять явную связь; для управляемой карточки сначала restore.
- [ ] **M-C018** `;mem cards audit` — найти пользовательские карточки с теми же сущностями, что в памяти.

- [ ] **M-C026** `;mem here` / `;mem here Место` — показать или указать текущее место.
- [ ] **M-C027** `;mem world` / `;mem world Описание` — показать или заменить описание мира.

## Сквозные сценарии и отрицательные проверки

- [ ] **M-S01 — установка и сохранение.** Установить четыре вкладки 1.8.0; `;mem ping` и `;mem status` показывают актуальный комплект. В копии проверить отказ смешанных версий без потери базы; после возврата полного комплекта данные доступны. На фикстуре неизвестной версии state Memory выдаёт отказ и сохраняет исходную запись.
- [ ] **M-S02 — технические команды.** В режимах Do и Say проверить служебную команду: ответ отделён переносами строк, сюжет не развивается, RPG не бросает кубики, не расходует деньги, время и потребности. Проверить `;mem`, совместимые `!mem`/`:mem` и обёртку интерфейса по отдельности.
- [ ] **M-S03 — персонаж и частичное изменение.** Создать тестового персонажа со всеми полями; изменить одно поле. Остальные поля, навыки и исходные RPG-показатели остаются прежними. Пустое или неизвестное поле отклоняется без частичной записи.
- [ ] **M-S04 — места и фракции.** Создать родителя и дочернее место, затем фракцию. `map` и `show` согласованы; отсутствующий родитель, самоссылка и цикл отвергаются, удаление используемого родителя защищено.
- [ ] **M-S05 — отношения и арки.** Создать А → Б и Б → А с разными значениями; изменение одного направления не меняет второе. Проверить trust на границах и вне диапазона. Изменить статус/результат арки и сверить timeline.
- [ ] **M-S06 — факты.** Добавить, изменить текст, изменить тему с текстом; ID сохраняется, второй факт не появляется. Точный повтор, слишком длинный текст и недопустимый ID не изменяют базу.
- [ ] **M-S07 — длинные факты.** Два факта с одинаковыми первыми 110 символами, но разными концами должны оставаться различными. Сейчас это известный дефект дедупликации; флажок закрывается после исправления.
- [ ] **M-S08 — очередь рассказчика.** Получить предложение из обычной сцены; до `accept` оно не меняет защищённое поле и активную карточку. Проверить просмотр источника, исправление предложения, accept, reject, журнал и защиту от повторного применения.
- [ ] **M-S09 — защищённые поля.** Предложение, противоречащее ручной биографии, не заменяет её без `accept ID replace`; обычное подтверждение объясняет конфликт. Проверить длинную биографию, в которой меняется только конец.
- [ ] **M-S10 — повреждённый отчёт.** На стенде проверить невалидный JSON, неизвестное поле, неверный тип, некорректного родителя и несколько служебных маркеров. История остаётся читаемой, частичная запись не повреждает канон, служебный текст не попадает в видимый сюжет.
- [ ] **M-S11 — импорт источников.** Изменить название, текст и ключи импортированной Custom-карточки, выполнить refresh. ID факта сохраняется, новая информация появляется. Проверить стандартный Character с ручной правкой: импорт не затирает защищённое поле.
- [ ] **M-S12 — Plot.** Проверить preview и auto-импорт доступных Plot Essentials/Author’s Note; вручную импортировать summary/instructions. Оригинальные Plot-поля не изменяются; архивированные инструкции не становятся новыми управляющими инструкциями модели.
- [ ] **M-S13 — передача Character.** Для копии Алисы сохранить исходник и Notes; выполнить audit → adopt с актуальным индексом → confirm. В списке остаётся одна связанная карточка; исходные тип, название, ключи и Notes сохраняются. `cards show char Алиса` находит активную запись; после повторного открытия карточка видна.
- [ ] **M-S14 — передача Location/Faction.** Повторить передачу по одному разу для места и фракции. Обновить соответствующее поле памяти: меняется та же карточка, соседние карточки и их ключи не затронуты.
- [ ] **M-S15 — исчезнувшая карточка.** В тестовой копии выполнить `cards show`, `cards repair`, проверить интерфейс. Для действительно удалённой управляемой карточки выполнить restore и confirm: создаётся один исходник, резервная копия не теряется до успешной записи.
- [ ] **M-S16 — Custom.** По отдельности передать «Записка», «Летопись», «Отношения» и обычный Custom. Сверить все строки и триггеры, название, точный тип, Notes. Тип не превращается самопроизвольно в событие или направленное отношение.
- [ ] **M-S17 — изменение Custom.** После adopt выполнить `edit fact ID | Текст`, затем вариант с новой темой; проверить новую строку через буквальное `\n`. После Output и повторного открытия изменена одна и та же карточка. Переполнение полного Entry отменяет правку без потери исходного текста.
- [ ] **M-S18 — связь.** Ручную карточку с другим названием связать с существующей записью через link и confirm; импорт не создаёт ещё одну сущность. Обычная синхронизация до adopt не создаёт вторую карточку. Проверить снятие явной связи через unlink и confirm.
- [ ] **M-S19 — выбор единственной карточки.** Если уже есть собственная копия и ручной источник, связать источник, просмотреть remove-own, подтвердить удаление только собственной копии, повторить audit с новыми индексами и adopt. При двух ручных кандидатах передача останавливается.
- [ ] **M-S20 — изменения между подтверждениями.** После предпросмотра изменить Entry, Notes, название либо запись памяти. Старый confirm отвергается. На стенде проверить отказ API и исключение после записи: исходная копия остаётся доступной.
- [ ] **M-S21 — дополнительные строки.** Проверить show/замену/очистку extras; точный текст, переносы и резервный исходник сохраняются. Профессия и возраст не обновляются автоматически из RPG без предусмотренного источника: устаревшие строки должны быть явно исправлены.
- [ ] **M-S22 — защита сохранённых карточек.** Прямая и пакетная попытки удалить связанный Custom-факт отвергаются. Заполнить память до лимита на стенде: защищённый факт не вытесняется. После restore факт снова обрабатывается по правилам ручного источника.
- [ ] **M-S23 — cards/auto.** Проверить независимо on/off каждого режима. `cards off` останавливает запись карточек, `auto off` — разбор предложений, но ручные команды памяти работают. После включения очереди изменения не теряются и не создают дубликаты.
- [ ] **M-S24 — календарь.** Проверить дату, время, високосный год, недопустимую дату, события без даты, day/summary/timeline, обычный и ежегодный plan. При date off данные не удаляются и собственная дата не передаётся рассказчику; включение возвращает сохранённые данные.
- [ ] **M-S25 — RPG-снимок.** Повторить export/import card и paste. Сверить героя, навыки, предметы и старые заметки; повторный импорт не размножает их. После нового экспорта явно проверить политику устаревающего места/профессии, а не считать их обновлёнными по сообщению об импорте.
- [ ] **M-S26 — условная дата RPG.** Проверить допустимую календарную дату и день, допустимый только в условном календаре RPG. Ручной import rpg calendar не должен подменять недопустимой датой календарь Memory; date off остаётся выключенным.
- [ ] **M-S27 — пакет.** Проверить обычный и legacy-форматы, все шаблоны, обязательный apply, превышение лимита и ошибку в последней строке. Ошибочный пакет не меняет предыдущие поля и не удаляет карточки; успешный пакет синхронизируется после Output.
- [ ] **M-S28 — undo.** Сверить базу и уже обновлённую карточку после отката принятого предложения или пакета. Сейчас автоматический откат карточек не реализован; полная согласованность остаётся открытым пунктом плана.
- [ ] **M-S29 — перенос приключения.** Проверить all/world, части в разном порядке, повтор части, пропущенную/повреждённую часть, checksum, preview и применение в пустую/непустую базу. Чужие ID не становятся местными связями. Дополнительные строки сейчас требуют отдельного контроля: их потеря в portable-пакете — известный дефект.
- [ ] **M-S30 — reset.** Для data/cards/all проверить предпросмотр и отказ без confirm, защиту при резервных копиях, сохранение чужих карточек и отказ API. На миграционной фикстуре отдельно отличить нормализацию старого config от очистки пользовательских данных.

Проверить повторный Output/Retry и повторное открытие без повторного применения одного предложения.
- [ ] **M-S32 — совместный запуск.** Проверить оба порядка подключения Memory/RPG, команды каждого скрипта и обычный ход. Не возникают второй бросок, двойной расход, конфликтующие даты или технический текст в сюжете. Изменения механики остаются в RPG, описательные факты — в Memory.
