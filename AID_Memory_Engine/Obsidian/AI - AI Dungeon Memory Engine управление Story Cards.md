# Управление пользовательскими Story Cards

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine все команды]]

## Почему возникает конфликт

Memory Engine хранит актуальные записи в `state.aidm` и при `cards on` создаёт собственные Story Cards для персонажей, мест и фракций. Ручная Story Card существует отдельно. Скрипт не перезаписывает её без команды игрока, поэтому старая карточка может противоречить памяти и попадать в контекст рассказчика.

Начиная с v1.7.6 совпадение **любого отдельного ключа** ручной карточки с именем сущности не даёт создать вторую карточку с тем же ключом. Уже существующие дубликаты можно убрать отдельно. Проверка ключей не устанавливает смысловое равенство разных названий.

## Проверка и перенос

1. Введи `;mem import`, если ещё не переносил стандартные Story Cards в память. Проверь `;mem list char/place/faction`.
2. Введи `;mem cards audit`. Он показывает ручные карточки типов Character, Location и Faction, для которых найдена одна соответствующая сущность памяти. `#INDEX` — **индекс Story Card, начиная с нуля**, а не ID факта. Например, строке `#1 char Алиса` соответствует команда `;mem cards adopt 1`: слово `INDEX` вводить не нужно.
3. Для нужной карточки введи `;mem cards adopt INDEX`, подставив число после `#`. Для Алисы из примера выше: `;mem cards adopt 1`. Скрипт покажет старый и новый текст с переносами строк, как они будут выглядеть в Story Card. Поля памяти выводятся отдельными строками, но переносы внутри одного поля `bio` сохранять нельзя: при записи в память они превращаются в пробелы. **Сверь новый текст**: строки исходной Story Card, которых нет в полях памяти, автоматически попадут в раздел «Дополнительные сведения из исходной карточки». Полный исходный `Entry` останется в резервной копии. Сравнение строк текстовое, поэтому возможны частичные повторы; дополнительные сведения могут устареть и тогда их нужно исправить.
4. Если предпросмотр верный, введи `;mem cards adopt INDEX confirm`. После подтверждения карточка получает метку `[AIDMEM:1:...]` и начинает обновляться из памяти при `;mem cards on`. Прежние непустые ключи-триггеры сохраняются. Если у исходной карточки ключи пустые, скрипт добавит имя сущности как ключ; исходный пустой набор останется в резервной копии. Для Алисы из примера: `;mem cards adopt 1 confirm`.
5. Повтори для остальных нужных карточек. Начни с одной и проверь в интерфейсе Story Cards, как она выглядит после следующего хода.

Если `adopt` сообщает, что уже существует отдельная собственная карточка Memory Engine, проверь `;mem cards audit`. Команда `;mem cards remove-own TYPE ИМЯ` покажет предпросмотр удаления **только** собственной дублирующей карточки. `... confirm` удалит её, оставив ручную. После этого снова выполни `audit` и `adopt`. `TYPE` здесь и в командах ниже — `char`, `place` или `faction`.

## Дополнительные сведения из ручной карточки

После передачи `;mem cards extra char Алиса` показывает автоматически сохранённые строки, которых не было в полях памяти. `;mem cards extra char Алиса | Новый текст` заменяет этот блок; `;mem cards extra char Алиса | -` очищает его. Для нескольких строк в одной команде используй буквальное `\n` между ними. Тип может быть `char`, `place` или `faction`.

При предпросмотре и правке скрипт проверяет лимит Entry в 1000 символов. Если полный текст не помещается, ручная карточка остаётся без изменений. При последующем изменении полей памяти проверь дополнительные сведения: они не умеют самостоятельно определять, какие старые факты устарели.

## Резервная копия и восстановление

- `;mem cards backups` — список переданных карточек.
- `;mem cards backup char Алиса` — полный исходный тип, ключи и `Entry` карточки Алисы. Аналогично для `place` и `faction`.
- `;mem cards restore char Алиса` — предпросмотр возврата ручной карточки.
- `;mem cards restore char Алиса confirm` — восстановить прежний тип, ключи и `Entry`; база Memory Engine останется. Если управляемая карточка была удалена через интерфейс, исходная будет создана заново с новым ID.

Резервные копии находятся **в `state.aidm` этого приключения**. Пока они есть, команды `;mem reset data/cards/all confirm` и удаление соответствующей сущности памяти остановятся: иначе исходные карточки можно было бы потерять. Для сброса сначала восстанови переданные карточки. Копия сохраняется, если API Story Cards отклонил восстановление.

После `restore` ручная карточка снова может устаревать. `;mem cards off` останавливает обновления собственных карточек, но не отключает существующие ручные карточки. При изменении данных Memory Engine обновляет управляемые карточки постепенно; это отдельный шаг и не даёт обещания синхронного появления карточки в контексте текущего хода.

## Границы функции

- Перенос доступен только для стандартной Story Card с **однозначным совпадением** имени или отдельного ключа с существующим персонажем, местом либо фракцией. Custom/Item/Lore, отношения в текстовых карточках, обменная карточка RPG и Plot этим способом не переходят.
- За один раз можно хранить резервные копии не более 30 переданных карточек. Если исходный `Entry` длиннее 3900 символов, перенос отклоняется, чтобы полную копию можно было проверить через команду.
- Скрипт не решает противоречия внутри самого текста памяти. Например, если старое местонахождение уже записано в `bio`, его надо исправить в памяти до подтверждения `adopt`. Предпросмотр показывает именно будущий активный текст.
- Передача и восстановление используют API Story Cards. AID-Sandbox лишь приближает поведение AI Dungeon; после установки проверь одну карточку в реальном приключении.
