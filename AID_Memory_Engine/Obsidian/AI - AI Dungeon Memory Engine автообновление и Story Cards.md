# AI Dungeon — Memory Engine: автообновление и Story Cards

## Отладка автоматических записей (v1.6.2)

Включи `;mem debug on`, затем соверши обычное действие и проверь техническое сообщение: `Input` принят, `Context` добавлен (с количеством символов), `Output` получил/не получил `[[AIDM_UPDATE]]`. Если появились предложения, их ID будут доступны через `;mem review`.

Для полного текста добавленного контекста используй `;mem debug context`. Для постоянного полного вывода — `;mem debug full`; для отключения — `;mem debug off`. Дополнение Memory Engine не равно всему окончательному контексту AI Dungeon. ## Как устроено автоматическое извлечение

> [!important] Новая модель подтверждения (v1.6.0)
> Модель **не записывает изменения непосредственно в канон**. Сначала появляется предложение; после решения игрока скрипт обновляет базу. Полный порядок и команды: [[AI - AI Dungeon Memory Engine проверка автопамяти]].


1. `Input` сохраняет последнее действие (кроме распознанных команд `;mem`).
2. `Context` выбирает подходящие записи из памяти и добавляет инструкцию рассказчику завершить ответ машинным отчётом.
3. Рассказчик должен написать обычный художественный текст, а в конце — строку `[[AIDM_UPDATE]]{...}[[/AIDM_UPDATE]]`.
4. `Output` удаляет эту строку из видимого текста, проверяет формат JSON и помещает изменения **в очередь предложений на подтверждение**, не меняя сразу базу или Story Cards.
5. При наличии новых предложений `state.message` показывает уведомление с ID и командами подтверждения, правки и отказа. При отсутствии маркера растёт счётчик пропусков, а короткий фрагмент сцены сохраняется как **непроверенный**.

Упрощённый **пример ожидаемого формата** (это не команда игрока):

```text
[[AIDM_UPDATE]]{"characters":[{"name":"Дана","traits":"Требовательная"}],"relations":[{"from":"Дана","to":"Алиса","view":"Заинтересована","reason":"Портфолио впечатлило"}],"events":[{"text":"Дана предложила Алисе пробную работу","importance":2}]}[[/AIDM_UPDATE]]
```

В v1.6.0 даже `date`, `time`, `place` и `world` из ответа модели **не применяются сразу**. Подтверждение игрока необходимо для любого предложенного изменения. Если модель повторяет уже записанное значение, новое предложение не создаётся. Техническая проверка не доказывает сюжетную достоверность.

Модель может присылать поля `date`, `time`, `place`, `world`, `characters`, `places`, `factions`, `relations`, `facts`, `events`, `daySummary`, `daySummaries`, `arcs`, `plans`, `observations`. Последнее поле предназначено для слухов и предположений. Используются поля, известные обработчику; неизвестные игнорируются. Размер пакета ограничен 4800 символами, внутри есть дополнительные лимиты записей за один ход.

> [!important] Это инструкция модели, а не независимый анализатор
> Нельзя рассчитывать, что рассказчик всегда выдаст маркер, поймёт все факты верно или аккуратно отделит выдумку от канона. Код проверяет форму данных и некоторые дубликаты, **но не сопоставляет каждое утверждение с исходным художественным текстом**.

## Режимы

```text
;mem auto on
;mem auto off
;mem cards on
;mem cards off
;mem status
;mem pending
;mem recent
```

- `auto off` отключает разбор JSON-обновлений, но не ручное редактирование базы и не создание сырых фрагментов.
- `cards off` отключает попытки синхронизировать Story Cards, но оставляет внутреннюю базу и контекст.
- `pending` теперь **показывает очередь ожидающих предложений и наблюдений**; полные сведения доступны через `;mem review ID`.
- `recent` — короткие текстовые фрагменты, их нельзя считать проверенными записями.

## Story Cards, созданные скриптом

Скрипт создаёт карточки только для **персонажей, локаций и фракций**, используя стандартные типы Character/Location/Faction. В начало `Entry` добавляется служебная метка:

```text
[AIDMEM:1:char:дана]
```

По этой метке можно отличить автоматически созданную карточку. За один вызов Output скрипт пытается обработать **не более 8** изменённых карточек (`maxAutoCardsPerTurn: 8`); очередь ограничена 80 пометками. Если карточка конфликтует с ручной, скрипт её пропускает. Если операция Story Card завершилась исключением API, задача возвращается в очередь и может быть повторена на следующем Output-хуке; `cardErrors` увеличивается. Одна и та же ошибочная задача не повторяется восемь раз в одном вызове. Он **не перезаписывает** пользовательские Story Cards с тем же ключом. При конфликте база всё равно сохраняет информацию, но карточка может остаться старой; `;mem status` не сообщает все конфликты как ошибки.

> [!warning] Две версии одной истины
> Если ручная карточка существует отдельно от базы или импортирована, изменения в структурированной памяти **не обязаны обновлять** эту ручную карточку. Это защита пользовательских данных, но она может приводить к расхождениям между контекстом и Story Cards.

## Удаление собственных карточек без потери базы

Предварительно вызови `;mem reset cards` без `confirm`: увидишь, сколько карточек персонажей, локаций и фракций будет удалено. Предпросмотр ничего не удаляет и не запускает фоновую синхронизацию карточек на этом ходу. Команда `;mem reset cards confirm` удаляет **только карточки с маркером** `[AIDMEM:1:char/place/faction:...]` в начале `Entry`. Это не то же самое, что `;mem cards off`: обычное `off` выключает создание новых карточек, но **не удаляет** старые. При сбросе `cards` режим тоже переключается в `off`, а очередь `cardDirty` очищается, чтобы удалённые карточки не возникли сразу повторно.

Если карточек более 30, повторяй команду: вывод покажет остаток. Пользовательские Story Cards и импортированные карточки других типов не удаляются. Команда `;mem reset data confirm` удалит записи базы, **но оставит уже созданные карточки**. `;mem reset all confirm` сначала удалит свои карточки, а затем очистит базу. Восстановление через `;mem undo` для этих операций не предусмотрено. Перед сбросом создай резервную копию приключения.

## Импорт старых Story Cards

```text
;mem import
```

Импорт обрабатывает категории **Character, Location, Faction** и переносит первые 650 символов поля `Entry` в `bio` персонажей или `description` локаций и фракций. Категории **Custom, Class, Race, Item, Lore и любые другие** не выбрасываются: они становятся именованными **фактами** со своим ID, заголовком и сохранённым исходным типом в `source`. Для таких импортированных карточек текст Entry сохраняется до **1100 символов**; это специальный путь импорта (обычная команда `;mem fact` сохраняет до 380 символов). В контекст попадает только сокращённая выдержка, если тема факта релевантна. Имя берётся из доступного API-поля карточки или из первого ключа-триггера, если имя отсутствует.

Это **не интеллектуальный разбор структуры**: например, карточка `Class` не создаёт игровые навыки, а карточка отношений не становится направленной связью между NPC. Оригинальные Story Cards остаются на месте.

После импорта проверь `;mem list char`, `;mem list place`, `;mem list faction`, `;mem list fact`; подробное содержание общего факта показывает `;mem show fact ID`. При повторном `;mem import` уже обработанные карточки пропускаются. Если раньше импортированы только стандартные карточки, повторная команда в v1.3.1 переносит оставшиеся нестандартные.

## Исправление записей и отмена

```text
;mem show rel Дана -> Алиса
;mem rel Дана -> Алиса | view=Осторожный профессиональный интерес
;mem delete rel Дана -> Алиса
;mem undo
```

`;mem undo` отменяет **только один последний непустой автоматический пакет или ручной `;mem batch`**, если его снимок не был сброшен последующим изменением. Ранее созданные Story Cards **не откатываются**. Это не редактор истории с произвольным переходом по версиям и не восстановление удалённых вручную записей.

**Рабочая политика для длинной игры:** включённое `auto` для чернового извлечения, регулярная проверка важных отношений/дат, ручная корректировка только ошибочных фактов. Если модель часто нарушает формат или портит канон — `;mem auto off` и ручная фиксация значимых событий.

## Пакетные правки и Story Cards

`;mem batch` сразу атомарно меняет внутреннюю базу. Автоматическое создание/обновление своих Story Cards выполняется отдельным шагом (до 8 за ответ) и не является частью транзакции. После `;mem undo` ранее синхронизированные карточки вручную проверь. [[AI - AI Dungeon Memory Engine пакетное заполнение]].

## Как повысить достоверность автоматических заметок

**Фактический механизм v1.5.0:** на каждом обычном ходе Input запоминает запрос, Context выбирает известные сущности и просит модель дописать один блок `[[AIDM_UPDATE]]{JSON}[[/AIDM_UPDATE]]`. Output удаляет блок из ответа, проверяет JSON и добавляет данные в `state.aidm`. Изменённые Character/Location/Faction помещаются в очередь создания/обновления собственных Story Cards (до восьми попыток за Output). При отсутствии блока сохраняется только короткий **непроверенный** фрагмент в `recent`.

**Ограничения текущей автоматизации:**

- JSON считается источником предложения, а не подтверждением сюжета. Скрипт не вызывает отдельную LLM и не сверяет семантику каждой новой записи с прозой.
- Старые заполненные `bio`, `traits`, `occupation`, `view` и другие поля модель может переписать. Числовой `trust` не вычисляется скриптом, но модель может ошибочно предложить число.
- Совпадающие факты и события частично фильтруются. Это не идеальная дедупликация перефразированных записей.
- Выборка фактов лексическая: совпадает текст темы или один из импортированных `keys`. Морфологический поиск (например, разные падежи) не гарантирован.

> [!tip] Предлагаемая архитектура следующего этапа (пока НЕ реализована)
> 1. Сохранять для каждого факта `source` (игрок, Story Card, Plot, RPG-экспорт или модель), время записи и доказательный фрагмент сцены.
> 2. Ручные и импортированные поля сделать защищёнными от прямого автоматического перезаписывания.
> 3. Конфликтные автоизменения помещать в очередь предложений с командами подтверждения/отклонения, а не сразу заменять канон.
> 4. Разделять подтверждённое событие, слух, план и предположение; автоматически не превращать план в свершившийся факт.
> 5. Отдельно проверять дневные сводки и удалять дубликаты при пересказах.
>
> Причина, по которой это не включено молча в v1.5.0: изменение политики автоматического перезаписывания затронет старые миры. Сначала нужна отдельная миграция и тесты совместимости.

## Расширенный импорт в v1.5.0

- `;mem import` — Story Cards и доступные поля `state.memory`.
- `;mem import refresh` — обновление ранее импортированных нестандартных карточек.
- `;mem import plot` — справка; `;mem import plot auto` — доступные Plot Essentials/Author's Note; `;mem import plot summary | ...` — ручная вставка Story Summary.
- `;mem import rpg` — схема обмена; `;mem import rpg card` или `;mem import rpg paste | {JSON}` — импорт снимка RPG, если он явно экспортирован.

Исходные Story Cards и Plot не редактируются. AI Instructions и Author's Note из архива **не превращаются в новые инструкции** для рассказчика. Подробнее: [[AI - AI Dungeon Memory Engine совместимость с RPG]] и [[AI - AI Dungeon Memory Engine все команды]].

## Отсутствующий маркер после команд RPG (v1.7.0)

Команды Universal RPG (`:setup`, `:aidm export` и другие действия с префиксом `:`) не являются игровыми событиями, поэтому Memory Engine не должен пытаться извлекать из них факты. С v1.7.0 эти ходы пропускаются рекордером без увеличения `misses`. Счётчик прошлых версий не обнуляется. Подробности: [[AI - AI Dungeon Memory Engine диагностика и ограничения]].
