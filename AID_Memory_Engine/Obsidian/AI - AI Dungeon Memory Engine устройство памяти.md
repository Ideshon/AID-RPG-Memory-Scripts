# AI Dungeon — Memory Engine: устройство памяти

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine автообновление и Story Cards]] · [[AI - AI Dungeon Memory Engine диагностика и ограничения]]

## Диагностический снимок `debugTrace`

При включённом `;mem debug on` скрипт сохраняет в `state.aidm.debugTrace` только **последний игровой ход**: факт получения Input, добавленный Memory Engine текст Context, длину, причину отказа при лимите и результат разбора Output. Этот снимок используется командами `;mem debug last` и `;mem debug context`. Он не является полной копией модельного контекста или журналом всех действий. `;mem debug off` отключает накопление нового снимка и очищает текущий отчёт.

**RPG-заметки** из `rpgSnapshot.notes` остаются справочной частью импорта, а не новой сюжетной памятью; они не дублируются в `amContext()`. Источник игровых механик — Universal RPG.


## Что является памятью

> [!note] Приоритет текущей локации
> При выборке до четырёх мест первые позиции отдаются текущему `;mem here` и до двух его родителей (если записи есть в `places`). Они помещаются в начале справочного контекста, чтобы сохранять непрерывность сцены. Другие сущности выбираются по совпадению названий. Важные события отбираются из последних 90 по значимости, дате, свежести и пересечению слов с запросом.


Основное хранилище — **`state.aidm` внутри отдельного Adventure Script**. Это не `state.memory`, не встроенный Memory Bank и не содержимое пользовательских Story Cards. Игровая база сохраняется между обычными ходами текущего приключения, если платформа сохраняет состояние скрипта.

| Коллекция/поле | Назначение | Как смотреть |
|---|---|---|
| `world` | Общее описание мира. | `;mem world`, `;mem map` |
| `date`, `time`, `place` | Текущие игровые дата, время, место. | `;mem status`, `;mem here` |
| `characters` | NPC и персонажи: био, характер, вид, роль, описательные навыки, местоположение. | `;mem list char`, `;mem show char Имя` |
| `relations` | Направленные связи A→B, мнение, причина, метки, условное доверие. | `;mem list rel`, `;mem show rel A -> B` |
| `places` | Локации и их родительские места. | `;mem list place`, `;mem map` |
| `factions` | Организации, территория, цели, статус. | `;mem list faction`, `;mem map` |
| `facts` | Короткие устойчивые факты. | При записи ID; выборочно — в контексте по совпадению темы. |
| `events`, `days`, `months` | Хронологические события, сводки дней, сжатые месяцы. | `;mem day`, `;mem timeline` |
| `arcs` | Сюжетные линии и крупные события с итогами. | `;mem list arc`, `;mem show arc Название` |
| `plans` | Запланированные календарные события, включая ежегодные. | `;mem calendar` |
| `recent` | Последние короткие фрагменты текста без подтверждения. | `;mem recent` |

## Очистка собственного состояния `state.aidm`

`state.aidm` — независимый объект постоянного состояния **этого Memory Engine** в конкретном приключении. Он включает всю структурированную базу, дату, очереди карточек, настройки и счётчики. Значение `version` **остаётся 1** в релизе v1.4.6; номер кода скрипта от него отличается.

До очистки используй `;mem reset data`, `;mem reset cards` или `;mem reset all` **без `confirm`**. Эти команды покажут количество записей по категориям, которые будут затронуты; `;mem reset` покажет обе группы вместе. Затем, при необходимости, выполняй `;mem reset data confirm`, `;mem reset cards confirm` или `;mem reset all confirm`. Команды **не требуют редактировать JavaScript**. Первый вариант обнуляет `state.aidm`, но не удаляет Story Cards. Второй удаляет собственные Story Cards, сохраняя память и отключая их автосоздание. Третий очищает оба источника данных Memory Engine, не затрагивая пользовательские карточки, историю или Memory Bank. Каждая команда требует буквального подтверждения `confirm`.

Если удаление собственных Story Cards остановилось посередине из-за лимита 30 карточек на вызов или ошибки API, повторяй ту же команду. Полная очистка базы при `reset all` выполняется только **после** успешного удаления всех найденных собственных карточек.

Подробно: [[AI - AI Dungeon Memory Engine все команды#Полный сброс памяти и Story Cards]].

## Как информация попадает в базу

1. **Ручная команда:** игрок сам задаёт запись (`;mem char`, `;mem fact`, `;mem event` и т. д.). Это наиболее контролируемый способ.
2. **Импорт Story Cards:** команда `;mem import` копирует доступные Character/Location/Faction карточки как исходный текст, не анализируя его семантически.
3. **Автоматический отчёт:** модель пишет в конце своего ответа структурированный JSON с маркером. Обработчик Output извлекает и сохраняет указанные сущности.
4. **Резервный фрагмент:** видимый ответ сокращается до ~260 символов и сохраняется как неподтверждённый фрагмент сцены; сам по себе **не создаёт** отношения/персонажа/факта.

> [!warning] Не все факты одинаково надёжны
> Объект из автоматического отчёта не проверяется второй моделью. Проверяются синтаксис, ограничения размеров и некоторые дубликаты, но **не истинность сюжетного утверждения**. Уверенность текста и доверие к нему нельзя приравнивать к независимому подтверждению.

## Как память попадает к рассказчику

Контекстный обработчик формирует справочный блок до **3200 символов** с описанием мира, текущим временем/местом, персонажами и локациями, чьи имена найдены в последнем действии и нескольких фрагментах истории. Также попадают отдельные отношения (только `view/reason`), факты по упомянутой теме, события дня, его сводка и ближайшие планы. **Не все поля выгружаются**: например `place.kind`, `faction.territory`, `rel.trust/tags`, `arc.result/start/end` в собственном `amContext` отсутствуют. Некоторые из них всё же встречаются в `map`, `show` или Story Cards.

Это **лексический подбор по совпадениям текста**, не векторный поиск и не полноценная система семантических воспоминаний. Записи, не подходящие по упоминаниям, могут не попасть в текущий ответ модели. Если места в контексте мало, скрипт пытается сократить раннюю часть `Recent Story`; если безопасно освободить место нельзя — не вставляет память.

## Чем отличается от встроенной памяти AI Dungeon

| Механизм | Предназначение |
|---|---|
| **Memory Engine** | Структурированные сущности, связи и календарь с ручными исправлениями. |
| **Story Cards** | Короткие карточки, которые AI Dungeon может активировать по триггерам; Memory Engine создаёт лишь собственные карточки. |
| **Memory Bank / Auto Summarization** | Общая история и сводки платформы; этим модулем не управляются. |
| **Universal RPG** | Числовые параметры, броски, деньги, предметы и эффекты персонажа. |

Не отключай встроенные механизмы общей памяти только ради нового скрипта без сравнительного теста: его контекстный отбор ограничен.

## Состояния, важные для диагностики

- `;mem status` — режимы, счётчики, число принятых отчётов, пропущенных маркеров и ошибок карточек.
- `;mem pending` — **не очередь согласования**, а статистика и последние события.
- `;mem recent` — сырые выдержки текста, не структурированные подтверждённые данные.
- `;mem undo` — только один последний пакет автозаписи **или** ручного `;mem batch`, до следующего изменения; не возврат всей истории и не откат Story Cards.

## Дополнительные хранилища импорта v1.5.0

| Поле | Содержание | Удаление |
|---|---|---|
| `facts[].cardType` / `triggers` / `sourceCardId` | Исходный тип и ключи нестандартной Story Card, связь с источником. | Вместе с записью факта или `reset data`. |
| `plotImports` | Копии доступных Plot Components с отметкой источника; не редактируют исходный Plot. | `reset data` / `reset all`. |
| `rpgSnapshot` | Последний явно импортированный снимок Universal RPG, отдельно от игровых механик. | `reset data` / `reset all`. |

Новые поля автоматически появляются при загрузке старых сохранений версии схемы `state.aidm.version=1`. Если `Plot Essentials` уже присутствуют в исходном контексте платформы, полная повторная вставка не выполняется: Memory Engine добавляет только короткую выдержку. Imported Author's Note и AI Instructions остаются архивными данными и не вставляются как служебные инструкции.

Контракт обмена с RPG см. [[AI - AI Dungeon Memory Engine совместимость с RPG]].

## Уровни и источники (v1.6.0)

`state.aidm.reviewQueue` хранит предложения от модели до подтверждения. `reviewHistory` — последние решения, `reviewSeen` — краткую историю дубликатов, `reviewNextId` — номера предложений. `provenance` — происхождение подтверждённых полей (`user`, `import`, `approved`).

В `Context.js` включаются только канонические данные. Предложения и наблюдения туда не попадают, чтобы предположения не превращались в «установленные факты». `Output.js` выводит уведомление в `state.message`, без изменения художественного ответа.

Детали и защита ручных данных: [[AI - AI Dungeon Memory Engine проверка автопамяти]].

## Перенос данных v1.7.0

Технические объекты `state.aidm.transferOut` (закодированный снимок исходной истории) и `state.aidm.transferIn` (временно полученные части) **не являются канонической памятью**. Они не попадают в контекст и очищаются через `;mem transfer cancel` либо после успешного переноса. Формат подтверждённой памяти переносится через вручную копируемые части; данные Universal RPG и ожидающие подтверждения наблюдения не включаются. См. [[AI - AI Dungeon Memory Engine перенос между историями]].
