# AI Dungeon — Memory Engine: летопись и календарь

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine все команды]] · [[AI - AI Dungeon Memory Engine устройство памяти]]

Время в этом модуле — **игровое**. Если используешь часы Universal RPG, выполни `;mem date off`: Memory Engine перестанет показывать рассказчику собственную текущую дату и время, календарные напоминания и сводку «сегодня». Сохранённые даты, события и планы остаются в базе; вернуть календарь можно командой `;mem date on`. Исторические события продолжают участвовать в памяти без дат в автоматическом контексте. RPG сообщает рассказчику собственную текущую дату и время через свой Context.

### Массовое создание летописи и планов

В v1.4 пакет использует обычные команды: `;mem batch`, затем `§;mem event Дата | Описание | 1..3`, `§;mem summary Дата | Итог`, `§;mem arc Название | summary=...` и `§;mem plan Дата | Название | Подробности`, в конце `§:apply`. Шаблоны: `;mem batch template event/day/arc/plan`. Планы не считаются произошедшими событиями. Старые поля `§event`, `§day`, `§arc` и `§plan` также поддерживаются. См. [[AI - AI Dungeon Memory Engine пакетное заполнение]].


## 1. Текущая игровая дата

```text
;mem date 2016-01-02 09:06
;mem status
```

Синтаксис: **`YYYY-MM-DD`**, необязательное время **`HH:MM`**. Проверяется корректность реальной календарной даты (включая високосные годы). Если время пропущено, прежнее сохранённое время остаётся неизменным; команда не обнуляет часы. Нет команды «прибавить N часов» — дата вводится напрямую или может быть установлена JSON-отчётом рассказчика при явном упоминании.

## 2. Мелкие события

```text
;mem event Алиса прошла собеседование у Даны
;mem event 2016-01-02 | Алиса получила пробное задание | 2
;mem day
;mem day 2016-01-02
```

Событие имеет ID, дату, время из текущих часов Memory Engine (если они заданы), описание и **значимость 1–3**. `1` — по умолчанию. **Значимость влияет на отбор до 4 событий из последних 90 в контекст.** Сильнее значимость — выше приоритет, но влияют также текущая дата, совпадение с запросом и свежесть. `day` отмечает значимость `[1/3]`, `[2/3]`, `[3/3]`; `timeline` отдельно показывает до 12 важных событий (2–3). Событие с одинаковой датой и дословно одинаковым текстом среди последних 12 записей повторно не создаётся. Если дата ещё не установлена, событие попадает в **«без даты»**, а не в отдельный календарный день. Если указываешь дату события явно, **время события всё равно берётся из текущих часов Memory Engine**, а не из указанного дня; проверяй сочетание даты и времени.

```text
;mem delete event 7
```

## 3. Сводка одного дня

```text
;mem summary 2016-01-02 | Алиса начала пробный период в Строй-Арт, познакомилась с коллегами и получила первое задание.
;mem day 2016-01-02
;mem timeline
```

Автоматический JSON может содержать `daySummary` или `daySummaries`. Но **нет независимого алгоритма**, который гарантированно обобщает каждый день. Если модель пропустила сводку, её можно внести вручную. Важно: автоматическое `daySummary` применяется к текущему дню, только если запись этого дня уже создана в базе; ручная команда `;mem summary` создаёт день при необходимости.

## 4. Большое событие / сюжетная линия

Для сюжетов, развивающихся многие дни, предназначены `arc`:

```text
;mem arc Пробный период Алисы | summary=Две недели работы в дизайнерском отделе | status=идёт | start=2016-01-02
;mem arc Пробный период Алисы | status=завершён | result=Алиса получила постоянный контракт | end=2016-01-16
;mem list arc
;mem show arc Пробный период Алисы
```

`start` и `end` в этой версии — **текстовые поля**, для них не проверяется даже формат даты, и они не запускают таймер. `status` — произвольный текст («идёт», «завершён»), а не переключатель логики. `summary` и `status` передаются в контекст только при отборе арки по имени; **`result`, `start`, `end` тоже включаются в контекст при выборе арки**, но не запускают таймер. Для арок Story Cards не создаются. Большие арки показываются в `;mem timeline` (последние 10).

## 5. Календарные планы

> [!example] Удаление плана по ID
> При создании `;mem plan 2016-01-22 | Снежная буря | Проблемы с транспортом` ответ содержит `План #ID`. Команда `;mem calendar` выводит тот же `#ID`. Введи `;mem delete plan ID`, заменив `ID` числом, чтобы удалить план. Это не удаляет уже произошедшее событие из летописи.


```text
;mem plan 2016-01-22 | Сильная снежная буря | Возможны транспортные задержки
;mem plan 2016-02-14 | День святого Валентина | Праздничные события в городе | yearly
;mem calendar
;mem day 2016-01-22
```

План — **предстоящее или повторяющееся событие**, не доказательство, что оно уже произошло. Когда дата наступает, рассказчик получает напоминание, но скрипт **не переносит персонажа, не вызывает событие принудительно и не отмечает его как завершённое**. Для факта произошедшего используй `;mem event`. **Удаление:** в ответе `;mem plan` и списках `;mem calendar`/`;mem day` теперь указан ID плана — например `#17`. Используй `;mem delete plan 17`. План остаётся только напоминанием, а не подтверждением произошедшего события.

**`;mem calendar` сортирует и показывает до 35 записей, в том числе уже прошедшие разовые планы; это не всегда «35 ближайших будущих».** Ежегодное повторение работает только через значение `yearly`. Логика повторения использует ближайшее подходящее календарное число; для особых дат вроде 29 февраля возможны пропуски невисокосных лет.

## 6. Как хранятся старые дни

Цель автоматического уплотнения — **75 подробных дней**; более старые при добавлении событий частично сворачиваются в текстовые месячные сводки (максимум 36 месяцев). **Нюанс:** ручная команда `;mem summary` и авто-`daySummaries` могут создавать новые дни без немедленного запуска уплотнения, поэтому это не жёсткий предел в каждый момент. `;mem timeline` выводит до 24 последних подробных дней и до 10 сюжетных арок. Старые месячные сводки сохраняются, но **отдельной команды их просмотра нет**. Последние 250 событий хранятся отдельно, с обрезкой самых старых. `;mem day` выводит максимум 18 последних событий выбранной даты. **Удаление события не пересчитывает вручную написанную сводку дня.** Сводка месяца, соответствующего текущей игровой дате, теперь добавляется в контекст (до 260 символов), если она существует. Отдельной команды просмотра старых месяцев пока нет.

> [!warning] Не подменяй события намерениями
> Запись «22 января ожидается буря» принадлежит `plan`; запись «22 января из-за бури закрыли дороги» после развития сюжета — `event`. Иначе память начнёт считать предсказания произошедшими фактами.
