# AI Dungeon — Memory Engine: пакетное заполнение

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine все команды]] · [[AI - AI Dungeon Memory Engine встроенная справка help]] · [[AI - AI Dungeon Memory Engine обновления]]

> [!warning] Обновление после неработающей v1.4
> Если команды перестали распознаваться, не меняй синтаксис пакета вслепую. В v1.4.1 команда `;mem ping` проверяет загрузку, а обновление требует **Library.js + Input.js + Context.js + Output.js**. Подробности в [[AI - AI Dungeon Memory Engine диагностика и ограничения]].


## Назначение

**Начиная с v1.4 пакет состоит из тех же команд, которые можно отправлять по одной.** Больше не требуется запоминать отдельные правила `§char=...`, `§bio=...` и порядок полей относительно текущего объекта. Достаточно скопировать обычную команду и поставить **`§` перед ней**, чтобы AI Dungeon не потерял границу строки.

Всё отправляется **одним сообщением в режиме Do**. Скрипт проверяет весь пакет на временной копии базы; если одна строка неправильная, **ничего из блока не сохраняется**. Изменения существующих объектов затрагивают только переданные поля.

### Общий вид

```text
;mem batch
§;mem char Имя | bio=Биография | traits=Характер
§;mem place Место | kind=комната | description=Описание
§;mem rel Имя -> Друг | view=Доверие | reason=Причина
§:apply
```

Три отличия от отдельных команд: первая строка `;mem batch`, дополнительный `§` перед каждой командой и завершающий `§:apply`. **Сами команды не изменяются.**

> [!tip] Можно обойтись без символа `§`
> Вариант с настоящими переносами строк тоже поддерживается:
> ```text
> ;mem batch
> ;mem char Алиса | bio=Дизайнер
> ;mem char Дана | bio=Руководитель
> ;mem apply
> ```
> Но если режим Do склеит строки, такой пакет перестанет корректно распознаваться. Поэтому рекомендуемый вариант — с `§` и `§:apply`.

## Готовые шаблоны по категориям

Каждая команда ниже **выводит заполненный пример для копирования** и не меняет память. Замени имена и описания своими; затем отправь полученный пакет отдельным сообщением.

| Команда шаблона | Что входит |
|---|---|
| `;mem batch template char` | Персонаж и один навык |
| `;mem batch template skill` | Несколько навыков существующего персонажа |
| `;mem batch template rel` | Два направленных отношения |
| `;mem batch template place` | Родительское здание и вложенная локация |
| `;mem batch template faction` | Две организации |
| `;mem batch template world` | Описание мира, дата и текущее место |
| `;mem batch template fact` | Несколько устойчивых фактов |
| `;mem batch template event` | Несколько произошедших событий |
| `;mem batch template day` | Сводки нескольких дней |
| `;mem batch template arc` | Сюжетные линии |
| `;mem batch template plan` | Разовые и ежегодные планы |
| `;mem batch template delete` | Удаление по типу и ID — **подставь реальные ID** |
| `;mem batch template all` | Универсальный пакет разных категорий |

Встроенная справка: `;mem help batch` или `;mem batch help`.

## Персонажи и отдельные навыки

```text
;mem batch
§;mem char Алиса | bio=Начинающая художница | traits=Упрямая, наблюдательная | appearance=Тёмные волосы | occupation=Стажёр
§;mem skill Алиса | Рисование | высокий | Делает карандашные эскизы
§;mem skill Алиса | Переговоры | начинающий | Неуверенно общается с клиентами
§;mem char Дана | bio=Руководитель компании | traits=Внимательная, требовательная
§:apply
```

`char.skills=...` — общий текст о способностях; `;mem skill ...` — **отдельный именованный навык**. Навыки не влияют на числовую механику Universal RPG. Строка `skill` требует существующего персонажа либо персонажа, создаваемого через `char` в этом же пакете.

## Отношения (в обе стороны независимо)

```text
;mem batch
§;mem rel Алиса -> Дана | view=Уважает | reason=Получила работу | trust=35
§;mem rel Дана -> Алиса | view=Заинтересована | reason=Увидела талант | trust=10
§:apply
```

Изменение `Алиса -> Дана` **не обновляет** `Дана -> Алиса`. `trust` — целое от −100 до 100, не модификатор бросков.

## Мир, вложенные локации и фракции

```text
;mem batch
§;mem world Современный город Де-Мойн, реалистичный сеттинг
§;mem place Де-Мойн | kind=город | description=Город в штате Айова
§;mem place Строй-Арт | parent=Де-Мойн | kind=здание | description=Офисный центр
§;mem place Офис Даны | parent=Строй-Арт | kind=кабинет | status=Открыт
§;mem faction Строй-Арт | description=Дизайнерская компания | territory=Де-Мойн | goal=Расширять бизнес
§;mem here Офис Даны
§:apply
```

**Родительская локация может создаваться после дочерней в пределах одного пакета.** При применении проверяются все ссылки `parent`; отсутствующие родители и циклы отклоняются. `here` устанавливает текущее место повествования, но не создаёт место автоматически.

## Факты, произошедшие события и сводки дней

```text
;mem batch
§;mem date 2016-01-02 09:06
§;mem fact Правило компании | Рабочий день начинается в девять утра
§;mem event 2016-01-02 | Алиса познакомилась с руководителем | 2
§;mem event 2016-01-02 | Алиса подписала документы о найме | 3
§;mem summary 2016-01-02 | Алиса устроилась на работу и познакомилась с коллегами
§:apply
```

`event` фиксирует **произошедшее** (значимость 1–3), а `summary` — текстовый итог дня. Старое пакетное поле `§day=...` соответствует обычной команде **`;mem summary ...`**.

## Сюжетные линии и календарь

```text
;mem batch
§;mem arc Новая работа | summary=Алиса начинает карьеру | status=Идёт | start=2016-01-02
§;mem plan 2016-01-10 | Совещание | Презентация первого проекта
§;mem plan 2016-02-14 | День святого Валентина | Ежегодный праздник | yearly
§:apply
```

`plan` — **намерение или запланированная дата**, а не событие, которое автоматически произойдёт. В календаре у каждого плана есть ID, доступный через `;mem calendar`.

## Пакетное исправление и удаление

```text
;mem batch
§;mem char Алиса | traits=Спокойная, решительная
§;mem rel Алиса -> Дана | trust=50
§;mem delete plan 15
§:apply
```

`delete` разрешён для `char`, `skill`, `place`, `faction`, `rel`, `arc`, `event`, `fact`, `plan`. Номер `15` — **пример**, перед применением узнай реальный ID через `;mem calendar`, `;mem list fact`, `;mem day` или `;mem timeline`. Если хотя бы одна запись для удаления отсутствует, пакет отклоняется целиком. Удаление родителя с оставшимися дочерними местами также отклоняется.

> [!warning] Story Cards и откат
> `;mem undo` восстанавливает **последний доступный пакет базы `state.aidm`**, но **не возвращает удалённые или изменённые Story Cards**. Синхронизация карточек — отдельная операция. Перед массовыми удалениями сделай резервную копию приключения, если платформа позволяет.

## Проверка результатов

После сохранения используй обычные команды:

```text
;mem status
;mem list char
;mem list place
;mem list rel
;mem map
;mem timeline
;mem calendar
```

## Ограничения и ошибки

- **Максимум 3950 символов** исходного пакета, включая команды и разделители.
- **До 55 развёрнутых полей/операций**. Команда `;mem char Имя | bio=... | traits=...` расходует несколько полей. Делай два пакета, если лимит превышен.
- `§:apply` должен завершать пакет; в варианте с сохранёнными переносами строк можно использовать `;mem apply`.
- В пакете разрешены **только команды изменения базы**: `char`, `skill`, `place`, `faction`, `rel`, `arc`, `world`, `date`, `here`, `fact`, `event`, `summary`, `plan`, `delete`.
- Команды просмотра и настроек (`status`, `list`, `show`, `map`, `auto`, `cards`, `import`, `help`, `undo`) запускаются **отдельно**, не как строки пакета.
- Ошибочное имя поля (`bioo=...`), некорректная дата, отсутствующий родитель, превышение лимита или удаление несуществующей записи отклоняют весь пакет.
- **Не смешивай** новые строки `§;mem ...` и старые `§bio=...` внутри одного пакета.
- Однотипные обновления одного объекта в пакете применяются в порядке строк. Неуказанные поля остаются прежними.

> [!danger] Не включай сброс в пакет
> `;mem reset`, `;mem reset data confirm`, `;mem reset cards confirm` и `;mem reset all confirm` работают **только отдельной командой**. Нельзя вставлять их как `§;mem reset ...`: пакетный валидатор отклонит операцию. Это защищает от случайного удаления вместе с обычными изменениями.

## Совместимость со старым пакетным форматом v1.1–v1.3.1

Следующий формат **по-прежнему работает**:

```text
;mem batch char Алиса
§bio=Молодая дизайнер
§traits=Любознательная
§skill=Рисование | высокий | Делает эскизы
§:apply
```

Команды для получения старых шаблонов:

- `;mem batch template legacy char`
- `;mem batch template legacy place`
- `;mem batch template legacy faction`
- `;mem batch template legacy arc`
- `;mem batch template legacy all`

**Существующие пакеты переписывать не требуется.** Для новых записей используй формат с `§;mem`, чтобы одну и ту же команду можно было отправлять отдельно или копировать в общий блок.
