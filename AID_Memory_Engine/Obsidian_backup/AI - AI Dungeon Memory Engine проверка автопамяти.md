# AI Dungeon — Memory Engine: проверка автоматической памяти

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine автообновление и Story Cards]] · [[AI - AI Dungeon Memory Engine все команды]] · [[AI - AI Dungeon Memory Engine обновления]]

## Что изменилось в версии 1.6.0

С v1.6.0 рассказчик **не может непосредственно изменять подтверждённые поля** персонажа, отношения, локации или летопись. `Output.js` считывает структурированный JSON, технически проверяет допустимые поля и помещает изменения в `state.aidm.reviewQueue`. Затем **через `state.message`** показывает уведомление игроку. Художественный ответ модели остаётся неизменным, технический JSON скрывается.

> [!important] Автоматическая проверка — не проверка достоверности
> Синтаксически корректный JSON от модели **не доказывает**, что событие действительно произошло. Извлечённая запись считается **предложением**, пока игрок её не подтвердит. Ручные записи и корректный импорт — другой, подтверждённый уровень.

## Три уровня сведений

| Уровень | Где хранится | Попадает ли в контекст и Story Cards | Как становится каноном |
|---|---|---|---|
| **Подтверждённые** | `characters`, `places`, `relations`, `facts` и остальные основные разделы `state.aidm` | Да, если релевантно. Для персонажей, мест и фракций возможно создание Story Cards | Ручная команда, импорт или `;mem accept ID` |
| **Предложенные автоматикой** | `state.aidm.reviewQueue` с `tier=proposed` | **Нет** | Игрок принимает `;mem accept ID`, при необходимости после правки |
| **Непроверенные наблюдения** | Та же очередь с `tier=observation`; короткие сырые отрывки отдельно в `recent` | Не вставляются как установленный факт и не создают Story Cards | Осознанное `;mem accept ID` создаст именованный факт; сырые отрывки не подтверждаются автоматически |

`reviewQueue` имеет максимум 60 ожидающих записей. `reviewHistory` хранит последние 100 решений, `reviewSeen` помогает не предлагать одно и то же на каждом ходу. Это ограниченное техническое устранение дублей по нормализованному тексту, **не семантическая проверка с отдельной моделью**.

## Уведомление после игровой сцены

Если модель предложила изменения, Memory Engine показывает сообщение через **`state.message`**, например:

```text
[AID MEMORY — ожидает решения: 2]
#12 [ПРЕДЛОЖЕНИЕ] Персонаж Алиса · occupation: Дизайнер
#13 [НЕПРОВЕРЕНО] Наблюдение Дана: Возможно, Дана скрывает прошлое
;mem accept ID — подтвердить; ;mem edit ID | новый текст — исправить; ;mem reject ID — отказаться.
;mem review — посмотреть все и источники.
```

Сообщение не является дополнительной Story Card и не приписывается рассказчику как сюжетный текст. В интерфейсе AI Dungeon отображение `state.message` зависит от платформы; если уведомление не видно, прочитай очередь вручную через `;mem review` или `;mem pending`.

## Команды игрока

| Команда | Что делает |
|---|---|
| `;mem review` | Список текущих предложений и наблюдений с ID, без изменений базы |
| `;mem review 12` | Полное предложение №12 и источник (номер хода, игровая дата и выдержка из ответа) |
| `;mem accept 12` | Подтвердить №12; если существующее подтверждённое поле защищено, показать конфликт |
| `;mem accept 12 replace` | **Явно заменить** существующее ручное, импортированное или старое поле |
| `;mem edit 12 | Новый текст` | Изменить предлагаемое значение, не сохраняя его сразу |
| `;mem accept 12` после правки | Принять исправленное игроком предложение; отдельный `replace` не нужен |
| `;mem reject 12` | Отменить предложение без изменения канона |
| `;mem review log` | Журнал принятых и отклонённых решений |
| `;mem sources char Алиса` | Показать известное происхождение отдельных полей Алисы |
| `;mem sources place Офис` | Происхождение полей локации |
| `;mem sources rel Алиса -> Дана` | Происхождение направленной связи |
| `;mem help review` | Встроенный тематический Help |

### Пример: исправление перед сохранением

```text
;mem review
;mem review 12
;mem edit 12 | Начинающий дизайнер
;mem accept 12
;mem sources char Алиса
```

**Навык:** предложение типа `skill` редактируется через `;mem edit ID | level=эксперт` либо `;mem edit ID | details=Новая подробность`. Без `level=`/`details=` текст заменяет уровень. Другие записи принимают обычный текст.

### Пример: конфликт с ручной биографией

Игрок ввёл: `;mem char Алиса | bio=Родилась в Де-Мойне`. Модель предложила другую биографию. `;mem accept ID` **откажется заменять** поле и покажет оба значения.

Игрок может либо отказаться командой `;mem reject ID`, либо осознанно исправить через `;mem edit ID | ...` и подтвердить. Если он хочет принять исходный вариант модели без редактирования — `;mem accept ID replace`.

> [!warning] Старые сохранения
> Поля, созданные до v1.6.0 и не имеющие сведений об источнике, **считаются защищёнными**, а не автоматически доверенными модели. Для их замены также требуется явное действие.

## Источники и защита ручных данных

В `state.aidm.provenance` сохраняются метки происхождения для изменённых полей:

- `user` — введено вручную или пакетным вводом;
- `import` — перенесено из Story Cards / Plot / снимка RPG;
- `approved` — предложено рассказчиком и подтверждено игроком.

Для решения доступны исходное предлагаемое значение, технический источник `narrator`, игровая дата, номер действия (`actionCount`, когда доступен) и краткий фрагмент сцены. Это **трассировка происхождения**, а не независимое доказательство истинности утверждения.

Подтверждённые факты и события в основной базе получают пометку `approved:narrator`. Старые записи без меток не изменяются автоматически. Импорт продолжает пользоваться прежними проверками и правилами защиты ручных карточек.

## Что не меняется

- `;mem auto off` отключает сбор предложений; уже ожидающие решения не исчезают.
- `;mem cards off` отключает синхронизацию собственных карточек; подтверждение всё равно меняет базу.
- `;mem undo` может восстановить данные предыдущего подтверждения, **но не откатывает уже выпущенные Story Cards**. Рекомендуется проверить их после отката.
- Непроверенные `recent` остаются фрагментами истории и не попадают автоматически в очередь как доказанные факты.
- В v1.6.0 **нет независимого семантического проверяющего**, автоматического массового подтверждения и межскриптового чтения `state.rpg`.

## Практическая последовательность

1. Выполни `;mem ping`, затем `;mem status` — убедись, что версия **1.6.0**.
2. Сыграй обычную сцену. После ответа модели проверь уведомление или `;mem review`.
3. Используй `;mem review ID` для важных утверждений, затем `;mem accept ID`, `;mem edit ID | ...` или `;mem reject ID`.
4. После принятия проверь `;mem show char Имя`, `;mem timeline`, `;mem map` или `;mem sources ...`.
5. Если модель ничего не предложила, используй `;mem recent` и при необходимости ручную команду — скрипт не может сам исправить отсутствие JSON.
