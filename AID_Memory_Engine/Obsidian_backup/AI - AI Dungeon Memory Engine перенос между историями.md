# AI Dungeon — Memory Engine: перенос памяти между историями

[[AI - AI Dungeon Memory Engine оглавление]] · [[AI - AI Dungeon Memory Engine установка]] · [[AI - AI Dungeon Memory Engine все команды]] · [[AI - AI Dungeon Memory Engine совместимость с RPG]]

## Назначение

Каждое приключение AI Dungeon имеет **собственное состояние Memory Engine** (`state.aidm`). Подключение скрипта в новой истории **не переносит** старую базу. Версия 1.7.0 вводит явный перенос через копирование текстовых команд между приключениями. Не нужны внешние серверы и прямой доступ к файлам игры.

> [!important] До начала
> В исходной и целевой истории должна быть установлена версия **v1.7.0** (все четыре вкладки JS из одного архива). Сначала создай резервную копию целевого приключения. Источник не изменяется. Все команды отправляются по одной в режиме **Do**.

## Что переносится

| Режим | Включено | Исключено |
|---|---|---|
| `all` (по умолчанию) | Описание мира, дата/время/текущее место Memory Engine, персонажи с описательными навыками, локации, фракции, отношения, факты, события, дневные и месячные сводки, сюжетные линии, планы, архив Plot, источники подтверждённых записей, журнал решений | Снимок `rpgSnapshot`, ожидающие решения предложения, сырые фрагменты сцен, временные сообщения/очереди экспорта, диагностические данные |
| `world` | Описание мира, локации, фракции, подтверждённые факты, архив Plot и происхождение записей | Персонажи, отношения, игровая дата и место героя, сюжетные события, календарные планы, RPG-снимок, очередь проверки |

**Не переносится ни в одном режиме:** история действий AI Dungeon, пользовательские и автоматически созданные Story Cards как объекты платформы, встроенный Memory Bank, содержимое Plot UI, `state.rpg` другого Adventure Script, другие скрипты и их настройки. Сохранённые в Memory Engine текстовые копии Plot становятся архивом, но не заменяют Plot в новой истории. Важно не путать эти вещи.

## Перенос всей памяти: пошагово

### Старая история — создать снимок

Введи:

```text
;mem transfer export
```

Скрипт покажет идентификатор и **количество частей** (например, 6). Для каждой части введи по отдельности:

```text
;mem transfer part 1
;mem transfer part 2
```

Продолжай до последней. Каждая команда выдаёт готовую строку **`;mem transfer import ...`**. Копируй **всю эту строку**, не заголовок с номером. Сохрани скопированные строки в текстовом файле, Obsidian или прямо вставляй по одной в новой истории. В середине переноса не вызывай новый `transfer export`, иначе идентификатор изменится.

> [!tip] Для небольших миров
> Часть содержит 1600 символов кодированных данных; вся команда укладывается в ограничение ввода. Частей может быть много, если заполнена подробная летопись. Обычный текст нельзя смешивать с командой импорта.

### Новая история — принять части

Подключи тот же Memory Engine v1.7.0. По одной вставляй строки, полученные в старой истории. Каждый раз будет сообщение `ПРИНЯТА ЧАСТЬ N/TOTAL`. **Порядок не важен**: например, 2, 1, 3. Повторная идентичная часть допустима.

Проверь:

```text
;mem transfer status
;mem transfer apply
```

`status` показывает полученные и отсутствующие номера. `apply` **без confirm** проверяет данные, контрольную сумму и показывает, что будет импортировано. Эти команды ничего не записывают в подтверждённую память.

Для пустой базы:

```text
;mem transfer apply confirm
```

**Для уже заполненной базы** понадобится более опасная явная команда:

```text
;mem transfer apply replace confirm
```

Она **ЗАМЕНЯЕТ** подтверждённую память целевой истории, а не объединяет записи. При этом старые собственные Story Cards Memory Engine целевого приключения нужно удалить заранее через `;mem reset cards confirm`, иначе применение блокируется. Пользовательские карточки не удаляются. После сброса карточек повторно включи `;mem cards on`, если хочешь их автосоздание.

После успешного применения выполни `;mem status`, `;mem map`, `;mem list char`, `;mem timeline`. Скрипт постепенно создаст свои Story Cards в новом приключении при последующих ходах (если включён `cards on`).

## Только сведения о мире

Если начинаешь отдельную историю с новыми персонажами и не хочешь переносить старый календарь и события:

```text
;mem transfer export world
```

Дальше порядок тот же: `part N` в старой истории, вставка готовых команд в новой, `status`, `apply`, `apply confirm`. Факты переносятся как записи памяти, а не как исходные пользовательские Story Cards.

## Все команды переноса

| Команда | Что происходит |
|---|---|
| `;mem transfer help` / `;mem help transfer` | Встроенная справка. |
| `;mem transfer export` | Зафиксировать всю подтверждённую память. |
| `;mem transfer export world` | Зафиксировать только географию, организации, мир и факты. |
| `;mem transfer part N` | Получить копируемую строку части N. |
| `;mem transfer import ID N/TOTAL DATA` | Принять часть в целевом приключении. |
| `;mem transfer status` | Количество полученных и недостающих частей. |
| `;mem transfer apply` | Проверить и показать предпросмотр, ничего не изменяя. |
| `;mem transfer apply confirm` | Применить к пустой базе. |
| `;mem transfer apply replace confirm` | Заменить непустую базу при явном подтверждении. |
| `;mem transfer cancel` | Удалить временные части и снимок экспорта **только этого приключения**. Не удаляет канон. |

## Защита и ограничения

- Для контроля целостности проверяются идентификатор и контрольная сумма **всего** снимка. Проверка обнаруживает случайные ошибки копирования, но **не доказывает подлинность** данных — импортируй только собственные снимки.
- Части не объединяют с данными из других экспортов: для начала нового импорта используй `;mem transfer cancel`.
- До применения части хранятся в техническом состоянии; не очищай `state.aidm` посередине переноса.
- Смена версии/кода посреди переноса не рекомендуется.
- Текущий формат не умеет объединять два существующих мира без конфликтов. Есть только **замена**, либо восстановление в пустое приключение.
- Идентификаторы старых Story Cards **не переносятся**. Подтверждённые карточки в памяти могут быть созданы заново как собственные карточки Memory Engine.
- Ожидающие подтверждения автонаблюдения не переносятся: сначала используй `;mem review`, `;mem accept` или `;mem reject` в исходной истории.
- Если в новом приключении используется Universal RPG, **отдельно** выполни `:aidm export` в RPG и `;mem import rpg card` в Memory Engine. Перенос Memory Engine не меняет механику другого скрипта.
- Служебный снимок и части могут содержать личные сюжетные данные. Не публикуй их, если не хочешь передавать содержимое мира.

## Диагностика

| Симптом | Что делать |
|---|---|
| «Получено 2/6» | Посмотри `;mem transfer status` и вставь отсутствующие части. |
| «Контрольная сумма не совпала» | Вставка повреждена. Выполни `;mem transfer cancel` и повтори перенос с одного нового экспорта. |
| «В очереди другой снимок» | Запомни, нужен ли старый набор; при ненужном вызови `;mem transfer cancel`. |
| «Текущая база непустая» | Используй чистое приключение либо явную замену `apply replace confirm` после резервной копии. |
| «Найдены старые Story Cards Memory Engine» | Удали **только** собственные карточки через `;mem reset cards confirm` (при количестве более 30 повтори) и снова выполни `transfer apply replace confirm`. |
| После переноса не видны карточки | Проверь `;mem cards on` и сделай обычный ход. Сама база проверяется через `;mem list char/place/fact`. |

**Проверено локально:** два изолированных игровых состояния, кириллица, последовательности из многих частей, пропущенные/повторные части, контрольная сумма, предотвращение неявной замены, сохранность пользовательских Story Cards и отсутствие переноса `rpgSnapshot`. Работа на сервере AI Dungeon должна быть проверена отдельно.
