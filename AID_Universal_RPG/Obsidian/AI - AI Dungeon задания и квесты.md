# AI Dungeon — задания и квесты

> [!tip] Справочник
> Синтаксис команд и параметры: [[AI - AI Dungeon все команды]].

## Предложение рассказчика о завершении задания

Если рассказчик напишет `Задание #2: done`, а квест #2 ещё имеет `active`, скрипт выдаст `[RPG] ПРОВЕРЬТЕ ИЗМЕНЕНИЯ` с названием задания, текущим и предлагаемым статусами и командой `:quest status 2 done`. Такое предложение **не закрывает квест автоматически**, но сохраняется в `:review`, поэтому его нельзя случайно потерять при дальнейшем развитии сюжета. После проверки выполни команду изменения статуса и по желанию закрой напоминание через `:review dismiss ID`.

Если статус уже `done`, скрипт покажет `[RPG] СВЕРЕНО СО СОХРАНЕНИЕМ`, без создания нового напоминания. Если задания с таким ID нет, сначала проверь `:quest list all`. См. [[AI - AI Dungeon проверка изменений]].

## Связь с развитием персонажа

Завершение задания само по себе XP **не даёт**. Пока опыт начисляется за реальные проверки навыков; модель не может повышать героя текстом. Задания и XP — независимые механики. См. [[AI - AI Dungeon опыт и прокачка]].


Задание — отдельная сущность с ID, названием, необязательным описанием, состоянием и необязательным сроком. Не путать с мечтой (`:char dream`).

## Команды

| Команда | Действие |
|---|---|
| `:quest add Найти работу \| Прийти на собеседование` | Создать активное задание |
| `:quest list` | Только активные задания |
| `:quest list all` | Все задания |
| `:quest list done` | Выполненные |
| `:quest info 1` | Детали задания #1 |
| `:quest edit 1 \| Название \| Описание` | Изменить название и описание |
| `:quest status 1 done` | Завершить |
| `:quest status 1 failed` | Провалить |
| `:quest status 1 cancelled` | Отменить |
| `:quest status 1 active` | Вернуть в активные |
| `:quest due 1 \| 2 4 15 18:00` | Установить срок: год, месяц, день, время |
| `:quest due 1 clear` | Убрать срок |
| `:quest remove 1 confirm` | Безвозвратно удалить |
| `:help quest` | Справка по командам |

Ограничения: до **60** заданий; название до **100** символов, описание до **600**. Для срока действует условный календарь (30 дней в месяце, 12 месяцев в году).

## Пример кампании

```text
:quest add Пройти собеседование | Прийти в агентство и поговорить с директором
:quest due 1 | 1 1 2 15:00
:quest info 1
:quest status 1 done
:notes квест
```

При изменении статуса в журнал добавляется запись категории `квест`. Только **активные** задания передаются рассказчику в контексте (до 8 последних). Сроки и пометка «ПРОСРОЧЕНО» показываются при проверке списка, но **просрочка не проваливает квест автоматически**.

## Почему задания меняются вручную

Модель может описать победу и ошибиться с результатом, сроком или последовательностью событий. Поэтому статус задания — авторитетная команда игрока; ни судья, ни секретарь не завершают квест по одной реплике рассказчика. Награду и деньги при необходимости проверяй отдельно через `:status` и `:money`.

## Мечта и задание — разные поля

- `:char dream` — долгосрочная мотивация без состояния выполнено/провалено.
- `:quest` — конкретная задача с переходами статуса.
- `:note` — факт о состоянии NPC, договорённости, свидетельство и т. п.
