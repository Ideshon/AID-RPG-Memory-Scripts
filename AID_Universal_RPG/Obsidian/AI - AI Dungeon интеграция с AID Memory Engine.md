# Universal RPG — передача снимка героя в AID Memory Engine v1.5.0

> [!info] Протокол v1 · Universal RPG v2.28
> Интеграция **односторонняя и ручная**. Universal RPG остаётся источником истины. AID Memory Engine получает лишь информационную копию через отдельную Custom Story Card.

## Как выполнить обмен

1. В том же приключении AI Dungeon убедись, что оба скрипта установлены и персонаж имеет настоящее имя длиной **2–80 символов**. При необходимости задай его командами `:char create`, `:char name Имя`, `:char done` или через `:setup`.
2. Выполни `:aidm status`. Команда только проверяет возможность экспорта, наличие карточки и текущие размеры данных.
3. Выполни **`:aidm export`** как отдельное действие. RPG создаст одну карточку с зарезервированными Keys либо обновит существующую карточку с тем же маркером.
4. В том же приключении выполни команду **`;mem import rpg card`** для AID Memory Engine v1.5.0. Это **не RPG-команда**.
5. Проверь приём командой **`;mem import rpg status`**. Повторный импорт неизменённого снимка не должен создавать нового персонажа; фактическое поведение приёмника следует проверить в живом приключении.

> [!warning] Два независимых скрипта
> В Universal RPG **не** добавлены файлы Memory Engine, обращения к `state.aidm` или команды `;mem`. Если в приключении активна другая версия Memory Engine, совместимость протокола v1 не гарантируется. Экспорт выполняется только вручную, автоматической синхронизации нет.

## Команды Universal RPG

| Команда | Что делает |
|---|---|
| `:aidm export` | Создаёт/обновляет Custom Story Card из текущего `state.rpg`. |
| `:aidm status` | Проверяет готовность данных и наличие собственной карточки; ничего не записывает. |
| `:aidm help` / `:help aidm` | Показывает встроенную справку по экспорту. |

После экспорта RPG сообщает количество переданных характеристик, навыков, предметов и заметок, размер JSON и число записей, не вошедших в бюджет. В случае ошибки сообщает причину. Без корректного имени героя экспорт отклоняется.

## Формат Story Card

| Поле | Содержимое |
|---|---|
| Type | `Custom` |
| Keys / Triggers | `__AID_RPG_EXPORT_V1__` |
| Начало Entry | **Строго** `[AID_RPG_EXPORT:1]`, затем перевод строки и JSON |
| Максимальный JSON | **5000 символов**, без строки маркера |
| Обязательные поля | `source: "Universal RPG"`, `version: 1`, `hero.name` (2–80 символов) |

Пример содержимого **Entry** (значения только для иллюстрации, не создаются автоматически):

```text
[AID_RPG_EXPORT:1]
{"source":"Universal RPG","version":1,"hero":{"name":"Алиса","bio":"Занимается расследованиями","occupation":"Следователь"},"location":"Офис Даны","date":"2026-11-04","time":"09:00","stats":{"Сила":12},"skills":{"Расследование":25},"inventory":["Фонарик ×1"],"notes":["Знает пароль от сейфа"]}
```

## Какие поля действительно экспортируются

| JSON | Откуда в Universal RPG | Ограничение |
|---|---|---|
| `hero.name` | `state.rpg.character.name` | Обязательное, 2–80 |
| `hero.race` | `character.race`, **только если поле реально существует** | 90 |
| `hero.class` | `character.class`, только если существует | 90 |
| `hero.bio` | `character.background` | 650 |
| `hero.appearance` | `character.appearance`, только если существует | 220 |
| `hero.occupation` | `character.occupation` либо стандартное `character.job` | 120 |
| `location` | `state.rpg.location` | 90 |
| `date` | `state.rpg.day` → игровой год, месяц, день | YYYY-MM-DD, только корректные даты |
| `time` | `state.rpg.timeMinutes` | HH:MM, 00:00–23:59 |
| `stats` | Сохранённые характеристики `state.rpg.stats` | До 25 ключей, имя до 60, значение до 90 |
| `skills` | Изученные навыки `state.rpg.skills` **с уровнем выше нуля** (либо реальные непустые текстовые значения) | До 50 ключей |
| `inventory` | `state.rpg.items` → `Имя ×Количество` | До 60 строк по 90 |
| `notes` | `state.rpg.journal`: сначала закреплённые, затем самые новые | До 15 строк по 220 |

**Неизвестные значения не придумываются.** Стандартный RPG-редактор не имеет отдельных полей расы, класса или описания внешности: обычно эти три поля отсутствуют в экспорте. Числовая характеристика `Внешность` не превращается в вымышленный текст `hero.appearance`. Плейсхолдеры `не указана`, `не задано` и `не определена` не экспортируются как реальные сведения.

### Важное отличие календарей

Universal RPG использует **12 месяцев по 30 дней**, а протокол импортёра требует корректный календарный `YYYY-MM-DD`. Если текущая игровая дата невозможна в григорианском календаре (например, **30 февраля**), экспорт **пропускает поле `date`**, а не подменяет дату. Информация о текущем времени `time` передаётся отдельно. Memory Engine не меняет глобальный календарь по снимку RPG.

### Как обеспечивается лимит 5000 символов

Сначала собираются реальные поля героя, характеристики, изученные навыки, инвентарь и важные заметки. Тексты отдельных полей ограничиваются указанными в контракте размерами. При превышении общего лимита сокращаются массивы заметок, предметов и список навыков; непоместившиеся записи подсчитываются и отображаются в результате команды. RPG-сохранение при этом **не сокращается и не изменяется**. Снимок содержит только поддерживаемые поля контракта, не включает HP, деньги, опыт, голод или временные эффекты.

## Защита Story Cards

- Повторный экспорт ищет карточку по маркеру **в начале Entry** и обновляет её посредством `updateStoryCard(index, keys, entry, type)`, где `index` — положение в `storyCards`, **не ID**.
- Если карточка с маркером имеет не те Keys или тип, либо таких карточек несколько, обновление **блокируется**.
- Если Keys `__AID_RPG_EXPORT_V1__` заняты пользовательской карточкой **без маркера**, создание **блокируется**. Пользовательские карточки не перезаписываются.
- Для первой карточки вызывается `addStoryCard(keys, entry, type)`. Ошибки API показываются пользователю; состояние RPG не сбрасывается.
- Команда `:aidm export` запрещена внутри `:batch`, чтобы отмена пакета не оставила внешнюю карточку.

Вручную переименовывать Keys, менять Entry или копировать экспортную карточку не следует: это приведёт к безопасному отказу до устранения конфликта. Удаление `state.rpg` командами обслуживания RPG **не удаляет** внешнюю Story Card: это отдельный объект AI Dungeon. При необходимости удаляй её через интерфейс карточек.

## Что требуется проверить в реальном AI Dungeon

- `:aidm export` при первой попытке создаёт ровно одну Custom Story Card с нужным Entry и Keys.
- После изменения навыка повторный экспорт обновляет ту же карточку, не создавая вторую.
- `;mem import rpg card` принимает JSON без необязательных полей; `;mem import rpg status` показывает сведения.
- Повторный импорт неизменённой карточки не создаёт дубликатов персонажей.
- В одном приключении `:aidm ...` обрабатывается RPG, а `;mem ...` — Memory Engine; `:status` и игровые механики RPG продолжают работать.

Последние три пункта **зависят от установленного Memory Engine v1.5.0**. Автоматические тесты комплекта Universal RPG проверяют контракт и имитируют Story Card API; они **не запускают** исходники Memory Engine и не подменяют собой интеграционный тест в игре.
