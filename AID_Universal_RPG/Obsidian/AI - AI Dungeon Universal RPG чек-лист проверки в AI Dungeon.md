Комплект проверки: **Universal RPG 2.33**, совместные сценарии — **Memory Engine 1.8.0**. Связанные документы: [[AI - AI Dungeon Universal RPG план исправлений]], [[AI - AI Dungeon Memory Engine аудит и план исправлений]], [[AI - AI Dungeon Memory Engine чек-лист проверки в AI Dungeon]], [[AI - AI Dungeon Universal RPG дерево команд]], [[AI - AI Dungeon все команды]].

## Что уже явно показано пользователем

- [x] **R-H01, ранее установленная версия.** Пользователь сообщил «Работает» и показал лист Алисы: имя, анкета, 9 характеристик, 9 навыков, 11 предметов, дата/место, ресурсы, режимы XP и 2 модификатора отображаются. Это подтверждает чтение сохранённого героя и вывод листа, но не применение всех механик.
- [x] **R-H02, прежние сеансы.** Несколько раз показан успешный `:aidm export` с обновлением карточки #15; Memory Engine затем импортировал снимок для Алисы. Сохранение дополнительных метаданных и поведение при отказе API отдельно не подтверждены.

Автоматический ход часов, расчёт потребностей, финансовые операции, броски, XP, эффекты, квестовые изменения и все варианты setup не считаются подтверждёнными только потому, что их значения видны в листе. Действующая версия 2.33 и совместный запуск с Memory 1.8.0 требуют отдельной сверки.

## Как заполнять результаты

`[ ]` означает отсутствие явного успешного подтверждения пользователем на указанной версии в настоящем AI Dungeon. `[x]` в историческом разделе означает только конкретное наблюдение из переписки; его область указана рядом. Локальные тесты, AID-Sandbox, текст справки и сообщение «команда выполнена» не подтверждают фактический игровой эффект.

Для каждого выполненного пункта запиши версию всех четырёх вкладок, дату, идентификатор пункта, исходное состояние, команду/действие, ожидаемый и фактический результат. Для совместной проверки запиши версию второго скрипта и порядок подключения. Флажок ставится только после сверки фактического состояния и повторного открытия приключения, если пункт затрагивает сохранение. При ошибке оставь `[ ]` и приложи текст ошибки/фактический результат. Если пункт содержит несколько вариантов, он закрывается после проверки каждого; частичные результаты записывай отдельно.

Шаблон записи: `ID: …; версия: …; дата: …; исходное состояние: …; действие: …; ожидается: …; получено: …; повторное открытие: …; итог: подтверждено/ошибка/не проверено`.

Проверки reset, uninstall, удаления, замены переносимой базы и миграций выполняй в копии приключения с сохранённым исходником. Указываемые ниже `ID`, `INDEX`, `Имя`, `TYPE` и значения — заменяемые аргументы; буквально их вводить не нужно. Индекс Story Card и ID факта не взаимозаменяемы. В блоках с `/` проверь перечисленные альтернативы по отдельности, а не вводи весь перечень, если синтаксис команды этого не разрешает.

## Известные ограничения проверки

Известный дефект не считается успешно проверенной функцией. Связанные с ним пункты оставлены открытыми до исправления и повторной проверки. Причины и критерии исправлений: [[AI - AI Dungeon Memory Engine аудит и план исправлений]]. Сценарии неизвестной версии сохранения, повреждения state, отказа API и точного переполнения контекста требуют подготовленной тестовой фикстуры или диагностического стенда: игровой команды для их создания нет. Не подменяй такой сценарий обычным ходом в игре.

## Полный проход команд и их вариантов

Ниже перечислены все командные строки и поля из текущего дерева команд. Все флажки открыты для нового полного прогона: исторические подтверждения приведены отдельно и не означают проверки всех режимов команды. Описание после команды задаёт ожидаемое назначение. Для изменения проверь точное изменение указанного поля, сохранение остальных полей и сохранение результата после повторного открытия; для просмотра проверь полноту вывода и отсутствие игровых изменений; для переключателя проверь оба положения и реальное поведение модуля. Для ошибочного ввода ожидаются объяснение и отсутствие частичной записи. Нужные аргументы и ограничения сверяй с полным справочником.

## Сквозные сценарии и отрицательные проверки

- [ ] **R-S01 — установка и миграция.** Проверить новый герой и копию старого приключения: анкета, ресурсы, инвентарь и режимы сохраняются после замены всех четырёх вкладок и повторного открытия. Неизвестная версия state — отдельная фикстура; сейчас сброс такой записи является известным дефектом.
- [ ] **R-S02 — отображение и команды.** Справка, status, debug/effects показываются читаемо с разделением строк; технические команды не продвигают сюжет и не тратят игровой ход. Проверить Do/Say и обёртки интерфейса; текст ошибок не склеивается с прежним ответом.
- [ ] **R-S03 — создание героя.** Полный цикл create → поля → stat/skill → done сохраняет распределение. Cancel оставляет прежнего героя. Проверить нехватку/избыток стартовых очков, неверные возраст, имя, навык и характеристику без частичной записи.
- [ ] **R-S04 — биография и мечта.** Показ, set, add, синонимы background/goal и clear с confirm меняют только заданное поле; отсутствие confirm не очищает его.
- [ ] **R-S05 — setup.** Проверить полный шаблон и разделы rules/hero/skills/resources, режимы creation/free и все перечисленные поля, включая auto=cautious. Ошибка в последнем поле, повтор ключа, отсутствие apply и неверный тип не дают частично изменить героя или часы.
- [ ] **R-S06 — навыки.** Создать пользовательский навык с ключами и атрибутом, изменить привязку и уровень, проверить info, распознавание по словоформам и удаление. Неверный или неоднозначный навык не создаётся сам и не получает XP.
- [ ] **R-S07 — кубики.** Проверить допустимые и недопустимые грани, ручной check с известной парой атрибут/навык, крайние значения DC и модификаторы. Для одного действия выполняется один предусмотренный бросок; Retry/повторный Output не начисляет результат заново.
- [ ] **R-S08 — предпросмотр проверки.** Preview не бросает кубик и не меняет XP, время, потребности и деньги. При нескольких вариантах choose применяет выбранный вариант ровно один раз; cancel и постороннее действие отменяют ожидающий выбор.
- [ ] **R-S09 — режимы автосудьи.** По отдельности проверить off/classic/smart/narrative/cautious и повторное on. Вопрос, намерение и совершённое действие различаются; неизвестное действие не получает произвольный навык. Для каждого режима сверить причины выбора в debug.
- [ ] **R-S10 — комбинированный судья.** Проверить simple/weighted/detailed, ведущий/вспомогательный навыки, override одной следующей проверки и clear. Удача основного действия и неудача отдельного риска не превращаются в общий успех.
- [ ] **R-S11 — обязательный провал.** После неудачного броска попросить рассказчика описать успех. RPG не выдаёт предмет, деньги или положительный результат за провал и не применяет противоречащий RPG_DELTA. Проверить manual, classic, cautious, narrative, smart и detailed по отдельности.
- [ ] **R-S12 — fallback/editor/ledger.** Проверить каждый резервный режим и editor on/off. На стенде подать правильный, повреждённый и повторный структурированный блок, затем выключить ledger. Проверить совместимость: smart/narrative отключают ledger и не позволяют включить его обратно; разрешённые classic/cautious проверяются отдельно. Не возникают двойное начисление, технический JSON в истории или изменение запрещённых полей.
- [ ] **R-S13 — магия.** При magic off магическое действие не получает разрешённую магическую механику; при on работают соответствующие навыки, проверки и модификаторы. Обычное действие не меняет режим магии.
- [ ] **R-S14 — XP.** Успех, провал и повтор одинакового действия дают предусмотренные начисления. При xp off опыт не растёт; slow/normal/fast и дробный коэффициент применяются точно, включая округление и уменьшение награды за повтор.
- [ ] **R-S15 — повышение.** Проверить instant/rest/manual, достаточный и недостаточный запас XP, xp apply, длительный отдых и журнал. Повышение применяется один раз; смена режима не пересчитывает прошлый опыт и не дублирует награды.
- [ ] **R-S16 — временные модификаторы.** Бонус, штраф, несколько целей, сочетание эффектов и истечение по игровому времени дают ожидаемый итог d20. Проверить remove/delete, clear confirm, aliases modifiers и чтение/удаление старых buff/debuff; новое добавление через устаревшие команды не должно обходить правила.
- [ ] **R-S17 — дата и время.** Проверить set времени и даты без расчёта прошедшего времени, advance/next/time с расчётом потребностей, переход суток, месяца и года. Календарь RPG условный: 12 месяцев по 30 дней. Неверная дата или HH:MM не меняет состояние.
- [ ] **R-S18 — авторасход времени.** По отдельности сверить действие, ожидание, переход, отдых и сон. Команда просмотра или Memory-команда не продвигает часы; после смены даты вручную не происходит повторного накопления потребностей за старый промежуток.
- [ ] **R-S19 — потребности.** Проверить on/off, status/why, еду, питьё, hunger/thirst/fatigue и границы 0–100. Сверить показатели до и после обычного действия, сна и команды rest; время и потребности не учитываются дважды.
- [ ] **R-S20 — здоровье, выносливость и бой.** Проверить ручные плюс/минус, границы ресурсов, автоматические последствия при combat on и их отключение при off. Провал еды/использования предмета не даёт эффект успешного употребления.
- [ ] **R-S21 — деньги и долг.** Проверить money, debt add/set/pay/log, точные дробные суммы, нехватку средств, economy on/off. Для явной оплаты меняются баланс и долг ровно один раз; сообщение рассказчика о выигрыше или списании само не меняет деньги.
- [ ] **R-S22 — финансовые формулировки.** Сравнить «плачу», вопрос о цене, намерение заплатить, отрицание оплаты, получение денег и долг. Сверить журнал и точную сумму. В исторических тестах есть расхождения финансов; этот пункт нельзя закрывать по прежним автотестам.
- [ ] **R-S23 — инвентарь.** Проверить give/take с количеством, нехватку предмета, нулевое/отрицательное/ошибочное количество, rename с существующим новым именем, use имеющегося и отсутствующего предмета, inventory on/off. Предмет и его количество не теряются при отказе.
- [ ] **R-S24 — служебные ключи.** На фикстуре проверить предметы и динамические таблицы с именами constructor/prototype/__proto__. Сейчас constructor допускается как служебный ключ: это известный дефект, ожидаемая безопасная обработка требует исправления.
- [ ] **R-S25 — полный цикл квеста.** Создать задание, проверить info/list и фильтры, edit, все статусы, due с временем, clear срока и remove с confirm. ID стабилен; неверный ID/статус/срок не меняет соседнее задание.
- [ ] **R-S26 — квест и рассказчик.** Описанное моделью завершение задания попадает в предусмотренное review и не меняет статус молча. После явной команды меняется ровно одно задание; показ due и текущей даты согласован.
- [ ] **R-S27 — review.** Проверить list/all, dismiss/remove и clear confirm; удаление напоминания не меняет баланс, предметы или статус квеста. Повтор одинаковой сцены не заполняет журнал бесконечными копиями.
- [ ] **R-S28 — разделение памяти.** Старые note/notes и шаблон notes объясняют переход в Memory и не создают новый RPG-журнал. Квест остаётся в RPG; сюжетный факт создаётся командой Memory и не меняет RPG-механику.
- [ ] **R-S29 — RPG-экспорт.** При правильном имени export создаёт/обновляет одну служебную карточку; при пустом или неверном имени отказывает без изменения героя. Проверить все поля снимка, длинные данные, чужую карточку с резервным ключом, дубли маркеров и отказ API на стенде. Export не расходует время и не сбрасывает ожидающий бросок.
- [ ] **R-S30 — пакеты.** Проверить все действующие template-категории и batch categories/help. Успешный пакет атомарен; ошибка последней строки, неподдерживаемая команда, служебный export и отсутствие apply не дают частичной записи. Устаревший note внутри пакета не должен незаметно создать заметку.
- [ ] **R-S31 — обслуживание.** Для memory clear/reset/uninstall проверить preview, отсутствие confirm и подтверждение в копии приключения. Сверить состав очистки; чужие Story Cards и Memory state не удаляются. После uninstall обычный ход не создаёт RPG заново, а явный reset возобновляет её по правилам.
- [ ] **R-S32 — контекст.** На стенде проверить длинную историю, большой memoryLength, бюджет меньше защищённой памяти и длинную механику. Известно превышение: при maxChars 5000 получено 8202 символа. Закрыть пункт после исправления и повторной проверки в AI Dungeon.
- [ ] **R-S33 — сохранение и повтор хука.** После повторного открытия сохраняются режимы, эффекты, XP, квесты, календарь и инвентарь. Retry, удаление/повтор последнего действия и повторный Output не списывают стоимость и не выдают XP повторно без нового действия.
- [ ] **R-S34 — совместная работа.** Проверить оба порядка Memory/RPG: обычная сцена, команды обоих скриптов, экспорт/импорт, date off в Memory и актуальная дата RPG у рассказчика. Не возникают два броска, двойной расход времени, конфликт дат, два листа героя или чужие служебные сообщения в сюжете.
