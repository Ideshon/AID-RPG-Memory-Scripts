# AI Dungeon — установка и обновление Universal RPG

> [!tip] Быстрые ссылки
> Команды: [[AI - AI Dungeon все команды]] · Инструкция первого запуска: [[AI - AI Dungeon быстрая настройка]] · Версии и миграции: [[AI - AI Dungeon обновления]].

## Что входит в комплект

- `scripts/Library.js` — основная логика, команды, состояние и проверки.
- `scripts/Input.js` — обработка ввода игрока.
- `scripts/Context.js` — сведения о мире, передаваемые рассказчику.
- `scripts/Output.js` — обработка ответа рассказчика и уведомлений.
- Markdown-файлы — отдельные руководства для Obsidian; папка `tests/` — локальные регрессионные проверки.

**Текущая версия скриптов: v2.31.** Для обновления с неизвестной версии полностью замени четыре JavaScript-файла. При переходе с v2.30 обнови `Library.js` и `Output.js`; `Input.js` и `Context.js` не изменялись. Для старых версий с v2.25 или ранее необходимы все четыре JS, поскольку подготовка к удалению должна отключать RPG-хуки. История изменений — только в [[AI - AI Dungeon обновления]].

## Первая настройка

После подключения скрипта достаточно отправить `:setup`: появится редактируемый шаблон основных параметров, героя и ресурсов. Отправь изменённый блок целиком, до `§:apply`, не удаляя маркеры `§`. Подробнее: [[AI - AI Dungeon быстрая настройка]]. Это заменяет необходимость вводить десятки стартовых команд по одной. Для изменения уже существующего героя пакетами привычных команд есть `:batch` — [[AI - AI Dungeon пакетные команды]].

## Установка в сценарий

1. Открой [AI Dungeon](https://play.aidungeon.com) → сценарий → **Edit** → **Scripts**.
2. Если редактор показывает четыре вкладки обработчиков, вставь файлы в одноимённые поля. `Library.js` — в библиотеку, остальные в Input/Context/Output.
3. Сохрани и запусти приключение (Play).
4. Выполни `:status` в режиме **Do**. При появлении `[RPG] ЛИСТ ПЕРСОНАЖА` скрипт загрузился.
5. Для другой истории добавь опубликованный Adventure Script в **Game Settings → Scripts → Add Script**, если он доступен в твоём интерфейсе.

Примечание: меню, права публикации и импорт скриптов меняются. Если опубликованный скрипт не обновился автоматически, проверь его версию и активную копию.

## Обновление без потери прогресса

1. Сохрани копию существующих четырёх файлов (на случай отката).
2. Обнови **все четыре JS** из полного комплекта, чтобы не смешать версии.
3. Сохрани сценарий и открой уже начатое приключение.
4. Выполни `:status`, `:char info`, `:date show`, `:notes`, `:quest list all`.

При обновлении ранее сохранённого приключения скрипт применяет предусмотренные миграции. Не создавай персонажа заново командой `:char create`. Детали переносов, включая устаревшие заметки и эффекты, собраны в [[AI - AI Dungeon обновления]].

**Не удаляй само приключение или историю в AI Dungeon.** Удалять и заменять можно только скачанную локальную папку. Имена Markdown-файлов стабильны; не добавляй номера версий к названиям заметок.

## Очистка, сброс и удаление скрипта

**Убедись, что работаешь с нужным приключением.** Сначала введи нужную команду **без `confirm`**, чтобы получить реальное количество и список данных, которые будут удалены. Только после проверки добавь `confirm`. Выполнение меняет сохранение, а не файлы скрипта; без резервной копии данные RPG не восстановить.

1. **Очистить только сюжетную память** — выполни `:rpg memory clear confirm`. Удаляются заметки, задания, краткая память и журналы; механика персонажа остаётся. Подробное описание — [[AI - AI Dungeon память и заметки]].
2. **Начать приключение с чистым RPG-состоянием** — выполни `:rpg reset confirm`. Стираются все поля `state.rpg` и заново устанавливаются значения по умолчанию. Если в сценарии есть стартовые placeholders, имя/пол героя могут быть восстановлены из них. После этого можно снова применить `:setup`.
3. **Удалить Universal RPG из приключения** — в игре выполни `:rpg uninstall confirm` **до** удаления файлов. Команда удалит `state.rpg` и остановит все четыре RPG-хука. После получения подтверждения в редакторе сценария удали содержимое вкладок `Library`, `Input`, `Context`, `Output` именно этого скрипта. Не очищай скрипты других проектов, если они находятся отдельно.

После команды удаления остаётся **только** служебный признак `state.aidUniversalRpgRemoved = true` вне `state.rpg`, чтобы хуки не воссоздали удалённую базу при следующем действии. Это не игровой профиль и не содержит содержимого RPG. Если скрипты ещё установлены и ты передумал, команда **`:rpg reset confirm`** удалит признак и создаст новое сохранение с настройками по умолчанию. После удаления всех скриптов признак не исполняет никакого кода; ручная очистка этого одиночного ключа возможна только средствами редактирования состояния, если они предоставляются AI Dungeon.

**Ограничение:** удаление `state.rpg` не стирает уже показанные сообщения, историю чата, Plot Essentials/Story Cards, Story Summary или Memory Bank AI Dungeon. Их требуется управлять отдельно через интерфейс платформы. Скрипт не может гарантировать полную очистку серверной памяти и резервных копий сервиса.

Команды обслуживания вызываются **отдельно**, не внутри `:batch`. `:rpg status` даёт краткую сводку, а команды `:rpg memory clear`, `:rpg reset`, `:rpg uninstall` без `confirm` показывают **подробные счётчики до удаления** и точную команду подтверждения. В предварительном просмотре значения текущего героя не меняются; история и отдельные компоненты памяти AI Dungeon не затрагиваются.

## Хранение и резервные копии

- ZIP с полным скриптом — локальная резервная копия исходников.
- Копия Story/Adventure внутри AI Dungeon содержит игровые данные на стороне сервиса; текущий пакет JS сам по себе не является экспортом прогресса.
- Экспортируй приключение средствами AI Dungeon, если требуется резервная копия текста; поддержка полного переноса `state.rpg` при экспорте зависит от сервиса и не гарантируется.
- В Obsidian распакуй документацию в прежнюю папку, заменяя одноимённые заметки и добавляя новые файлы. Имена существующих документов неизменны.

## Обновление до v2.28 и обмен с Memory Engine

При переходе с **v2.27** замените в AI Dungeon **только** `scripts/Library.js` и `scripts/Input.js`. `scripts/Context.js` и `scripts/Output.js` сохранены без изменений. Скопируйте документы Obsidian поверх прежних, не переименовывая файлы; добавится [[AI - AI Dungeon интеграция с AID Memory Engine]].

Оба скрипта остаются независимыми. Их файлы не объединяются: RPG экспортирует одну Custom Story Card командой `:aidm export`, а установленный отдельно Memory Engine v1.5.0 импортирует её своей командой `;mem import rpg card`. Чтобы проверить перенос, выполните `;mem import rpg status`. Это ручной одноразовый снимок, а не непрерывная синхронизация.

> [!warning] При `:rpg reset confirm` или `:rpg uninstall confirm` обменная Story Card **не** удаляется вместе с `state.rpg`. Она относится к данным AI Dungeon, а не к локальной памяти RPG; при необходимости удалите её отдельно через интерфейс карточек.

## Обновление с v2.28 до v2.29

Заменить содержимое только `scripts/Library.js` и `scripts/Input.js` в соответствующих вкладках AI Dungeon. `Context.js` и `Output.js` полностью совпадают с v2.28. Обновить существующие Obsidian-заметки без переименований, добавить [[AI - AI Dungeon полуавтоматические проверки]]. Никакая миграция `state.rpg` не требуется: `config.cautiousJudge` автоматически добавляется как `false` без изменения других игровых данных. Для осторожной автоматической проверки включи `:auto cautious`; для ручного выбора `:check preview ...` → `:check choose 1`. Экспорт `:aidm export` не менялся.

## Обновление с v2.29 до v2.30

Заменить только `scripts/Library.js` в AI Dungeon; остальные три JS совпадают с v2.29. Существующие RPG-сохранения и пресеты `slow/normal/fast` сохраняются без миграции. Доступны `:xp speed 1.5` и `:setup §xp_speed=1.5 §:apply`, а также использование обычной команды внутри `:batch`. Для проверки введи `:help xp`, `:xp` и `:status`. Подробности — [[AI - AI Dungeon опыт и прокачка]].
