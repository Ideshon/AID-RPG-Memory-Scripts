# AI Dungeon — журнал памяти и заметки

> [!warning] Журнал RPG устарел
> Новые сюжетные факты и события храни в AID Memory Engine через `;mem fact` и `;mem event`. `:note` / `:notes` в RPG больше не управляют памятью. Старые записи можно перенести: `:aidm export` → `;mem import rpg card` → `;mem import rpg notes`. Квесты остаются в Universal RPG.

> [!tip] Справочник
> Синтаксис команд и параметры: [[AI - AI Dungeon все команды]].

## Опыт персонажа и журнал

Новый XP-прогресс хранится в отдельных счётчиках `state.rpg.xp` и не занимает заметки журнала. Повышения можно посмотреть через `:xp log`; их не нужно вручную копировать в `:note`, если они не являются важным сюжетным событием. [[AI - AI Dungeon опыт и прокачка]].


Журнал хранит **установленные факты**, а не планы или предположения. Сохраняется в `state.rpg.journal` конкретного приключения.

## Внешний информационный снимок (v2.28)

Команда `:aidm export` создаёт или обновляет **специальную Custom Story Card** из текущего `state.rpg`. Она не копирует весь журнал или игровую механику в чужое хранилище и не обращается к `state.aidm`. Важные заметки (`journal`, сначала закреплённые), изученные навыки и инвентарь попадают в ограниченный JSON-снимок до 5000 символов. На стороне AID Memory Engine v1.5.0 выполните отдельно `;mem import rpg card` и `;mem import rpg status`.

Создание/обновление карточки не очищает `state.rpg`, не переносит её данные в `state.aidm` автоматически и не изменяет историю чата. При полном сбросе/удалении `state.rpg` уже созданная Story Card остаётся в AI Dungeon до её ручного удаления. Подробности: [[AI - AI Dungeon интеграция с AID Memory Engine]].

## Обслуживание памяти движка

Сохранение Universal RPG находится в **`state.rpg`**. В нём сосуществуют механические данные (персонаж, ресурсы, время, XP, настройки) и текстовые записи (журнал, задания, фрагменты сюжета и служебные истории). Это не весь текст приключения в AI Dungeon.

| Команда | Результат |
|---|---|
| `:rpg status` | Краткое количество записей, флагов и ожидающих действий в хранилище; без изменений. |
| `:rpg memory clear` | **Предпросмотр** очистки: точное количество удаляемых заметок, квестов, фрагментов памяти, журналов, флагов и ожидающих действий; указано, что останется. Не очищает сохранение. |
| `:rpg reset` | **Предпросмотр** полного сброса: количество и состав затрагиваемых данных персонажа, XP, ресурсов, предметов, модификаторов, настроек и всей памяти. Не сбрасывает. |
| `:rpg uninstall` | **Предпросмотр** удаления `state.rpg` целиком с подсчётом содержимого; не отключает скрипт. |
| `:rpg memory clear confirm` | **Очищает сюжетную память RPG:** журнал заметок (включая закреплённые), задания, короткую память `recent`, `review`, историю бросков, финансовые и автоматические журналы, журнал повышений XP, следы повторений и сюжетные флаги. Сбрасывает ID заметок, заданий и напоминаний. |
| `:rpg reset confirm` | Полностью создаёт новое `state.rpg` с настройками по умолчанию. **Удаляются персонаж и его прогресс, все предметы, деньги, ресурсы, XP, эффекты, логи.** Начальные имя и пол могут снова считываться из полей сценария. |
| `:rpg uninstall confirm` | Удаляет объект `state.rpg`, отключает хуки RPG и подготавливает приключение к удалению четырёх JS-файлов; подробнее в [[AI - AI Dungeon установка и обновление]]. |
| `:help rpg` | Встроенные предупреждения и точный синтаксис. |

**При частичной очистке** сохраняются характеристика и навыки героя, его биография и мечта, ресурсы, баланс/долг, XP и уровни, часы, активные модификаторы, инвентарь и переключатели систем. Задания исчезают: это часть сюжетной памяти, а не постоянных параметров героя. Очистка не формирует новую игровую сессию и не меняет дату.

> [!warning] Необратимость и внешняя память
> Перед очисткой скопируй сохранение средствами AI Dungeon, если сервис позволяет. Команды **не удаляют** историю сообщений, Story Summary, Plot Essentials, Story Cards, Memory Bank или другие собственные разделы памяти AI Dungeon. Рассказчик может вновь увидеть старые сведения из них. Для удаления этой информации используй соответствующие средства интерфейса AI Dungeon. Полный сброс `:rpg reset confirm` предназначен для новой игры, а не для обычной чистки заметок.

**Порядок:** сначала вызови команду **без `confirm`**, проверь реальные счётчики и перечень того, что будет удалено; если результат подходит, повтори ту же команду с `confirm`. Предпросмотр не очищает сохранение, не снимает ожидающие броски и не сбрасывает уведомления. Нулевые категории тоже показываются, чтобы было видно полный охват. Для полного сброса/удаления указывается число полей верхнего уровня и длина JSON в символах (это **не** объём файла в байтах).

Все три команды с `confirm` выполняются **только по одной**: `:batch` их не поддерживает. Слова `confirm` и весь синтаксис обязательны. Выполнение не отменяется перезагрузкой скрипта.

## Команды

| Команда | Действие |
|---|---|
| `:note Текст` | Быстро добавить факт в категорию `факт` |
| `:note add npc \| Текст` | Добавить запись с категорией |
| `:notes` | Последние 20 записей |
| `:notes all` | До 50 последних записей |
| `:notes npc` | Записи категории `npc` |
| `:notes pinned` | Только закреплённые |
| `:note search охранник` | Поиск по тексту и категории |
| `:note edit 3 \| Новый текст` | Заменить содержимое #3 |
| `:note remove 3` | Удалить #3 |
| `:note pin 3` / `:note unpin 3` | Закрепить или снять важность |
| `:note clear confirm` | Очистить весь журнал без возможности отмены |
| `:help note` | Полная справка и форматы |

Доступные категории: `факт`, `npc`, `событие`, `обещание`, `место`, `квест`, `мир`.

## Пример

```text
:note add npc | Охранник северных ворот запомнил лицо героя
:note add обещание | Работодатель назначил встречу на завтра
:notes
:note pin 2
:note edit 1 | Охранник заметил подозрительное поведение героя
:note search охранник
```

## Ограничения и механика

- До **100** записей по **400** символов каждая. Слишком длинный текст отклоняется целиком.
- Каждая получает **постоянный номер ID**; после удаления ID **не переиспользуется**.
- При заполнении журнала удаляется старейшая **незакреплённая** запись. Закреплённые нельзя вытеснить автоматически.
- Рассказчику передаются не все записи: до 8 последних закреплённых и 8 свежих незакреплённых, но их общий текст ограничивается контекстным бюджетом.
- Для старых сохранений предусмотрен однократный перенос прежних заметок в журнал с ID. Подробности: [[AI - AI Dungeon обновления]].
- AI Dungeon отдельно ведёт Story Summary/Memory Bank. Эти системы не равны локальному журналу скрипта.

### Что НЕ стоит хранить в журнале

Постоянные характеристики и точные числа HP/денег дублировать не нужно — они хранятся в состоянии движка. Значимые события, которые реально изменили биографию, можно записать также в `:char bio add` (но в биографию добавлять только существенные вехи).

Если записанный факт оказался ложным, **редактируй или удаляй** его; иначе модель может закрепить ошибку.
